# Mlogent 1.4.0

这一版加入复杂蓝图的编辑流程，从读出某个处理器的代码，到预览、替换和回退。MCP 接口版本为 `0.3.0`。

- **提取与注入**：用 `mlog_extract` 查看处理器清单、链接和签名注释，提取带标签的 mlog 或 Mindcode 草稿。用 `mlog_inject` 预览差异、诊断与链接状态，再按索引替换代码。原蓝图中其余方块、链接和配置会保留。
- **指令轨迹**：用 `mlog_sim` 的 `trace_vars` 采集真实执行器轨迹。用 `mlog_trace` 按标签和变量查看，或比较两次执行的首次偏离。
- **蓝图版本**：注入成功后生成持久记录，`mlog_revision` 可以查看原代码和检查结果。当当前蓝图与该次生成结果完全匹配时，可以取回原粘贴码。
- **标签与签名**：交付代码使用数字跳转，名称随签名载荷保留。再次提取时恢复原名。Mindcode 的官方反编译命令可以生成编辑草稿，跳转仍需人工整理为高层控制流。
- **生成与入门**：修复 `mlog_gen` 的文件输入，保留源文件。重写 README，集中 CLI、MCP、蓝图编辑和部署入口。

## 下载

| 包 | 内容 |
| --- | --- |
| `toolchain` | Python 工具、规则、测试和文档 |
| `knowledge` | 知识库、机制证据和游戏资料 |
| `skills` | 两份可独立安装的技能及生成的工具载荷 |
| `mcp` | MCP 服务、知识库和部署配置 |

使用 `SHA256SUMS.txt` 校验下载文件。模拟和 Mindcode 需要另行提供 Java 及对应 jar。

## 更新在线 MCP

通过 `/health` 查看接口版本，保留上一份部署产物。蓝图版本记录默认落在 `out/_mlog_revisions/`，
可用 `MLOG_REVISION_DIR` 指向持久目录。重建容器或切换部署版本时保留该目录。
更多说明见 [MCP 部署](https://github.com/EnernalIliary/Mlogent/blob/v1.4.0/docs/MCP部署.md)。
