## §1 需求 → 实现对照

| 需求 | 实现 | 位置 |
| --- | --- | --- |
| 0. 纯 JS + rino，不用 Java | 三个脚本，唯一 Java 交互是 `Packages.*`；无 `loadContent()`、无方块/单位注册 | `scripts/{main,gtb-lib,gtb-ui}.js` |

| 1. 特定语言黑名单（黑名单 / 观察对象二选一） | `langMode = off|ban|watch`；判据 `player.locale` 归一化后按逗号列表前缀匹配（`zh` 命中 `zh_cn`）。ban = 直接拉黑 + 转旁观；watch = 只进观察名单，「成员」口径缩到观察对象（`targetOf()` 返回 `target|watched|admin`） | `lib.localeInList` / `targetOf` |

| 2⑤ 涡轮/火电被填爆混 → 禁用 + 警告 + 通告 | 扫 `steam-generator`/`combustion-generator`/`turbine-generator`，`items.get(blastCompound) > 0` → `items.set(...,0)` + 停用 + 通告建造者 | `scanGenerators` |

## §3 关键运行时事实（都是踩出来的，v160.7 发布 jar）

- **`mindustry/entities/comp/` 在发布 jar 里根本不存在**（三个 jar 条目数都是 0），ECS 字段以生成物形式在 `mindustry/gen/`。`mindustry/gen/Building.class` 上 `public boolean enabled`（flags 0x81）⇒ `b.enabled` 可直接读写；源码 `BuildingComp.java` 里的 `transient boolean enabled` 只是编译期形态，别照着源码找类。
- **Rhino 里 `Packages.xxx.MyClass` 是 NativeJavaClass，只暴露 static 成员**：`getDeclaredField/getField/getSuperclass/getName` 这些 `java.lang.Class` 实例方法一律不可达（抛 `InternalError: Java class "..." has no public instance field or method named "getField"`，或静默 null）。要反射必须 `Packages.java.lang.Class.forName("全名")` —— 返回真 Class，实例方法全可用。`NetServer$VoteSession.target` 是 package-private（modifiers 0），靠这条才能读到，否则整条 votekick 功能是死的。
- 队伍 0 = `Team.derelict`；官方 `switchTeam` 就是 `other.team(team)`（NetServer.java:912-916），插件同路径。转旁观前 `clearUnit()`。
- 封禁：`admins.banPlayerID(uid)` / `unbanPlayerID(uid)` / `getBanned()`（`banPlayer` 会连 IP 一起封，这里只用 ID）。
- 处理器停用：`b.executor.load(LAssembler.assemble("", privileged))` —— 不是"改代码"，是把它换成空程序；热量扫描用的 `NuclearReactor` 在 `enabled == false` 时确实会让 `heat` 按 `ambientCooldownTime` 衰减（NuclearReactor.java:101-110），所以"停用到热量归零再恢复"成立。
- 服务器/单机判断：`Vars.net` 为 null（单机）或 `net.server()` 为真，才准备写名单/踢人；`net.active()` 且非 server 时所有写操作只弹提示（客户端那份不该自己动手）。
- `Logic.update()` 每帧无条件 `Events.fire(Trigger.update)` ⇒ 服务端也会跑到我们的 `tick()`。
- 无头/服务端加载模组的正确目录是 `<workdir>/config/mods/<mod>/`，**不是** `<workdir>/mods/`（后者 45 s 里一条 mod 行都没有）。

## §5 装机

`out/_dist/GTB-0.1.0/install.ps1 -Silent` → `E:\Program Files (x86)\Steam\steamapps\common\Mindustry\saves\mods\GriefToBan`（Steam 版数据目录，依据 `Vars.java:494-495`；**不是** %APPDATA%）。装后 8 文件字节数与包内一致，`mod.hjson version: "0.1.0"`。卸载 = 同目录 `uninstall.ps1`。

**装完要重启游戏才会加载**（模组只在启动时扫描 mods 目录）。已装的 MAI 0.24.1 不受影响：两个模组各自一个目录，事件钩子互不干扰。

## §6 已知限制 / 待真机验

1. **爆混发电机**：清空背包 + 停用是"事后处置"，不是拦截填充动作（v160 没有"填充"事件可钩）。停用后玩家可以手动重新启用 —— 但下一次扫描（3 s）会再清一次、再停一次。
2. **钍堆离核心过近**只警告不处置（按需求原文）。
3. **AFK 判据**用 `aimX/aimY` 不动，不区分"在看地图"与"真挂机"；玩家把单位停在原地但一直瞄准同一方向也会被判 AFK（默认 3 分钟）。
4. **病毒逻辑**只认 `ucontrol build ... @this` 这一种自复制写法（与检查器同一判据）；用 `sensor` 读别人处理器再写的变种不认。
5. **votekick** 靠反射读包私有字段，Mindustry 大版本改 `VoteSession` 结构就会失效（失效时功能静默降级：不转旁观，不报错）。自检里有一条 `field VoteSession.target` 专门盯这个。
6. **更新检查**只有按钮与版本比较，GitHub 仓库还没建（`https://github.com/EnernalIliary/MAI-GriefToBan` 是占位）。
7. 真机未验：语言黑名单是否真按 `player.locale` 生效（不同客户端的 locale 写法有 `zh_CN`/`zh`/`zh_cn` 三种，lib 已做归一化）、设置界面在手机端窄屏的排版、`admins.banPlayerID` 与插件名单同时开启时会不会重复封。
