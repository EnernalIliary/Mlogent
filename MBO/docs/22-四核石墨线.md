# 22 四核石墨线：4 台压机 = 2.67/s

> 用户 m03391：「试试增加到四核，四个石墨厂」。
> 目标：把石墨线从 1 台/2 台压机扩到 **4 台**，用脚本搜索出候选，再上真机验证。

## 0 硬约束先说清楚

| 量 | 值 | 推论 |
|---|---|---|
| 单台 `graphite-press` | 90 帧/周期 = 0.6667 次/s，每周期 2 coal → 1 graphite | 4 台理论上限 **2.6667/s** |
| 4 台的煤需求 | 2 × 2.6667 = **5.3333/s** | **单格物流上限 4.9/s ⇒ 至少 2 个输入口** |
| 端口规则 | 源/黑洞必须落在工厂外接矩形之外（docs/19） | 4 台排成一行时，中间两台四面都被机器挡住，出口只能往上/下拐 |
| 吞吐由物流定（docs/19） | 最大流模型 + 真机侧向投料会掉速 | 优先"每台直连一个黑洞"，其次才谈合流 |

## 1 为什么先写 spike，而不是直接改 `mbo/search.py`

`mbo/search.py` 的枚举族写死两件机器：`_machine_spec` 只接受 2 台、`_arrangements` 只给两个位置、
`_bridges` 只找"同时贴两台机器"的格子。四核的形状空间（4 台的排布 × 喂料 × 排料）结构不同，
所以这一轮先落在 `spikes/gen/`，跑通并真机验证后再决定要不要并进生产枚举（见 §6）。

## 2 两版失败尝试（保留原因，避免下次再踩）

**v1 `spikes/gen/search_quad.py`：贪心 beam 构造。**

从 4 台机器出发，每步往"贴着已有方块的空格"加方块（带子 4 向 / 两种门 4 向 / 路由器 / 端口），
用 `logistics.estimate` 打分，beam 保留前 N 个状态。

- 只收敛到"每台机器一套源 + 一个黑洞"的贪心解：**8 端口 / 16 工厂格 / 预测 2.6667/s**；
  把端口数卡到 ≤4 时 **0 可行**。
- 根因：**贪心按分数排序，而"源贴着机器"立刻有输入分、"源 → 门 → 两台机器"要先放门（分数为 0），
  所以少端口结构永远搜不出来**。这是 beam search 在多步协同结构上的典型失效，不是参数问题。
- 另一条教训：**不能把连接件限制在机器外接矩形内**——带子/门本身会把工厂矩形撑大，
  只有端口必须在"最终"矩形外。

**v2 两阶段 beam（`want="in"` 只加源+连接件、`want="out"` 只加黑洞+连接件，端口限制在"当前矩形之外"）**
仍然 `--caps 2,1` 无解，结论同上：**缺的是结构化枚举，不是更强的启发式**。

## 3 生效的结构化枚举：`spikes/gen/search_quad3.py`

三块独立枚举，笛卡尔积后统一交给 `mbo.search.evaluate`（端口在外 + 物流最大流）验收：

| 维度 | 方案 |
|---|---|
| 排布 `arrangements(4)` | 叠放/横排/2×2 共 8 种，缝宽 0–2（`row0-2`、`col0-2`、`grid0-1`） |
| 喂料 `feed_pair` | 找**同时 4-邻接两台机器**的桥接格放反溢门，门旁再贴一个源；**2 个门 + 2 个源喂 4 台** |
| 喂料 `feed_per` | 每台机器各贴一个源（4 个源） |
| 排料 `sink_single` | 每台机器 BFS 找 ≤6 格带子路径，通到矩形外的黑洞（能直连就不放带子） |
| 排料 `sink_groups` | 一组机器共用一个黑洞（多条带子从不同侧投进去） |
| 排料 `sink_router_pairs` | 两台机器的带子先进同一台路由器，路由器再贴黑洞（12 格双端蓝图的手法） |

`GRID=(21,17)`，一次全枚举约 30 s，得到去重后 **600 张可行候选**，按 (端口数, 工厂格) 只有两档：

```
  ports=6 tiles=18 →  24 张
  ports=8 tiles=16 → 576 张
```

## 4 真机结果（1800 tick，warmup 13 s）

| run | 形状 | 端口 | 工厂格 | 蓝图尺寸 | 静态 | 真机 | 判定 |
|---|---|---|---|---|---|---|---|
| `runs/q8` | 4 台横排 + 每台一个源/黑洞 | 8 | 16 | 9×4 | OK（端口全在外） | **2.7081/s**（+1.6%） | **PASS** |
| `runs/q6` | 4 台横排 + 2 门喂 2 源 + 每台一个黑洞 | 6 | 18 | 12×4 | OK（端口全在外） | **2.7026/s**（+1.3%） | **PASS** |

两条都 `verify` 通过、`gate 12/12`；画廊 20 个 run。

### 8 端口 / 16 格（`runs/q8`，最省格）

```
   S S S        S=物品源  M=石墨压机  x=物品黑洞
SMMMMMMMM
 MMMMMMMM
 x x x x
```

方块：4×`graphite-press`(1,1)(3,1)(5,1)(7,1) + `item-source` (0,1)(3,0)(5,0)(7,0)
+ `item-void` (1,3)(3,3)(5,3)(7,3)。每台机器的输入、输出都直连，**没有中间物流元件**。

### 6 端口 / 18 格（`runs/q6`，少两个端口）

```
    x  x  x
xMM MM MM MM
 MM+MM MM+MM
   S     S
```

方块：4×`graphite-press`(1,1)(4,1)(7,1)(10,1) + `underflow-gate`(3,2)(9,2)
+ `item-source`(3,3)(9,3) + `item-void`(0,1)(4,0)(7,0)(10,0)。
一个门喂两台机器（门直行位朝东接 P2，西侧进 P1），源贴在门下方；**2 个源就够喂满 4 台**。

## 5 复现

```powershell
cd MBO
python -X utf8 spikes/gen/run_quad.py --ports 8 --out q8     # 2.708/s
python -X utf8 spikes/gen/run_quad.py --ports 6 --out q6     # 2.703/s
python -X utf8 spikes/gen/quad3_front.py                     # 只出 Pareto 前沿
python -X utf8 -m mbo preview q8 --scale 12                  # 贴图预览
```

`run_quad.py` 会重建全部候选（确定性，约 30 s），再挑 `ports` 指定的那一档里最省格的一张，
跑静态校验 + 真机 + 写 `runs/<id>/`（5 件产物）。

## 6 局限与下一步

1. **4 端口（2 源 + 2 黑洞）这一档没搜到可行解**。路由器合流方案（`sink_router_pairs`）已经实现，
   但 4 台横排时中间两台被机器围住，"端口必须在矩形外"逼着合流点往上下两端挤，
   本轮的枚举没铺出合法形状。**这是下一步最值得攻的点**（类比双端的 12 格）。
2. 物流模型是**容量模型**，不建模"侧向投料掉速"（docs/19 实测三条带子侧向合流只有 0.795/s）。
   本轮两档都没有侧向合流，所以预测与真机只差 1.3–1.6%。
3. 本轮只做了"刚好 4 台"；把 N 台并进 `mbo/search.py` 生产枚举（放宽 `_machine_spec`）
   要等形状空间稳定后再做，否则枚举器会被一次性需求绑死。
