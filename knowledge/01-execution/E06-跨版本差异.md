# E06 跨版本差异

## 一句话

本项目有**两个权威**：语义看 `v159.3` 源码树（tag v159.3，HEAD 5811844），数值看 `v160.7` jar 反射 + 真机 —— 源码比线上落后一个次版本，所以「源码没写」不等于「游戏没有」。 [src: knowledge/VERSION.md:1]

## 规则 / 公式

### 1. 双权威分工（VERSION.md）

| 权威 | 位置 | 用来回答 |
|---|---|---|
| v160.7_rt | `out/_server160.jar` 反射、`MBO/gamedata/v160.7/`、真机 | 数值、枚举集合、实际行为 | [src: knowledge/VERSION.md:1]
| v159.3_src | `Mindustry-Source/core/src/mindustry`（tag v159.3） | 语义、执行流程、字段顺序 | [src: knowledge/VERSION.md:1]

数值优先级：**jar 反射 > v159.3 源码 > 真机实测 > 自写手册 > 其它副本**。 [src: knowledge/VERSION.md:1]

### 2. 已确认的版本差异

| 项 | [v159.3] | [v160.7] | 证据 |
|---|---|---|---|
| `status` 的状态名 | 只认**裸名**（`wet`） | 裸名与 `@status-wet` **等效** | 断言表 L1-23/L1-24 |
| `op select` | 正常可选 | **被静默换成 noop**（`@RegisterStatement("noop")`），指令下标不变 | L1-25 |
| LAccess 集合 | 无 `enabled` / `color` | **有**（共 77 项） | `tools/sensor_attrs.json` 的 `added_2026_10_25` |
| world processor 速率上限 | 源码为 8 ipt / 40 clamp | **maxInstructionsPerTick=1000** | Blocks.java:6949-6960 vs jar |
| 存档 build 号 | — | build 160 存档**只能用 v160 载入** | 断言表 L3-04 |

### 3. 写法约定（本项目强制）

可能随版本变的行为必须**并排写**：

```text
[v159.3] status 槽只认裸名 wet。
[v160.7] status 槽裸名与 @status-wet 等价。
```

只在单版本成立的结论，frontmatter 的 `ver` 只列该版本（如 `ver: [v160.7_rt]`）。

### 4. 文档冲突清单（**不要继承**）

| 冲突 | 错误说法 | 正确 | 证据 |
|---|---|---|---|
| status 参数 | status 用 true/false | 源码字段是 boolean `clear`，写作 true / false | L2-22 |
| ulocate 参数 | 前几槽是坐标输出 | 第 1 槽是 locate 枚举，outX/outY 在 4/5 槽 | L2-23 |
| radar | 第 6 槽是数量 | 是**排序方向 ±1**，输出只有一个 | L2-17 |
| uradar | 7 参都有用 | 第 5 槽是死槽（源码传 null） | L2-17 |
| 单位速度 | `@velX` / `@velY` | `@velocityX` / `@velocityY` | L2-24 |
| `cmd_index.json` 的参数序 | getblock/setblock/weathersense/spawnwave/playsound 顺序错 | 以 md 的 `## 导出格式` 为准 | `06-mlog/instructions.json.meta.discrepancies` |
| 旧 data 表 | `craftTime` 447 条全 -1 | 不可用 | VERSION.md |
| 文档「耗电」列 | 说是每单位时间 | 实际是**每 tick** | VERSION.md |
| `instr_semantics.json` | 三个尺寸版本并存 | 以 `tools/` 的 **56.5KB** 为准 | VERSION.md |

### 5. 如何判断「这条是不是版本差异」

1. 先查 jar 反射产物（`tools/*.json` 的 `source`/`version` 字段）。
2. 再查 v159.3 源码；若源码没有而 jar 有 ⇒ **新版本新增**，标 [v160.7]。
3. 两者都有但行为不同 ⇒ 真语义变更，必须实测（真机/模拟器）后并排写。
4. 只有手册有 ⇒ 降级为 **U**，并写「需要什么实验」。

## 实测与反例

- ✅【E】`op select` 在 v160.7 静默变 noop（L1-25）；这条在 v159.3 源码里看不出来，**只能靠实测发现** —— 反例：只读源码会漏掉这类「版本漂移」。 [实测: docs/断言表.md]
- ✅【E】`status` 的裸名/`@status-` 双写法差异（L1-23/24）说明「文档写的槽位对但取值集合变了」。
- 反例（不成立边界）：**「源码 = 线上行为」不成立**。源码落后一次版本，至少 2 处已确认差异。
- 【U】如何可靠判断「模拟器跑的是哪个版本」未固化进探针；需要读 `_server160.jar` 的 manifest 或 `Vars.build`。

## 常见误解

1. 「源码里没有就是没有」——可能是新版本新增。
2. 「手册里的数字都能用」——`craftTime` 全 -1、耗电列单位错，必须先查 VERSION.md 的已知错误。
3. 「三个 instr_semantics 随便用一个」——只认 `tools/` 的 56.5KB 版。
