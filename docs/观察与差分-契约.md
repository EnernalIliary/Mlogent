# 观察与差分：接口契约（规划 §3）

> 本文是 `tools/observation.py` 与 `tools/differential.py` 的实现约定。两个模块由不同
> 的人/代理写，**先按本文对齐，再写代码**；契约变了要同时改这两个模块和本文。

## 为什么需要它

`mlogsim` 跑的是真执行器 + 真单位更新，但没有波次 AI、没有完整地形碰撞；`mlog-server`
（`tools/world_server.py` 起的常驻世界）是真实游戏世界，但贵、慢、要人在。规划 §3 要求
把同一个 Scenario 交给两边，**比较它们给出的观察**，从而知道"离线通过"离"游戏里通过"
有多远。差异本身不是 bug，是保真度边界（§3 P2）。

## 一、观察 Schema：`mlog-observation/v1`

一个观察是一次运行的**全部可观测量**，两种来源同构：

```json
{
  "schema": "mlog-observation/v1",
  "source": "sim",                     // "sim" | "world"
  "scenario": "unit-control",          // 场景 id/name
  "ticks": 60,
  "summary": {
    "ok": true,                        // 这次运行本身有没有炸（不是断言结果）
    "errors": [],                      // 运行期错误文本，逐条
    "instructions": null,              // 能拿到就给（sim 有，world 一般没有）
    "elapsed_ms": 1234
  },
  "state": {
    "logs": {"p": {"x": "7", "flag": "true"}},
    "units": [
      {"id": 123, "type": "flare", "team": "sharded", "controller": "LogicAI",
       "x": 12.5, "y": 30.25, "hp": 90.0, "amount": 0}
    ],
    "buildings": [
      {"block": "container", "x": 10, "y": 10, "team": "sharded",
       "items": {"copper": 30}}
    ],
    "core": {"items": {"copper": 500}, "x": 20, "y": 20}
  },
  "events": [
    {"tick": 12, "type": "ucontrol", "logic": "p", "detail": "move 12 30"},
    {"tick": 13, "type": "print",   "logic": "p", "detail": "hello"},
    {"tick": 19, "type": "shoot",   "logic": "p", "detail": "flare"}
  ],
  "env": {
    "mindustry": "v160.7",             // 版本串，两边的来源不同，比较时只看 major
    "java": "21.0.5",                  // 可为 null
    "map": "blank-64",                 // 地图名/形状描述
    "world_size": [64, 64],
    "team": "sharded",
    "update": "all",                   // sim 的 --update，world 固定 "live"
    "sampling": "every-tick"           // "every-tick" | "final" | "poll"
  }
}
```

约定：

- **所有数值都是数字**，不要留字符串（`"7"` 只出现在 `logs`，因为 mlog 变量天然是字符串）。
  没有的值写 `null`，不要省略键——省略会让 diff 分不清"没有"和"零"。
- `events` 按 `tick` 升序；同一 tick 内保持观测顺序。
- `source="world"` 时 `instructions` 与 `elapsed_ms` 允许为 `null`。
- 单位坐标是**格**（tile），不是像素；world 侧读出来若是像素要除以 8。
- `id` 只在同一侧内稳定，跨侧不比较。

## 二、`tools/observation.py` 的 API

```python
SCHEMA = "mlog-observation/v1"
SOURCES = ("sim", "world")

def make(source, *, scenario, ticks, summary=None, state=None,
         events=None, env=None) -> dict:
    """按 schema 填空；缺的键补 null/空容器，保证两个来源形状一致。"""

def from_scenario(sim: dict, *, scenario: str = "", ticks: int | None = None) -> dict:
    """把 tools/scenario.py 的 `_sim()` 结果（finals/samples/refs/report/ticks）
    转成观察。`report` 里的 placed/configured/stocked/linked/units 进 env 的
    scene 段（新增键 `scene`，允许超出上面的最小 schema）。"""

def from_world(payload: dict, *, scenario: str = "") -> dict:
    """把 world 侧抓到的原始 dict 转成观察。payload 结构见第五节。"""

def normalize(obs: dict) -> dict:
    """排序 events、数字统一成 float/int、logs 值转字符串。幂等。"""

def compare(a: dict, b: dict, spec: dict | None = None) -> dict:
    """返回 {"same": bool, "checked": int, "differences": [...]}。

    每条 difference：
      {"path": "state.units[flare#0].x", "rule": "tolerance",
       "left": 12.5, "right": 13.1, "detail": "|Δ|=0.6 > 0.5"}
    """

def parity(a: dict, b: dict) -> dict:
    """只比 env：{"same", "checks": [{"field","left","right","ok"}], "notes": [...]}。

    硬比较（不一致 = 失败）：map、team、world_size、mindustry 的 major。
    只记 note（不判失败）：update、sampling、以及只有一侧报告的字段。
    """

def report(a, b, *, spec=None, scenario="", level="summary") -> dict:
    """差分结论包进 mlog_eval 信封：不一致时 failure_type=
    "simulation_real_difference"，diagnostics 里逐条列出 differences，
    next_steps 指向 Fidelity Envelope（不是让人去改场景）。"""
```

`compare` 的默认 spec（也是 `SPEC` 常量）：

```python
SPEC = {
    "logs":      {"mode": "exact"},
    "units":     {"mode": "match", "key": ["type"],
                  "fields": {"x": 0.5, "y": 0.5, "hp": "5%"}},
    "buildings": {"mode": "match", "key": ["block", "x", "y"],
                  "fields": {"items": "exact"}},
    "core":      {"mode": "exact"},
    "events":    {"mode": "ordered", "key": ["type"], "tick_tolerance": 3},
}
```

规则语义：

| mode | 含义 |
|---|---|
| `exact` | 值与结构都严格相等（数字先规范化，`7` 与 `7.0` 视为相等） |
| `tolerance` | 数字允许绝对误差；字段级 `0.5` 表示绝对容差 |
| `match` | 按 `key` 字段配对后再比 `fields`；配不上的条目算 difference（`left`/`right` 写 `null`） |
| `ordered` | 事件按 `key` 做**子序列**匹配，允许插入，但相对顺序必须一致；`tick` 允许 `tick_tolerance` |

`"5%"` 表示相对容差（相对两侧较大值）。字符串比较前 `strip()`。

**parity 的两种落地是硬约束**：一个 env 字段要么进 `checks` 并给出 `ok`，要么进 `notes`
并说明为什么不算失败，不许两边都不出现。`update` 是宿主驱动时钟的方式（离线侧自己步进、
活世界跑真实 60 Hz 循环），按构造就不同，判失败会让每一对诚实的 sim/world 观测都红；
`sampling` 是录制精度；只有一侧报告意味着「没记录」而不是「环境不一致」。

**不许**用 `json.dumps(a) == json.dumps(b)` 这种整体比较——规划明确禁止。

## 三、`tools/differential.py` 的 CLI

```
python tools/differential.py run scenes/scenarios/unit-control.json
python tools/differential.py run SCENARIO --spec spec.json --json
python tools/differential.py parity SCENARIO          # 只比环境
```

- 先跑 sim（`scenario.run(sc, via="sim", level="diagnostics")`），再跑 world
  （`scenario.run(sc, via="world", ...)`），两边都转成观察后 `compare`。
- world 侧不可用（没起世界 / 没 JVM / 没 jar）→ `failure_type="unsupported_environment"`，
  **exit 3**（干净 checkout 的惯例），不要伪装成差异。
- 两边都跑通且一致 → `ok=True`，`artifacts` 里给出两侧观察的 `observation_ref`
  （走 mlog_eval 的 artifact 机制，summary 档只回摘要）。
- 不一致 → `ok=False`、`failure_type="simulation_real_difference"`，diagnostics 逐条列。

`scenario.py` 的 `via="world"` 由本阶段真正实现：铺场景 → 跑够 tick → 读回逻辑变量 →
产出与 `via="sim"` **同构**的 `_sim()` 结果（`finals`/`samples`/`refs`/`report`），
这样上层的观察、断言、信封都不用分叉。

## 四、测试与门禁

- `tests/observation/run_observation_tests.py`：纯数据，不需要 JVM。
  至少覆盖：exact/tolerance/match/ordered 四类规则、缺键、NaN/None、事件乱序、
  `parity` 的版本 major 比较、`report` 的 failure_type 与 exit code。
- `tests/differential/run_differential_tests.py`：没有世界/JVM 时 exit 3（SKIP）；
  有世界时跑一个最小场景做端到端。
- `gate.py` 增加一步 `observation`（纯数据测试，必须常驻）；差分测试与
  `mindcode`/`scenario` 同档（exit 3 = SKIP）。

## 五、world 侧抓取的原始 payload

`scenario.run(via="world")` 内部通过 `tools/world_client.py` 调 `world_server`：

1. `scene <绝对路径>` —— 铺场景（`world_scene` 的 CLI 形态）。
2. 让世界跑 `ticks` 个 tick（`world_pause` 关 + 轮询，或 server 的 tick 计数）。
3. `scene_probe <路径>` —— 按场景 checks 读回逻辑变量，返回逐条判定。
4. `units --team ...`、`buildings --team ...`、`js` 读核心物品。

`from_world(payload)` 期望：

```python
{
  "scenario": "unit-control",
  "ticks": 60,
  "errors": [],                       # 服务端返回的错误文本
  "scene": {"placed": 3, "configured": 3, "errors": []},
  "logs": {"p": {"x": "7"}},          # 处理器变量表（world_logic_vars 的合并）
  "units": [{"id": 1, "type": "flare", "x": 12.5, "y": 30.25, "hp": 90.0,
             "team": "sharded", "controller": "LogicAI", "amount": 0}],
  "buildings": [{"block": "container", "x": 10, "y": 10, "items": {"copper": 30}}],
  "core": {"items": {"copper": 500}},
  "events": [{"tick": 12, "type": "print", "logic": "p", "detail": "hello"}],
  "env": {"mindustry": "v160.7", "map": "groundZero", "world_size": [200, 200],
          "team": "sharded", "update": "live", "sampling": "final"},
}
```

world 侧拿不到逐 tick 事件时 `sampling="final"` 且 `events` 可以为空——
`compare` 会把"一侧没有事件"记成 note 而不是 difference（`SPEC["events"]["optional"]`）。
