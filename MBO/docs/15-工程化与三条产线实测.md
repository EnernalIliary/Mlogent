## 1. 包结构（`MBO/mbo/`）

| 模块 | 职责 | 关键出口 |
|---|---|---|
| `gamedata.py` | L0 游戏数据快照 | `GameData()`、`Block`、`Recipe`（`craft_time_frames` + `cycles_per_second`） |
| `codec.py` | L1 二进制层 | `read/read_bytes/write/to_base64/body_of/semantic_tiles`、`build_schematic_ext` |
| `model.py` | L1 IR | `Tile`、`Layout`（中心格坐标 R1、occupancy 自检 R7）、`ROT`/`DIRV`/`BELT_RATE` |
| `production.py` | L2 生产 | `expand(gd,target,rate,boundary,force)` → `Plan(machines, demand, power_need)` |
| `layout.py` | L2 空间 + 物流 + 电力 | `build(gd,plan,canvas)`、`route_power` |
| `validate.py` | 静态校验 | `static_check(lay,gd,plan)` → `{ok,errors,warnings,info}` |
| `engine.py` | L4 真机 | `run(lay,gd,target,ticks)` → `{rate,window,eff,power_sat_min,deadlock,…}` |
| `report.py` | 产物 + Gate | `write_run()` 写 5 件产物、`_verdict` |
| `cli.py` | 入口 | `python -m mbo calc\|gen\|verify\|build-snapshot` |

约束来源：`docs/13` R1–R7 已逐条落在 `model.py`/`layout.py`/`validate.py`/`engine.py` 里（中心格、place 中心锚、显式 power config、consumer 邻接、禁 `Groups.build`、occupancy 自检）。

## 2. 三条产线实测细节

### 2.1 石墨 1/s（最简，零电力）

- 规划：`graphite-press ×2`（0.6667/s 每台），边界 coal 2.667/s，耗电 0。
- 布局：每条输入一行 `item-source → conveyor×2 → 机器 → container`，两台上下排。
- 静态：10 blocks / 22 tiles / 无电力需求。
- 真机：窗口 308→1801 tick（24.88 s），容器 Δ34 个 → **1.3666/s**，`eff_avg=1.0`、`eff_low=0`、无死锁。

### 2.2 玻璃 4/s（有电力，输入两种）

- 规划：`kiln ×2`（2.0/s 每台），边界 lead 4/s + sand 4/s，耗电 72/s。
- 布局：每台 kiln 两条输入支线（lead、sand 各一行）；布线器自动放 2 个 power-node（贴 kiln）+ 1 个 power-source，连通块 1。
- 真机：窗口 308→1804 tick → **4.0119/s**，`sat_min=1.0`、`eff_avg=1.0`。

### 2.3 硅 3/s（E1 目标，有电力 + 两种输入）

- 规划：`silicon-smelter ×2`（1.5/s 每台，恰好 3.0/s，无超产），边界 coal 3/s + sand 6/s，耗电 60/s。
- 布局：19 blocks / 31 tiles，2 node + 1 source，连通块 1。
- 真机：窗口 311→1812 tick → **2.9581/s**（−1.4%），`eff_avg=1.0`、`power_sat_min=1.0`。
- `verify`：重建 19 建筑/31 格，重编码 body 与 `blueprint.msch` 逐字节一致。

## 3. CLI 契约（与 docs/02 §2.2 对齐）

```
python -X utf8 -m mbo calc  <item:rate> [--boundary a,b] [--force item=block]
python -X utf8 -m mbo gen   <item:rate> [--boundary a,b] [--canvas 24x24] [--out NAME]
                                        [--ticks 1800] [--timeout 180] [--no-engine]
python -X utf8 -m mbo verify <run_id> [--engine]
python -X utf8 -m mbo build-snapshot [--from spikes/data/gamedata.json]
```

- 退出码：`0` 通过 / `2` 静态失败（或 verify 字节不一致）/ `3` Gate 失败。
- `--no-engine` 只做静态校验，`metrics.verdict.gate_checked=false`，报告写"不计入 Gate"。

## 4. 一次运行的 5 件产物（`MBO/runs/<run_id>/`）

| 文件 | 内容 |
|---|---|
| `blueprint.msch` | 二进制蓝图（可拖进游戏 / 可被 `tools/msch.py` 解析） |
| `blueprint.b64.txt` | 游戏内粘贴码（一行 base64） |
| `metrics.json` | 预测、静态结果、真机采样全量、Gate 判定 |
| `report.md` | 人读的结论、复制粘贴按钮（提示 `paste` 到游戏） |
| `trace.json` | 重建所需的全部输入：布局快照（含 config tag）、画布、参数、快照 id、复现命令 |

## 5. 实现要点（踩坑后固化的规则）

1. **配方选择打分**：`(是否引入新边界, 超产量, 机器数, 占地, 名字)`。闭包 `servable()` 保证只选"边界内可造"的配方，避免误选 Erekir 的 `silicon-crucible`/`arc-furnace`（E1 因此稳定选中 `silicon-smelter ×2 = 3.0/s`）。
2. **采样口径**：丢前 300 tick；`rate = Σ容器增量 / 窗口秒`；`deadlock = eff_avg<0.05 且 progress 不涨`。
3. **世界坐标**：`place()` 以蓝图中心为锚，读数时 `ox=64-w//2`，否则多格方块全读成 `null`（这个 bug 让 s3 首次跑出 0/s）。
4. **采样行解析**：`SAMPLE\t<tick>\t<payload>`，tick 是第 2 个字段；`srv.js()` 每次只可靠返回一行。
5. **verify 的强校验**：`trace → Layout → to_bytes()` 必须与归档 `.msch` 的 **body 逐字节一致**；不一致直接退出码 2。这保证了"报告里的蓝图 = 磁盘上的蓝图 = 粘贴码里的蓝图"。
6. **`--no-engine` 不算 Gate**：`gate_checked=false`，避免"静态绿了就说通过"。

## 6.5 人工审阅快照（`mbo preview`）

生成物是二进制/JSON，肉眼不友好。`preview` 从 `runs/<id>/trace.json` 重建布局并画成俯视图（不需要开游戏）：

```powershell
python -X utf8 -m mbo preview s3            # → runs/s3/preview.png（默认 2x 像素）
python -X utf8 -m mbo preview s3 --ascii    # 终端里直接看字符图 + 预测/实测
python -X utf8 -m mbo preview s3 --scale 3  # 更大，方便截图
python -X utf8 -m mbo preview --all         # → runs/index.html 画廊（所有 run 一页看完）
```

图例：紫=物料源，灰=物流（箭头=朝向），绿=生产，橙=产物仓，黄=电力节点/电源（黄线=links），红=核心。
ASCII 图例：`S` 物料源 / `n` 电力节点 / `P` 电源 / `M` 机器 / `>v<^` 朝向 / `C` 产物仓。

三种审阅层次（推荐都过一遍）：
1. **字符图**（秒级）：看拓扑是否对——源在左、带子向右、机器相邻、产物仓在右、节点贴着机器。
2. **PNG**（秒级）：看电力连线有没有乱飞、有没有压在方块上、占地是否紧凑。
3. **真游戏**（权威）：把 `blueprint.b64.txt` 一行粘进游戏（或 `blueprint.msch` 拖进去）。只有这一层能证明"真的能转、真的产得出来"。

> 局限：PNG 是**示意俯视图**，不是游戏渲染；不表现传送带上的实际物品、不做贴图，只保证方块位置/朝向/电力连线与蓝图一致。
