# M06 世界交互

## 一句话

世界处理器（world processor）是**唯一能改世界状态**的执行体：可写规则、生成单位、放炸弹、开关建筑；普通处理器只能读世界 + 改自己链接到的方块。

## 规则 / 公式

### 1. 特权判定

`LogicBlock.java:559-562`：

```java
if(!privileged) ipt = instructionsPerTick;          // 非特权只能用自己的 ipt
if(disableWorldProcessors && privileged) return;    // 房主可一键禁用世界处理器
```

| 处理器 | privileged | ipt | max/tick | range |
|---|---|---|---|---|
| micro / logic / hyper | false | 2 / 8 / 25 | 40 | 80 / 176 / 336 tile |
| world processor | **true** | 8 | **1000** | 无限 |

### 2. control：改自己链接到的方块

`control <类型> <目标> <p1> <p2> <p3> <p4>`，类型是 ControlType 枚举（5 个）：

| 类型 | 作用 | 参数 |
|---|---|---|
| enabled | 开关方块 | p1 = 布尔 |
| config | 写配置（如工厂选配方） | p1 = 配置对象/数值 |
| color | 写颜色 | p1 = 颜色值 |
| shoot | 朝坐标开火 | p1,p2 = 目标；p3 = 是否射击 |
| shootp | 朝单位开火 | p1 = 单位；p2 = 是否射击 |

**坑**：源码对 `p1..p4` **每次全部求值**（LExecutor.java:577/584），即使用了不上的槽也会读取；所以把未定义变量放进无用槽不会有副作用，但把 **表达式/带副作用的操作**放进去会照样执行。

### 3. setrule：改游戏规则（LogicRule 29 项）

`setrule <规则> <值> <p1> <p2> <p3> <p4>`，规则名是 LogicRule 枚举 token：

| 组 | 规则 |
|---|---|
| 波次 | currentWaveTime, waveTimer, waves, wave, waveSpacing, waveSending, attackMode |
| 地图 | enemyCoreBuildRadius, dropZoneRadius, unitCap, mapArea, lighting, canGameOver, ambientLight, solarMultiplier, dragMultiplier |
| 玩家管理 | ban, unban, pauseDisabled |
| 数值倍率 | buildSpeed, unitHealth, unitBuildSpeed, unitMineSpeed, unitCost, unitDamage, blockHealth, blockDamage |
| AI | rtsMinWeight, rtsMinSquad |

只有 `mapArea` 会读 p1..p4（矩形四角），team 倍率类规则读 p1；其余只读 value（LExecutor.java:1786/1812）。

### 4. world processor 的 26 条指令（按用途分组）

| 组 | 指令 | 说明 |
|---|---|---|
| 方块读写 | getblock, setblock | **首槽是 layer**：`getblock <layer> <result> <x> <y>`、`setblock <layer> <block> <x> <y> <team> <rotation>` |
| 实体生成 | spawn, bullet, explosion, effect, spawnwave | 坐标是 tile |
| 规则/环境 | setrule, weathersense, weatherset, message, localeprint | |
| 单位/玩家 | fetch, clientdata, query, sync | fetch 的 FetchType 8 项 |
| 交互 | cutscene, setmarker, makemarker, playsound, playmusic | 只影响客户端观感 |
| 状态 | getflag, setflag, setprop | flag 用于跨处理器传值（数字） |

`fetch <类型> <结果> <team> <index> <extra>`：FetchType = unit, unitCount, player, playerCount, core, coreCount, build, buildCount（8 项）。

### 4b. TileLayer：四层与可写性

源码 `Mindustry-Source/core/src/mindustry/logic/TileLayer.java`：

```java
public enum TileLayer{
    floor,
    ore,
    block,
    building;
    public static final TileLayer[] all = values(), settable = {floor, ore, block};   // :9
}
```

| 层 | 含义 | getblock 返回 | setblock 可写 | 源码 |
|---|---|---|---|---|
| floor | 地板（含空气） | `tile.floor()` | ✅ 只接受 Floor 且非 overlay/air | GetBlockI:1530 / SetBlockI:1567-1571 |
| ore | 矿脉（overlay） | `tile.overlay()` | ✅ 只接受 OverlayFloor 或 air | GetBlockI:1531 / SetBlockI:1564-1566 |
| block | 方块 | `tile.block()` | ✅ 接受非 floor 方块（air 可清空） | GetBlockI:1532 / SetBlockI:1572-1580 |
| building | 建筑实例 | `tile.build` | ❌ **不可写**（`settable` 不含 building） | GetBlockI:1533 / SetBlockI:1582 `//building case not allowed` |

**layer 在 0 号槽，不是末槽：**

| 指令 | 正确文本（docs 与源码一致） | 错误文本（cmd_index.json 的写法） |
|---|---|---|
| getblock | `getblock <layer> <result> <x> <y>` | ~~`getblock <result> <x> <y> <layer>`~~ |
| setblock | `setblock <layer> <block> <x> <y> <team> <rotation>` | ~~`setblock <x> <y> <block> <team> <rotation> <layer>`~~ |

坐标是**整数格号**：`world.tile(Mathf.round(x.numf()), Mathf.round(y.numf()))`（GetBlockI:1525 / SetBlockI:1561）—— 不乘 8，直接写 tile 下标。目标格不存在（越界）时 getblock 把 result 置 null（:1526-1527）。

### 4c. message / cutscene / query 的四个一句话枚举

| 枚举 | 全部取值 | 语义要点 | 源码 |
|---|---|---|---|
| MessageType（`logic/MessageType.java`） | notify / announce / toast / mission | `mission` 是唯一在 headless 服务器也执行的；其余在服务器上被丢弃并清空文本缓冲 | MessageType.java:3-7 / LExecutor.java:1906-1909 |
| CutsceneAction（`logic/CutsceneAction.java`） | pan / zoom / stop | pan 读 p1,p2（tile，`World.unconv` 乘 8）与 p3 速度；zoom 只读 p1（clamp）；stop 关闭电影模式 | CutsceneAction.java:3-6 / LExecutor.java:1328-1341 |
| QueryType（`logic/QueryType.java`） | unit / building / bullet | **bullet 不可查询**：`queryable = {unit, building}`，源码对 bullet 直接 return（池化对象引用会失效） | QueryType.java:3-7 / LExecutor.java:1462 |
| QueryShape（`logic/QueryShape.java`） | circle / rect | circle 把 width 当半径、(x,y) 当圆心；rect 用 width/height | QueryShape.java:3-4 / LExecutor.java:1449-1457 |

`query <类型> <目标队伍> <x> <y> <w> <h> <result>`（7 参）另有两条易错点：

- 坐标是 tile，但源码走 `numfWorld()`（×8 转世界，LExecutor.java:1449）⇒ 可以写小数格。
- `team` 写 `@derelict` 之类的空队伍时源码遍历所有 present 队伍（LExecutor.java:1468-1471/1488-1492）。

`message <类型> <时长> <outSuccess>`：缓冲内容由之前的 `print` 累积；`@wait` 作为第三参会让它阻塞（counter-- + yield），否则用 outSuccess=0 表示「上一条还没消失，自己重试」（LExecutor.java:1911-1924）。

`cutscene` 在 headless 直接 return（LExecutor.java:1326）⇒ 纯客户端效果，服务器上跑世界处理器看不到变化。

### 5. 建造 / 拆除的预算口径

- 单位建造走 `ucontrol build` / `ucontrol deconstruct`：**一条指令一次动作**，速度上限由处理器 ipt 与规则 `buildSpeed`/`unitBuildSpeed` 共同决定。
- hyper 处理器 ipt=25 ⇒ 理论每秒 25×60=1500 次 build 调用，但实际建造受单位自身建造速度与方块造价限制，**调用数 ≠ 完成数**。
- 具体每 tick 能推进多少建造进度：**【U】未核实**，需要一次「unitBuildSpeed=1 下测单方块建成 tick 数」的实验。

## 实测与反例

- ✅【E】`--update all` 工厂会生产、`none` 不生产（断言表 L3-02）；`worldTick` 会跳过处理器避免双重执行（L3-03）。
- ✅【E】`build 160` 存档只能用 v160 载入（L3-04）。
- 反例（不成立边界）：**world processor 不是万能的**。它不能改存档结构、不能绕过 `disableWorldProcessors` 开关、也不能让逻辑屏在 headless 服务器上显示。
- 反例：**setrule 的倍率不会追溯**。改 `unitDamage` 只影响之后的伤害结算，已有血条不会重算。

## 常见误解

1. 「world processor 只是范围大」——它能改规则、生成实体，普通处理器不能。
2. 「getblock 先给坐标」——首槽是 layer。
3. 「control 只读用到的参数」——四个参数全部求值。
4. 「setflag 能存字符串」——flag 只有数字语义。
