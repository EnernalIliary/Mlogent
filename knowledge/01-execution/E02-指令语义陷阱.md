# E02 指令语义陷阱 30 条

## 一句话

mlog 的坑几乎都落在同一个根上：**它有 null（对象位），而 `num()` 把 null 读成 0**；其余是槽位顺序、1 tick 时序、固定上限三类。每条给出「错误写法 → 正确写法 → 原因」。 [src: knowledge/VERSION.md:1]

## 规则 / 公式

### A. 向量 / 坐标（4 条）

1. **坐标单位混用** —— ✗ `sensor x @unit result` 后直接当 tile 用 → ✓ 先除 8（`op div result result 8`）。原因：sensor 的 x/y 是世界像素，`tilesize=8`；而 getblock/setblock 吃 tile。
2. **radar 第 6 槽当成数量** —— ✗ `radar enemy any any distance turret 5 result` → ✓ 第 6 槽只放 `1` / `-1` / `0`（排序方向），输出只有 1 个。原因：defs=[6]，槽 6 是 ±1 的 order。
3. **uradar 第 5 槽放东西** —— ✗ 想用第 5 槽（building 过滤）的第 6 个参数 → ✓ 该槽是死槽，源码传 null、`buildFrom()` 返回 false。原因：7 参里第 5 槽不参与构建。
4. **getblock 先写坐标** —— ✗ `getblock result x y layer` → ✓ `getblock layer result x y`。原因：源码 layer 是 0 号 token；cmd_index.json 此处写错（见 instructions.json.meta.discrepancies）。

### B. 对象 / null（5 条）

5. **用 `equal x 0` 判「读到空」** —— ✗ → ✓ `jump ... equal x null`。原因：`LVar.num()` 对 null 返回 **0**（Lvar.java:56-58），而 `numOrNan()` 才返回 NaN。
6. **NaN 想当哨兵值** —— ✗ `op div r 1 0` 之后判 `equal r nan` → ✓ NaN 赋值会写进对象位（`setnum` :87-97：`invalid(value)` ⇒ `objval=null;isobj=true`），即整数意义上「变成 null」。原因：`invalid = NaN || Inf`。
7. **set 未知属性名** —— ✗ `set foo 1` 期待无副作用 → ✓ 它会**把 foo 写成 null 覆盖旧值**。原因：断言表 S-16 实测。
8. **未绑定的链接名当 sensor 目标** —— ✗ → ✓ 先判 `@links` 或用 `getlink` 校验；未绑定名作目标 ⇒ 结果为 null（S-17）。
9. **读空容器** —— ✗ 期待 0 → ✓ 判 null。原因：有 payload 容器时读出数量（vault=100），无容器时 mlog 层是 null（内部 Float.NaN）：`op equal b 0`→1、lessThan/greaterThan→0（S-14）。

### C. 数值（6 条）

10. **op select 二选一** —— ✗ `op select r c a b` → ✓ 用 jump 分支或 `op add`+乘法掩码。原因：v160.7 把 select 静默换成 noop（`@RegisterStatement("noop")`），指令下标不变，结果不写（L1-25）。 [实测: docs/断言表.md]
11. **读 @velX / @velY** —— ✗ 得 null → ✓ `@velocityX` / `@velocityY`（L2-24）。
12. **status 槽用裸名还是 @status-** —— [v159.3] 只认裸名 `wet`；[v160.7] 裸名与 `@status-wet` 等效（L1-23/24）。跨版本写 `@status-` 形式。
13. **颜色随手写大数** —— ✗ `draw color 99999999 0 0 0 0` → ✓ 每通道 0..255 后打包。原因：DisplayCmdStruct 每字段 **10 bit 有符号**，`unpackSign` 范围 **−511..511**（LogicDisplay.java:286-288），超范围语义按负数解释。
14. **用 equal 判数值相等** —— ✗ `op equal r a b` 对 null 与 0 都成立 → ✓ 需要严格区分时用 `strictEqual`（ConditionOp 8 项之一）。
15. **set 内置常量** —— ✗ `set @ipt 10` / `set @unit u` → ✓ `setrate` / `ubind`。原因：@ipt/@unit 是 `putConst`（LAssembler.java:27），SetI 静默丢弃。

### D. 时序（5 条）

16. **wait 0 当延迟** —— ✗ → ✓ 它只让出本 tick、**不扣预算**（L1-30）；要延迟 1 tick 用 `wait 0.0166`（参数单位是秒）。 [实测: docs/断言表.md]
17. **期待亚帧精度** —— ✗ `wait 0.5` 想等半帧 → ✓ 参数单位是**秒**（`wait 0.5`=30 tick），粒度 1 tick（L1-29，`curTime += Time.delta/60f`）。 [实测: docs/断言表.md]
18. **以为改 @counter 立刻跳转** —— ✗ 当前指令之后还想再执行 → ✓ 当前指令一定执行完，跳转在**下一条**生效（runOnce 先取后加）。
19. **以为所有指令都吃预算** —— ✗ → ✓ `yield` 分支在 `accumulator--` 之前 break，`wait`/`stop` 不扣点。
20. **靠处理器先后顺序同步** —— ✗ 两个处理器同 tick 的读写顺序**未定**（断言表 L3-05 待定）→ ✓ 用 `sync` 或 flag/memory 显式握手。

### E. 内存 / 文本（4 条）

21. **memory cell 越界** —— ✗ 写 `memory[63]`（memory-cell 只有 64 格、memory-bank 512 格；类默认 32 是被实例覆盖的值）→ ✓ 先读 `@memoryCapacity` 再用；越界读返回 null(NaN)、越界写静默丢弃。 [src: MemoryBlock.java:64-81]
22. **print 塞长文本** —— ✗ 以为会自动扩容 → ✓ 缓冲 400 字符（LExecutor.java:46），满了**直接丢弃**（:1057/:1100），不报错。
23. **format 拼超长** —— ✗ → ✓ 截断到 400（:1155-1156）。注意 `Vars.maxTextLength=150` 是**聊天**上限，与 print 无关。
24. **程序超 1000 行** —— ✗ → ✓ 解析上限 1000（LParser.java:185），画布也 `truncate(1000)`（LCanvas.java:148），超出的行**静默消失**。

### F. 交互 / 单位（6 条）

25. **control 只填用到的参数** —— ✗ 在无用槽放带副作用的表达式 → ✓ p1..p4 **全部求值**（LExecutor.java:577/584），副作用照样发生。
26. **ulocate 失败后读全部输出** —— ✗ → ✓ 失败时**只写 outFound**（false），outX/outY/outBuild 保持旧值（defs=[4,5,6,7]）。
27. **ucontrol within 参数错位** —— ✗ → ✓ `within x y radius 0 result`：第 5 槽是输出，第 4 槽留 0。
28. **ucontrol getBlock 输出位置** —— ✗ 以为末尾两槽 → ✓ 第 **4/5/6** 槽依次是 type/building/floor。
29. **fetch 参数顺序** —— ✗ 按构造器顺序写 → ✓ 文本序是 `fetch <type> <result> <team> <index> <extra>`。
30. **ubind 一次永久持有** —— ✗ → ✓ 单位死亡后 `@unit` 变 null，所有 ucontrol 变空操作；每轮先判 `equal @unit null` 再 ubind。

## 实测与反例

- ✅【E】30 条中有 19 条能对上验证记录总表的 PASS/PASS(E) 行（S-14..S-18、L1-23..L1-31、L2-24 等）。
- 反例（不成立边界）：**第 6 条的「NaN 变 null」只在赋值路径成立**；把 NaN 从 `@unit` 这类内部值读出来时，它仍是 NaN 对象，不在 mlog 层显形。
- 【U】第 20 条的处理器执行顺序需要一次双处理器竞赛实验（同 tick 互相写同一变量，跑 1000 tick 统计）。

## 常见误解

1. 「null 和 0 一样」——在 `num()` 口径一样，在 `jump equal` 与 `strictEqual` 口径不一样。
2. 「指令数 = ipt」——ipt 是每秒点数率，不是每 tick 条数。
3. 「文档里的坑都是版本 bug」——多数是槽位顺序与 null 语义，跨版本稳定。
