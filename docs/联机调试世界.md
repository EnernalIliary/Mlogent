# 联机调试世界（玩家 + Agent 共享一个 Mindustry 世界）

一句话：**一个 headless 服务端常驻进程**（`tools/world_server.py`）负责真正的游戏世界，
**一个 MCP 外壳**（`tools/world_mcp.py`）把它翻译成 `world_*` 工具给 Agent。
玩家用普通客户端连进来，Agent 用工具读写同一个世界。

---

## 1. 怎么加入

| 场景 | 地址 |
|---|---|
| 同一局域网 | `192.168.3.11:15000` |
| 远程（Radmin VPN，双方都在同一网络里） | `26.98.127.37:15000` |

> **端口不是 6567 而是 15000**。Windows/Hyper-V 把 TCP `6528-6727` 整段保留了
> （`netsh int ipv4 show excludedportrange protocol=tcp` 可查），绑上去会 WSAEACCES，
> 而游戏只会笼统地打印 `Unable to host: Port 6567 already in use!`。脚本开服前会用
> UDP+TCP 双探测挑端口，挑不到 6567 就往上找，实际端口写在握手文件和 `world_status.gamePort` 里。

客户端与服务端必须是 **v160.7**（存档版本绑死，build 160 的 `.msav` 用别的版本打不开）。

## 2. 起停

```powershell
# 前台起（Ctrl+C 关，适合自己调试）
python tools/world_server.py --map Fork

# 指定端口 / 开服即暂停 / 只起 JVM 不开服
python tools/world_server.py --map Fork --game-port 15000 --paused
python tools/world_server.py --no-host
```

Agent 侧用 MCP 工具：`world_start`（后台拉起，已有世界在跑会拒绝，除非 `restart=true`）、
`world_stop`、`world_status`。

> **进程存活**：世界跑在**独立进程**里，MCP 随会话重启不会踢掉玩家。但 `world_start` 是从
> 当前工具进程里 spawn 出去的 —— 如果宿主把工具进程放在会回收子进程的作业对象里，世界会跟着退出。
> 这种环境下改成「让 Agent 用后台任务（background job）跑 `world_server.py`」或「自己开一个终端跑」，
> 更稳。

## 4. `world_js` 的四个坑（都踩过）

1. **只有几个全局变量**：`Vars`、`Groups`、`Packages` 可用；
   `Java`、`mindustry` 都**未定义**。要类就写 `Packages.mindustry.gen.Groups.unit`。
2. **静态方法调不到**：`Packages.mindustry.maps.Maps.all()` 会报
   `no public instance field or method named "all"`；但**通过实例字段**可以：
   `Vars.maps.all()`（拿到 18 张图）。同理没有 `Java.type()`。
3. **换行要转义**：工具会把整段 JS 折成一行发出去，所以字符串里的**真实换行会被吃掉**。
   要在 JS 里拼多行文本，写 `\n` 转义（两个字符），别真换行。
4. **`setBlock` 放出来的方块是关着的**：`tile.setBlock(block)` 后 `build.enabled == false`、
   队伍是 `derelict`，处理器一条指令都不会跑（`executor.vars` 全是 null）。
   用 `world_place` 就自动处理了（`setBlock(blk, defaultTeam)` + `enabled = true`）；
   自己写 js 的话必须补这两步。

另外：`u.controller` 在 v160 是**方法对**（`UnitController controller()` 与 setter），
Rhino 里要写成 `u.controller()`；`Vars.state.isPaused()` 是方法，`rules.difficulty` 在 v160 已不存在。

## 5. `world_pause` 是提示性的

`pause on` 不带玩家时可靠（`isPaused()` 与 `tick` 都会冻住）。
**有玩家在线时，客户端/加入事件会把暂停解除** —— 用完必须再读一次 `world_status` 复核 `paused`。
要做「暂停→改世界→恢复」的事务，就在两步之间检查 `paused`，看到 false 就别假设世界是静的。

## 8. 能读到哪些调试信息（按工具列全）

### 世界层 · `world_status`
`map`（地图显示名）、`mode`、`wave`/`waveIn`、`tick`（世界 tick，60/s）、`width`/`height`（格）、
`players`、`units`（全图单位数）、`buildings`（全图建筑数）、`paused`、`infiniteResources`、
`gamePort`、`uptime`（守护进程秒数）、`dataDir`。

### 人 · `world_players`
`name`、`team`、`x`/`y`（格坐标，浮点）、`admin`。

### 单位 · `world_units`
`id`、`type`、`team`、`x`/`y`（格）、`health`/`maxHealth`、`dead`、
`controller`（`Player` / `LogicAI` / `CommandAI` / `GroundAI` … 类名）、
`item`（`@firstItem`，空手 null）、`carry`（`@totalItems`）、`itemCapacity`、
`elevation`（0 贴地 / 1 飞起，boost 单位看得出助推）、`controlTimer`（`LogicAI.controlTimer`，
非逻辑控 -1，掉控阈值 600 tick）。

### 建筑 · `world_buildings` / `world_building`
`block`、`team`、`x`/`y`（**原点格**）、`health`、`items`（货舱总量，无货舱 -1）、
`capacity`（`block.itemCapacity`，无货舱 -1）；单格查询额外返回 `found`。

### 逻辑处理器 · `world_logic{,_code,_vars}`
`x`/`y`/`block`/`codeLen`（字节）/ `vars`（变量个数）；
源码原样读回（换行保留）；变量表 = `@counter` + 逻辑里出现过的每个变量名 → 当前值
（对象显示 `toString`：`Unit#211:poly (240.0,236.0)`、`Building#210[59,59]:core-shard`，null 原样）。

### 逃生口 · `world_js` / `world_console`
任意 Rhino 表达式：`Vars.state.*`、`Vars.world.tile(x,y).*`、`Groups.*`、任一方块/单位实例字段；
控制台 20 多条命令（`status`/`rules`/`dumpsettings`/`fillitems`/…）。

### 逻辑侧读不到的（引擎内部，别指望）
着陆台的冷却进度与进口率（`cooldown`/`arrivingTimer` 不在 `LAccess` 里）、单位 AI 的目标与路径、
电力/物流网络明细。要这些只能走 `world_js` 反射读实例字段。

### 两个已知边界
- `world_buildings` 走 tile 扫描，**不会**漏掉 `update=false` 的方块（container / 传送带 / 墙）。
- 多格建筑只在原点格报一次（3×3 核心不刷 9 行）。

## 9. 变更日志与 flag 通道

建筑变更日志在守护进程启动时就装好（`_boot` 里调 `EV_INSTALL_JS`），订阅两个事件：

| 事件 | 记什么 | 说明 |
|---|---|---|
| `EventType$TileChangeEvent` | `P`（放下）+ `B`（变 air，即拆除） | 每格一次；多格方块只在原点记 `P`，其余格子的 air 噪声由 Python 侧按 `size` 消掉 |
| `EventType$ConfigEvent` | `C` + 配置值 | 着陆台换物品、分拣器换货、处理器改代码档位都走这里 |

每条行是 `{kind, seq, tick, x, y, block, team, size, extra}`；环形缓冲只留最近 500 条，重启守护进程清空。
增量读法：拿到 `nextSeq` 后下次带上 `since=nextSeq`。

坑：嵌套静态类在 Rhino 里必须写全 `Packages.mindustry.game.EventType$TileChangeEvent`；
先 `var ET = Packages...EventType` 再拼 `ET$TileChangeEvent` 会得到 undefined，`Events.on` 静默不装。

## 10. 改动怎么让玩家看见（`setNet` vs `setBlock`）

**`Tile.setBlock()` 只改服务端本地，客户端永远看不到**——这就是「我这边放了东西，玩家屏幕上什么也没变」的原因。
要同步，必须走：

| 写法 | 实际调用 | 效果 |
|---|---|---|
| `tile.setNet(block, team, rotation)` | `Call.setTile(...)` → `Tile.setTile`（`@Remote(called = Loc.server)`） | 服务端立刻生效**并且**把 `TileChange` 包广播给所有客户端 |
| `tile.setBlock(...)` | 纯本地 `Tile.setBlock` | 只有服务端变，客户端不变 |

`world_place` / `world_clear` / `world_clear_buildings` / `world_schematic` 现在全部走 `setNet`（`tools/world_server.py` 的
`PLACE_JS` / `CLEAR_JS` / `CLEARBUILDS_JS` / `SCHEMATIC_PLACE_JS` 各一行）。
自己写 `world_js` 改地图时也要用 `setNet`，否则玩家看不到。

另外：**`World.js` 会把 JS 里的换行折成空格**，所以脚本里不能写 `//` 行注释（会注释掉后面的代码，报
`missing } in compound statement`）；要注释用 `/* */`。同一次会话里 Rhino 的全局作用域是共享的，
重复 `const`/`var` 同名会报 `redeclaration`，建议把整段包进 `(function(){ ... })()`。

### 聊天栏日志

守护进程默认把 agent 的写操作打进游戏聊天栏（`[agent] place container @ 33,60` / `[agent] 蓝图 多控测试台 @ 30,75 (放下 10 块)`）。
关掉用 `--no-chat-log`，改前缀用 `--chat-prefix`。命中的 op：`place`/`clear`/`spawn`/`killunits`/`clearbuilds`/`reset`/`switch`/`logic_set`/`schematic`/`schematic_save`/`load`/`save`/`pause`。

### flag 通道：让逻辑自己汇报状态

`ucontrol flag n` 写的是单位的 `flag` 字段，服务端能直接读（`world_unit.flag`）。
这是逻辑 → 观察者最省的一条通道：每槽热路径加一条 `ucontrol flag <相位>`，
agent 就能在 `world_units` 表里看到每只单位当前处在哪个相位（0 待命 / 1 取货 / 2 投递 …），
不用去反推坐标。



## 11. 玩家聊天回传给 agent

玩家在聊天栏发的每句话现在都能读回来（MCP world_chat / client chat）。

- 钩子：Packages.arc.Events.on(EventType$PlayerChatEvent, ...)，事件字段 player / message
  （Mindustry-Source/core/src/mindustry/game/EventType.java:224-232）。监听器在守护进程 _boot 里
  随 EV_INSTALL_JS 一起装，环形缓冲 300 条。
- 读取：world_chat(since=上次的 nextSeq, limit=80) → {seq, tick, player, message}。
  since 传上一次返回的 nextSeq 就是增量，不传=全部。
- 落盘：同时追加到 out/_world/chat.log（[tick] 玩家: 内容），不接 MCP 也能 tail。
- 玩家名带颜色标签（如 Ili[#8abcd1]ary[#654321]艾铭[#ffb6c1]✽），原样返回，别当 ID 用。
- 只收玩家消息：world_say 与 [agent] 日志是服务端广播，不进这个缓冲，不会自激。
- 自检手段（没有真人在线时）：js 里 fire(new Packages.mindustry.game.EventType$PlayerChatEvent(null, 'x'))，
  player 为 null 时 name 记成 ?，消息照收。
## 12. 场景文件：模拟器里调好的台子，一键搬到真世界

`tools/scene.py` 定义一份 JSON，**`mlogsim` 和 `world_server` 都认**：在模拟器里跑通的建筑布局、链接顺序、物品、单位、逻辑代码，粘到真世界不用重抄坐标。

```powershell
# 模拟器侧：--scene 会自己铺场，--scene-probe 读变量并按 checks 判定
python tools/mlogsim.py --scene scenes/v27-rig.json --scene-probe --ticks 400

# 真世界侧（客户端）
python tools/world_client.py scene scenes/v27-rig.json
python tools/world_client.py scene_probe scenes/v27-rig.json

# 只看不铺：校验 + 摘要 / 打印要执行的 JS
python tools/scene.py check scenes/v27-rig.json
python tools/scene.py emit --flavor world scenes/v27-rig.json
```

MCP 里是 `world_scene(path)` / `world_scene_probe(path)`。

### 12.1 格式（v1）

| 键 | 说明 |
|---|---|
| `world.size` | 空白世界的边长；`world.rules` 覆盖 `infiniteResources`/`waves`/`canGameOver`/`logicUnitControl`/`allowEditWorldProcessors`/`possessionAllowed` |
| `clear` | `[x, y, w, h]`，铺之前先把这块清成 air（核心不动） |
| `buildings[]` | `block`/`x`/`y`/`name`/`team`/`enabled`/`config{item|value}`/`items{}`/`code`/`links[]` |
| `units[]` | `type`/`count`/`team`/`at[x,y]`/`radius`，黄金角螺旋铺开 |
| `checks[]` | `{logic, var, equals}`；`equals` 写建筑名时按「原点格 + 方块名」比对 |

执行顺序是硬约束（写在 `build_js()` 的注释里）：**先全部 place → 再 config/items → 再 links+code → 最后 units**，因为链接和代码都要指向已经存在的建筑。

坐标语义 = 交给 `setBlock`/`setNet` 的格子，多格建筑以它为中心（`Tile.java:255-288`，`off = -(size-1)/2`）。报告里回显的是引擎真实的原点格（`b.tile.x/y`），铺完对照一眼就能发现偏格。

### 12.2 报告里现在有三样有用的东西

- `K` 行：**执行器真实的链接下标映射**（`getlink 1` 到底指向谁）。只要有一条链接不合法，`updateCode()` 会把它丢掉并把后面的往前挤（`LogicBlock.java:376-394`），下标静默错位。
- `ERR` 行：声明了 N 条链接但只解析出 M 条时直接报错，不用靠症状反推。
- `place` 校验：放完立刻比对 `b.block.name`，放错方块（比如多格建筑压住别的方块）会显式报错。

### 12.3 三个坑（都踩过）

1. **模拟器里处理器一条指令都不跑**：空白/暂停世界的 building 从没执行过 `update()`，`efficiency` 停在 0，而 `LogicBlock.updateTile()` 的累加器是 `edelta() * ipt` —— 被 efficiency 缩放后是 0。sim 分支在载入代码后补 `b.efficiency=1`。
2. **模拟器只 tick 一台处理器**：`_loop_js` 只驱动传入的那一个对象；场景里的处理器要靠 `var PROCS=[...]` 发布出来，再由 tick 钩子逐个 `updateTile()`。（Rhino 没有 `globalThis`，顶层 `var` 就是全局。）
3. **刚铺完读变量是空的**：处理器要跑过一轮才有 `executor.vars`，`world_scene_probe` 里等了 1.5 s；自己写探针时同理。

### 12.4 实测

`scenes/v27-rig.json`（31 槽搬运 v27：micro + sorter + 两个 container + core + 8 只 poly）：

- 模拟器：`placed=5 config=1 stock=2 logic=1 units=8`，三条 check 全 ok。
- 真世界：同一份 JSON 铺完 `placed=5`、链接映射 `0=container2 1=container1 2=sorter1`，`tmp.lnk=container[33,60]`、`lx/ly=33.5/60.5`、`u1..u8` 全是 `Unit#…:poly`，`@counter` 在跑。

## 13. 点击门：玩家点一下方块，就进那个沙盘

### 13.1 为什么任意方块都能当按钮

客户端点任何格子都会上报：`DesktopInput.java:486-490` → `Call.tileTap(player, selected)`；
服务端 `InputHandler.java:732-739` `@Remote(targets = Loc.both, called = Loc.both, unreliable = true)`
→ `Events.fire(new TapEvent(player, tile))`。
所以门不需要特殊的方块类型，**只要有一个玩家点得到的格子**。这里用 `shock-mine` 只是因为它不占地方、
本队玩家踩不出事（`ShockMine.java:69-74` 只对 `unit.team != team` 触发），当个可见的按钮。

### 13.2 注册一扇门

```powershell
# 入口: 点 62,62 -> 铺 scenes/door-sandbox.json -> 把玩家换成沙盘里的 poly -> 镜头跟过去
python tools/world_client.py door --x 62 --y 62 --kind possess --unit poly \
    --tx 88 --ty 90 --label '沙盘入口' --scene scenes/door-sandbox.json

# 出口: 点沙盘里的 86,88 -> 换回进来之前的那个单位
python tools/world_client.py door --x 86 --y 88 --kind exit --label '出口'

python tools/world_client.py doors      # 看已注册的门
python tools/world_client.py door_clear # 全清(方块留着, 只是不再是门)
python tools/world_client.py taps       # 看点击流水(谁点了哪格)
```

字段：`--kind possess|exit|camera`（默认 possess）、`--unit`（possess 刷什么兵）、
`--tx/--ty`（沙盘里的落点，也是镜头目标）、`--scene`（点下去先铺这个场景 JSON）、`--block`（按钮用什么方块）。

### 13.3 一次点击里发生什么

`_doorAct(pl, x, y)`（`tools/world_server.py` 的 `DOOR_ACT_JS`）按顺序：

1. `_doors["x,y"]` 查表，没有就 `nodoor`；
2. `d.scene` 存在 → `eval(_doorjs["x,y"])`：**把场景整块铺出来**（setNet，玩家立刻看见）；
3. 没有玩家（合成点击/自测）→ `noplayer`，铺场景这一段照样生效；
4. `kind=possess`：记下 `_ret[玩家名] = 原单位`，`Vars.content.unit(type).spawn(player.team(), tx*8+4, ty*8+4)`，
   `Call.unitControl(玩家, 新单位)` + `Call.setCameraPosition`；
5. `kind=exit`：取回 `_ret` 里的原单位，`Call.unitControl` 换回去，没有就 `noreset`；
6. `kind=camera`：只拉镜头。

附身能成立的关键（`InputHandler.java:771-818`）：`unitControl` 只校验
`unit.isAI() && unit.team == player.team() && !unit.dead && unit.playerControllable()`，
所以**刷出来的单位必须用玩家自己的队伍**（代码里取 `pl.team()`，取不到才退回 `defaultTeam`）。
换单位后玩家原来的 `alpha` 变成自由单位留在原地；出口门把它换回来。

### 13.4 三个坑（都踩过）

1. **`var` 出不了这次 js 调用**。`World.js` 把提交的脚本包成 `(function(){ ... })()`，
   `var _doorAct = ...` 是函数内局部变量，下一次调用 `typeof _doorAct == 'undefined'`。
   必须写成隐式全局赋值 `_doorAct = function(...){}`（`_doors = {}` 一直有效就是因为它没写 var）。
2. **`_doorAct` 会先往 `sb` 里铺场景再返回结果**，所以 `sb.append('R\t').append(_doorAct(...))`
   会把场景第一行粘在 `R\t` 后面（解析出 "B"）。先算结果再 append。
3. **没有玩家单位就测不了附身**：`_doorAct` 返回 `noplayer`，只有场景会铺。
   自测顺序是先 `tap --x 62 --y 62`（验场景），再等玩家连进来 `door_enter --x 62 --y 62`。

### 13.5 实测

- 注册 + 合成点击：`tap --x 62 --y 62` → `status` 从 `buildings 1 units 0` 变成 `buildings 3 units 9`，
  `_doorerr=ok`；直接调 `_doorAct(玩家,62,62)` 返回 `possessed`，玩家单位从 `alpha@81,92` 变成
  `poly@89,91`、`controller=Player`。
- 出口门在同一张图的沙盘里（86,88），换回原单位走 `_ret`，不需要跨服务器。

## 14 状态镜：把仿真画进真世界（mlogsim --push ↔ mirror_feed）

仿真跑在另一个 JVM 里，服务端没法直接看它的单位。两边靠**一个 JSON 文件**解耦：

```
mlogsim --push FILE --push-every N   →   FILE   →   world_server --mirror-feed FILE（后台线程）
```

### 14.1 用法

```powershell
# 1) 服务端启动时盯住文件（也可运行时用 mirror_feed op 挂上）
python tools/world_server.py --map '大肥鱼的调试世界' --mirror-feed out/_world/mirror.json

# 2) 仿真每次跑的时候把状态推出来（每 15 tick = 4 Hz）
python tools/mlogsim.py 'Logic/单位多控-搬运-v27.mlog' --units poly:8 --world 128 --base 58,58 `
  --core-items copper:400 --combat off --links auto --no-preflight --ticks 240 `
  --push out/_world/mirror.json --push-every 15
```

文件内容是 `[{"type":"poly","x":464.0,"y":464.0,"amount":0,"ctrl":1}, ...]`：

| 字段 | 含义 |
| --- | --- |
| `type` | 兵种名（`poly`/`flare`/…），用来取精灵图 |
| `x` / `y` | **格坐标**（tiles）；`mlogsim` 推送时已经把 `u.x/8` 折好了 |
| `amount` | 货舱数量，>0 时图标上写 `x12` |
| `rot` | 朝向（度，0 = 指向 +x）。图标按 `rot - 90` 画，精灵本来就朝上 |
| `ctrl` | 0 自由 / 1 逻辑控 / 2 玩家，用来上色（白 / 青 / 黄） |

### 14.2 工具

| 工具 / op | 做什么 |
| --- | --- |
| `world_mirror_feed` / `mirror_feed` | 起后台线程盯文件，变了就重画；`stop:true` = 停线程并清屏 |
| `world_mirror_state` / `mirror_state` | 直接给一组 `units`（或 `file`）画一次，不用线程 |
| `mirror_clear` | 停线程 + 删掉所有状态镜 marker |

命令行：`python tools/world_client.py mirror_feed out/_world/mirror.json`、
`python tools/world_client.py mirror_state out/mirror.json`、`python tools/world_client.py mirror_clear`。

### 14.3 实现要点（踩过的坑）

1. **marker 必须两步建**：`Call.createMarker` 时给空的 `TextureHolder`，**建完**再
   `Call.updateMarkerTexture(id, 内容对象)`；创建包里直接塞贴图会显示成白模。
2. 贴图值用**内容对象** `Vars.content.unit("poly")`，不要写 `"poly-full"`（那是 ohno 占位图）。
3. `world/minimap/light` 不是布尔而是引擎分配的层号，`-1` 才是「这层不画」；不要手填。
4. Rhino 里 `Groups.unit` 是 `EntityGroup`，**没有 `get(int)`**，要 `Groups.unit.each(function(u){...})`。
5. `mlogsim` 的 JVM 工作目录是临时目录，`--push` 的相对路径在 python 侧就转成绝对路径。
6. 服务端线程 0.12 s 轮询 `(mtime_ns, size)`，仿真 4 Hz 推送时几乎实时；`World.js` 里有
   `self._lock` 串行化，和 MCP 的其它调用不会打架。
7. 仿真坐标系和真世界不一样时用 `dx`/`dy`（按格）整体平移，两个 op 都收：
   `mirror_feed {path, dx:-55, dy:-55}` 就是「往左上挪 55 格」。
9. 想用眼睛看就别让仿真全速跑：`--rt 1` 把仿真节流到实时（60 tick/s），`--rt 4` 是 4 倍速；不节流时 12 万 tick 十几秒就跑完，图标只会闪一下。
8. 图标/文字是**服务端权威发包**，玩家换视角也看得见；但仿真里的单位本体不在这个世界，
   点它没有任何交互（想能点就等下一步的门 + `world_spawn`）。

### 14.4 实测

- `mlogsim ... --ticks 240 --push out/_world/mirror.json --push-every 15` 跑完后
  `mirror_state` 侧读到 `n=8`，`Vars.state.markers.size()=16`（8 个贴图 + 8 条头顶文字）。
- 仿真里 8 只 poly 搬运 v27 逻辑，真世界屏幕上就是 8 个 poly 图标在动，青色 = 逻辑控。

## 15. 放一颗脉冲地雷就开始投影（拆掉就结束）

仿真在跑的时候，玩家只要在想要的位置**放一颗脉冲地雷**，服务器就以它自己为圆心把场景
复刻出来、把单位影子挂上去；**把地雷拆掉，复刻出来的建筑（含核心）和全部 marker 一起消失。**
不附身、不拉镜头、也不会给玩家换单位。

```
mlogsim --push feed            world_server 的两个后台线程
      │                              │
      │  文件 mtime 变新              ├─ mirror 线程：feed → _msApply（只有投影期间才推）
      ▼                              │
   feed 新鲜 ────────────────────────┤
                                     │
  玩家放下 shock-mine ──TileChangeEvent──► _mineHits
                                     │
                     projection_director（0.5 s 轮询）取走新格子
                                     ▼
        project_at：世界清场 → 复刻场景（at=雷格）→ 把雷钉回原位 → mirror_watch(feed)
                                     │
  玩家拆掉那颗雷 ──director 读圆心格子──► end_projection：停 mirror → 拆建筑 → 清 marker
```

### 15.1 用法

```powershell
# 服务端：给了 --watch-feed/--watch-scene，director 就在 boot 时起来等着
python tools/world_server.py --map '大肥鱼的调试世界' --name 'world.execute(Mindustry)' `
  --watch-feed out/_world/mirror.json --watch-scene scenes/sandbox-mine.json

# 仿真：实时推送（--rt 1 = 60 tick/s）；js-timeout 必须大于这场仿真跑完的时间
python tools/mlogsim.py --scene scenes/sandbox-mine.json --ticks 36000 --rt 1 `
  --push out/_world/mirror.json --push-every 3 --ore copper --ore-at 250,268 `
  --ore-radius 4 --js-timeout 1200
```

MCP 侧：`world_arm`（只起 director，不动世界）、`world_projection`（`on:false` 立刻结束当前投影）、
`world_projstat`（看圆心 / 复刻清单 / feed / 偏移）。命令行同名的 `arm` / `projection` / `projstat`。

### 15.2 关键行为

| 行为 | 说明 |
| --- | --- |
| 触发 | `TileChangeEvent` 里方块名 == `shock-mine` 的**放置**事件（拆除不触发）；Java 回调不了 Python，所以只把格子 push 进全局 `_mineHits`，由 director 轮询取走 |
| 唯一条件 | feed 存在且 mtime ≤ 25 s（`feed_age`）。仿真没在跑时放雷只会收到一句「仿真没在跑」的聊天提示，不会复刻 |
| 圆心 | 就是玩家放的那颗雷（`project_at(x, y, feed, scene)`），场景偏移 = `雷格 - 场景锚点` |
| 雷会被场景清场误抹 | 场景 `clear` 矩形盖住雷格时，`REPLACE_MINE_JS` 在铺完后把雷 `setNet` 钉回去，并先写 `_mineIgnore` 防止自触发 |
| 场景内容 | `scene.world_js(sc, at=雷格)`：建筑（方块/队伍/旋转/血量/液体/物品/配置）+ 处理器代码，处理器 `enabled=false`（不抢仿真那批单位）；`project.units="mirror"` 时**不刷单位** |
| 结束条件 | director 每圈读圆心格子的方块名（`MINE_STATE_JS`），**不是**监测 air 事件——场景清场会瞬间产生一堆 air 事件，用事件判必然误报 |
| 结束时拆什么 | 复刻清单（报告里的 `B` 行 → `[[x,y,block],…]`）逐个 `setNet(air)`，**含核心**；只有「当前格还是当初那个方块」才拆，不误伤玩家后放的 |
| 结束时清什么 | `mirror_stop`：`_mirror_seq += 1` → 清 `_ms` 48 个 id（图标+文字）→ 0.2 s 后再清一遍；`end_projection` 拆完楼再清第三次 |
| 玩家能看到 | 建筑增删全走 `setNet`（客户端同步），聊天栏有两句 `[agent]` 播报 |

### 15.3 踩过的坑（都修了）

1. **boot 不能重装 `doors.json`**：旧门重装会就地补一颗 `shock-mine`，那是个真实的 TileChangeEvent，
   director 会当成「玩家又放了一颗雷」⇒ 凭空多出一次投影（曾经莫名出现 (263,262)/(300,220) 的投影）。
   现在 `_boot()` 不再调 `door_reload`，点击门机制整体废弃。
2. **`JSON.parse([[...]])` 会失败**：`%(list)s` 展开成 JS 数组字面量后是**已解析好的对象**，
   再 `JSON.parse` 等于 `String(arr)` ⇒ `SyntaxError: Expected end of stream at char 3`，
   表现为「拆 0 座建筑」。直接 `var pick = [[...]];` 就行。
3. **场景报告的坐标是 `"246.0"`**：Rhino 把 Java double 打成浮点，`int("246.0")` 抛 ValueError 被吞
   ⇒ 清单恒空。必须 `int(float(x))`。
4. **marker 清完又长回来**：清理时镜像线程手里可能还有一帧在路上。用代次号
   （`mirror_push(..., gen=...)` 与 `_mirror_seq` 比对）丢掉它，另外清理扫的是
   `_ms.base + 0..63` 固定窗口而不是 `_ms.n`（重启后 `_ms.n` 可能是 0 而屏幕上还留着上次的 16 个）。
5. **别用 `m.pos.x.toFixed(1)` 读 marker 坐标**：对 Java float 调 `toFixed` 会得到假值 `2000.0`。
   用字符串拼接 `(a.pos.x + ',' + a.pos.y)`。这条害我排查了「marker 卡在 2000,2000」半天，
   实际管道一直是对的。
6. **`mlogsim` 的 `js_timeout` 默认 180 s**（`tools/mlogsim.py:392`，`wait_for("undefined")` 是同步等整段 JS 跑完）：
   `--ticks 54000 --rt 1` 要 15 min，必然超时退出、feed 停更、世界侧影子冻结。长跑必须给
   `--js-timeout` 并把 ticks 控制在「跑完时间 < timeout」。

### 15.5 多场景与矩形边界（只用 marker，不动地形）

一块地方放一个沙盘，玩家把雷放在哪个框里就复刻哪个场景。框是**一圈小方块 marker**，
不碰地形——早先用 `metal-floor` 铺过真地板，结果把玩家自己刷的染色地板盖掉了，
而且看起来像「没有仿真也有东西」。

**两块规矩（都比较硬）**：

1. **没有仿真就不画框**。director 每 0.5 s 看一次 feed 的 mtime，新鲜（≤10 s，`FRAME_LIVE_MAX`）
   才画，一过期立刻 `FRAME_CLEAR_JS` 擦掉。所以框本身就是「仿真在跑」的指示灯。
2. **场景固定排布，不跟着雷跑**。按 `--frame-cell`（默认 64）见方的格子从**地图左上角**开始排，
   第 i 个场景落在第 i 格、锚点在格心；雷放在框外直接拒绝（聊天栏提示），不再「以雷为圆心」乱铺。

```powershell
python tools/world_server.py --map '大肥鱼的调试世界' --name 'world.execute(Mindustry)' ^
  --watch-feed out/_world/mirror.json ^
  --watch-scene scenes/sandbox-mine.json --watch-scene scenes/sandbox-haul.json ^
  --frame-cell 64
```

| 项 | 说明 |
| --- | --- |
| 框从哪来 | 场景 JSON 可写 `"frame":[x,y,w,h]`；没写就自动取 `clear` 矩形 ∪ 建筑/单位包围盒再外扩 1 格（`scene.frame_of`） |
| 怎么排 | `layout_scenes(w, scenes, cell=64)`：`col=i % (宽//cell)`、`row=i // (宽//cell)`，锚点 = 格心；`frame`/`clear`/单位/建筑整体平移 `shift = 格心 - 原锚点` |
| 怎么画 | `FRAME_PAINT_JS` 沿矩形边每 `step` 格放一个 `ShapeMarker`（`fill=true`、`sides=4`、`rotation=45`），顶点去重。默认 `step=1`、`radius=7`（世界单位），金色 `ffd159` |
| 显隐 | 只看 feed：新鲜 → 画（日志 `检测到仿真在跑：2 个沙盘边界已画出（220 个点）`），过期/不存在 → 擦（`仿真停了：沙盘边界已擦掉`） |
| id 段 | 7000 起，按 key 存 `_fr.keys`；重启时 `FRAME_SWEEP_JS` 扫 7000..7999 先擦干净（否则客户端留着上次进程画的框） |
| 选场景 | 雷格落在哪个 `frame` 就复刻哪个；框外 → 聊天栏「这颗地雷没落在任何沙盘边界里」并忽略 |
| 命令行 | `world_client.py frames list|clear|paint`（`--step` / `--radius`），MCP 是 `world_frames` |
| 场景锚点 | 平移后锚点就在格心，所以同一场景每次复刻都落在同一处（和框对齐） |
**每个沙盘两个框（金框 = 放雷区，青框 = 仿真世界里那张图的真实边界）**

金框是「把雷放这里」，但单位会跑去矿区/核心/容器，跑出金框是正常的。所以 director 还会画
第二个框：key + "@live"，内容 = **模拟器那张地图的整体尺寸**（feed.world），不是单位外接框。

- 仿真侧 scenes/sim/*.json 是 64×64 的沙盘副本（out/mksim.py 用 scene.translate 平移出来，
  锚点搬到 (32,32)、world.size=64）。这样「仿真世界多大」才是个有意义的框。
- 坐标系不同就得换算：feed 负载里带 anchor（仿真场景的锚点），世界侧用
  偏移 = 格心 − feed.anchor 现算，框 = [格心−锚点, 仿真宽, 仿真高]，再按地图尺寸裁剪。
  实测三个 64×64 沙盘 → 三个青框正好是 [0,0,64,64] / [64,0,64,64] / [128,0,64,64]。
- 点密度按周长自动收缩（step = round((w+h)/48)），大框不会塞几千个 marker。
- 老格式 feed（纯数组、没 world/anchor）自动退回「单位外接框 + 场景位移」。

### 15.6 自动投影（默认，不需要地雷）

仿真一起来就自己铺，不用玩家放雷：director 每 0.5 s 看一次每块沙盘的 feed，
新鲜（≤10 s）且该槽还没投影 → 直接 `project_at(格心, 该场景, 该 feed, slot=i, pin=False)`
把场景复刻到那格、挂上影子；feed 一停 → 立刻 `end_projection`（拆建筑 + 清 marker）。

- 自动模式**不钉地雷**（`pin=False`），也**完全不看地雷事件**（`MINE_HITS_JS` / `MINE_STATE_JS` 都跳过），
  所以不会出现「拆雷把自动投影弄没了」这种互相打架的情况。
- 框照旧显示：金框 = 落雷区（现在是纯参考，告诉你这块归哪个场景），青框 = 仿真世界真实边界。
- 想回到手动（放雷才开始）：启动加 `--manual`，或 op `arm` 传 `{"auto": false}`。

```powershell
# 默认自动：三条 feed 一起起来，三块沙盘几秒内自己出现
python tools/world_server.py --map '大肥鱼的调试世界' ^
  --watch-feed out/_world/mirror.json --watch-feed out/_world/mirror_haul.json ^
  --watch-feed out/_world/mirror_mono.json ^
  --watch-scene scenes/sandbox-mine.json --watch-scene scenes/sandbox-haul.json ^
  --watch-scene scenes/sandbox-mono.json --frame-cell 64
```

实测（三条 64×64 仿真同时跑）：约 1 s 内三块沙盘全出，`projstat` 三个 slot 的 center 恰好是格心
(32,32)/(96,32)/(160,32)，世界里 0 颗地雷，marker 632（6 个框 + 24 图标 + 24 文字）；
把仿真杀掉后 10 s 内三块全部收摊、框一起消失。



**量纲坑（又踩了一次）**：`PointMarker.radius` 的单位是**格**（`draw()` 里 `radius * tilesize`），
而且它自带 1.67 s 的扩散动画（`(Time.globalTime / 100f) % 1f`），拿它画框会整圈呼吸闪烁；
`ShapeMarker.radius` 才是**世界单位**（`Lines.poly` 直接吃），静态、不闪。框用的是后者。

实测（2026-11-16 22:30，512×512）：两个场景各得到一个 64×64 格位——矿场框 `[19,19,26,32]` 锚点 `(32,32)`、
物流框 `[82,18,28,28]` 锚点 `(96,32)`（左上角起算）。

| 场景 | `frames list` | `markers.world` |
| --- | --- | --- |
| 没有仿真 | 空 | **0** |
| 仿真在跑 | `mine:112 | haul:108` | **220** |
| 仿真停 10 s 后 | 空 | **0** |

雷丢在框外 (200,200)：`projstat.center = null`、什么建筑都没出现，只有那颗雷本身。
雷丢在矿场框内 (30,30)：复刻 `micro@26,32 / container@30,32 / core@26,25`（= 格心 (32,32) + 场景内偏移），
marker 236（220 框 + 8 图标 + 8 文字），拆雷后回到 220。
框上地砖仍是 `colored-floor`，地形零改动。

### 15.7 文本日志板：每块沙盘一块 TextMarker 面板

每块沙盘在自己的格子里升起一块「文本板」（TextMarker，不是逻辑显示屏、不吃处理器指令）：

```
#1 sandbox-mine            <- 标题（#序号 + 场景文件名）
feed 0.0s live             <- feed 帧龄 + live/idle
proj ON  bld 3             <- 投影状态 + 复刻建筑数
units 8                    <- 当前影子数
frame 19,19 26x32          <- 落雷框
00:02:53 proj start, bld 3 <- 最近 3 条事件
00:02:56 feed live
```

- id 段：`5000 + slot*8`（SB_BASE=5000 / SB_SPAN=8 / SB_MAX_LINES=8 / SB_FONT=0.9）；
  位置 = 该格 `(cell.x+2, cell.y+3)`，每行上移 0.95 格（TextMarker 文字从锚点往上长）。
- 事件源：`sb_event(w, slot, msg)`，三处 —— 投影开始（`proj start, bld N`）、
  投影结束（`proj end, razed N`）、feed 状态翻转（`feed live` / `feed lost`）；行首自动加 `HH:MM:SS`。
- 文本没变就不发 js（`sb_render` 自己缓存），稳态 0 网络开销。
- 重启守护进程：boot 跑 `SB_SWEEP_JS` 清 `5000..5999` 再重置，避免残影。
- 读：op `sblog`（`{"action":"list"}`）或 MCP `world_sblog`；`action=log` 追加一行、`clear` 清空。

**坑 1：`LMarkerControl` 里没有 `text`。** 改文字只能
`Call.updateMarkerText(id, LMarkerControl.flushText, true, s)`
（枚举全集：remove world minimap light autoscale pos endPos drawLayer color radius stroke outline
rotation shape arc flushText fontSize textHeight textAlign lineAlign labelFlags texture textureSize posi uvi colori）。
写 `LC.text` 会得到 `InternalError: ... has no public instance method named "text"`。
字号要单独发 `updateMarker(id, LC.fontSize, sz, 0, 0)`。

**坑 2：面板内容走文件通道，而且必须是 JSON 数组。** 控制台的 `js` 一行塞不下多行文本，
所以 Python 写 `out/_world/server/sb<slot>.txt`（就是 java 进程的 cwd），JS 侧
`_sbSetF(sl, gx, gy, sz)` 用 `Files.readString(Path.of('sb'+sl+'.txt'))` 读；
文件里要放 `json.dumps(lines)`，因为 `_sbSet` 里是 `JSON.parse` ——
早先直接写纯文本（首行 `#1 ...`）会报 `SyntaxError: Unexpected token: #`（我一度误判成「控制台吃字符串字面量」）。

### 15.8 客户端看到的是空处理器？——代码与配置要单独补发

`setNet` 只摆方块，客户端那台处理器的代码是空的。`tools/scene.py` 的 world flavor 补了两条：

- 代码：`_links_stmt` 里 `b.code = s; b.updateCode(s); b.configureAny(LogicBlock.compress(s, b.relativeConnections()))`
- 配置：`_config_stmt` 的 item 分支 `b.configureAny(Vars.content.item(x))`

`configureAny` = `Call.tileConfig(null, self(), value)`（源码注释「Configure from a server」），
服务端本地生效并广播；客户端 `InputHandler.tileConfig` 收到后 `build.configured(null, value)`，
`LogicBlock` 的 `config(byte[].class)` 分支走 `build.readCompressed(data, true)`。

首包可能和方块创建同帧被丢，所以投影铺完还有一遍 RESYNC：对场景报告里每栋建筑
`b.configureAny(b.config())`（幂等），打印 `RESYNC\t<n>`。

实测（2026-11-17 00:03，3 块沙盘）：`micro@26,32` = **7718 字符，enabled=false，links=1**；
`micro@90,32` = **28101 字符，enabled=false**；`sorter@91,34` 的 `config()` = **copper**。

**坑 3：投影里的处理器必须是 `enabled=false`。** 它只是「复刻出来的模型」，真跑逻辑的是仿真进程。
`tools/scene.py` 的 `world_js` 只在建筑没显式写 `enabled` 时才强制关掉，而
`out/mksim.py` 生成 64×64 仿真场景时会连 `enabled: true` 一起抄 ⇒ 世界里那台处理器真的跑起来了。
修法：`out/mksim.py` 里 `b2.pop('enabled', None)`，重生成 `scenes/sim/sandbox-*.json`。



## 16. 游戏里 /push：管理员在聊天栏直接跟 agent 说话

想一边在游戏里看投影、一边指挥 agent，不用切窗口：**在聊天栏敲 `/push <文本>`**，
这句话会进到 agent 的会话里（作为一次"敲门"），agent 处理完可以用 `world_say` 回到聊天栏。

### 16.1 用法

```
/push 把矿场沙盘的 N 改成 4 我看看
!push 也一样（前缀 / 或 ! 都认）
```

- **只有管理员能用**。调试世界默认给每个进来的玩家 `admin = true`（`--no-push-admin` 可关），
  这样不需要先打 `/admin`。
- 服务端回一句 `[agent] 收到 /push(N 字), 已转交给会话`；不是管理员会被回绝并提示用控制台 `admin <名字>`。
- 没有玩家在线也能测：`python tools/world_client.py push` 直接读队列。

### 16.2 链路

| 段 | 东西 | 位置 |
| --- | --- | --- |
| 采集 | `PlayerChatEvent` 里匹配 `/push ` / `!push `，检查 `player.admin` | tools/world_server.py 的 `EV_INSTALL_JS` |
| 缓冲 | JS 全局 `_pushlog`（最多 50 条） | 内存 |
| 落盘 | 每条追加一行 JSON 到 `out/_world/server/push.jsonl` | 持久，重启不丢 |
| 取走 | op `push`（`drain=true` 取走并清空） | `PUSH_JS` / `world_client.py push` |
| 敲门 | `tools/push_wait.py` 轮询 op `push`，收到就打印并**退出** | 后台任务结束时 harness 会通知 agent |
| 回复 | agent 调 `world_say`（或 MCP `world_say`） | 聊天栏可见 |

为什么用"后台任务退出"当敲门：DSH 会话没有对外的插话端口，后台任务结束会唤醒 agent，
这是把游戏里的 `/push` 变成"插队消息"的最短路径（无需改 DSH）。

### 16.3 常驻命令

```powershell
python tools/push_wait.py --timeout 3600   # 作为后台任务起；收到一条就退出
```

一条消息 = 一次唤醒。处理完再起一遍即可（或把 `--timeout` 给大一点，至少不用频繁重启）。

### 16.4 排错

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `/push` 没反应、也没回执 | 玩家 `admin = 0` | `world_players` 看 `admin` 字段；控制台 `admin <名字>` 或让它重进（自动给） |
| `push` 返回空 | 守护进程还是老的（没有 push 钩子） | 重启 `world_server.py`；返回 `NOSETUP` 会直接报错 |
| 收到但 agent 没动 | 没起 `push_wait.py` 后台任务 | 起一个；它退出时才是"敲门" |
| 消息太长 | 服务端聊天上限 150 字（`Vars.maxTextLength`），超了服务端会踢 | 分几条发 |
