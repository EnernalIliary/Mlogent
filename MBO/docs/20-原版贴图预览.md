# 20 · 用原版贴图做预览

> 一句话：`mbo preview` 现在直接把游戏原版方块贴图贴上去，不再只有色块；贴图来自工作区
> `assetsraw/assets-raw/sprites/`，找不到时自动回落到色块，不影响任何既有命令。

## 0. 结论

| 项 | 结果 |
|---|---|
| 贴图来源 | 工作区 `assetsraw/assets-raw/sprites/blocks/<分类>/<方块名>.png`（3013 张，32 px / 格） |
| 索引命中 | `runs/` 里出现过的 14 种方块 **14/14 有贴图**，缺 0 |

## 1. 贴图从哪来

优先用工作区里已经拆好的素材（快、不依赖 Steam 安装路径）：

```
assetsraw/
  assets-raw/sprites/
    blocks/<分类>/<方块名>.png      # ← 预览用这个（32 px / 格，2×2 机器就是 64×64）
    items/<物品名>.png              # 物品图标（本期未用）
  assets/sprites/sprites.png        # 打好的图集（未用）
  assets/sprites/sprites.aatls      # 图集索引（未用）
```

顺带查清的备用来源（没走这条路）：游戏安装目录 `E:\Program Files (x86)\Steam\steamapps\common\Mindustry\`
下面的 `jre\desktop.jar` 里有 `sprites/sprites.png` + `sprites/sprites.aatls`；`zipdata.zip` 只是用户数据
（saves / schematics / maps），**不含贴图**；工作区 `out/_server160.jar` 是 headless 版，也没有贴图。

## 2. 索引规则（`mbo/sprites.py`）

`SpriteSet` 扫描 `<root>/blocks/**/*.png`，以文件名为键建索引，解析顺序：

1. 精确名：`graphite-press.png` → `graphite-press`
2. 带子/管道这类“多混合位 × 多帧”的方块，文件名是 `<名字>-<混合位>-<帧>.png`：
   预览取**无混合、第 0 帧**的 `<名字>-0-0.png`（例如 `conveyor-0-0.png`）
3. 再退一步试 `<名字>-0`
4. 都没有 → 返回 `None`，调用方画色块（所以缺贴图不会炸）

`find_root()` 的查找顺序：环境变量 `MBO_SPRITES` → 从当前目录向上找工作区
`assetsraw/assets-raw/sprites`（或 `assets/sprites`）。CLI 上可用 `--sprites DIR` 指定。

## 3. 旋转规则

- 只对 `gamedata` 里 `rotate == True` 的方块旋转（带子、管道、钻头、门…）；机器/仓库/容器
  `rotate == False`，无论 `rotation` 字段是多少都不转（单测覆盖）。
- 旋转角 = `rotation × 90°` **逆时针**（`PIL.Image.rotate`）。这与模型里的方向表一致：

  | rotation | `DIRV`（布局坐标） | 屏幕上 |
  |---|---|---|
  | 0 | (1, 0) | 右（东） |
  | 1 | (0, -1) | 上（北） |
  | 2 | (-1, 0) | 左（西） |
  | 3 | (0, 1) | 下（南） |

- `overflow-gate` / `underflow-gate` / `router` 在数据里是 `rotate == False`，贴图本身不带方向，
  流向仍以 ASCII 图的 `+`（门）/`n`（节点）与文档里的语义为准。

## 4. 命令

```powershell
cd F:\OneDrive\桌面\AtomicStates\MBO
python -X utf8 -m mbo preview d10                    # 默认自动找贴图，写成 runs/d10/preview.png
python -X utf8 -m mbo preview p-one --scale 3        # 放大 3 倍（一格 78 px）
python -X utf8 -m mbo preview --all --scale 3        # 重绘全部 run + 重生成 runs/index.html
python -X utf8 -m mbo preview d10 --no-sprites       # 强制色块（对比用）
python -X utf8 -m mbo preview d10 --sprites <目录>    # 指定贴图根目录（需含 blocks/）
```

`--all` 会先逐张重绘 PNG 再写画廊；单张 run 出错只跳过它，不拖垮整批。

## 5. 自检证据

`spikes/gen/_check_sprites.py`（探针）与 `tests/test_mbo.py::TestSprites`（7 项）覆盖：

- 索引命中 14/14，`conveyor` 解析到 `conveyor-0-0.png`；
- 贴图尺寸 = `size × 格边长`（2×2 机器在 `cell_px=26` 时是 52×52）；
- 四个 rotation 的带子贴图两两不同；`rotate=False` 的方块贴图与 rotation 无关；
- 粘贴逐字节一致（不缩放、不调色）；
- 贴图版颜色数明显多于色块版。

全量核对（`spikes/gen/_verify_sprite_paste.py`）：把 `runs/` 下 13 张蓝图逐块重渲染，**107 个
方块的不透明像素与源贴图 0 处不一致**（透明处正确露出背景）。

对照图（同一张蓝图，左色块 / 右贴图）：`docs/img/compare-d10.png`、`docs/img/compare-p-one.png`。

## 6. 局限（有意不做）

- **无动画**：只取第 0 帧，机器不转、带子不流动。
- **无物品图标**：容器/黑洞里看不到石墨，产量仍看 `preview.summarize` 的文字行。
- **无混合位**：带子三通/拐角的自动拼接不画，只画直线底图。
- **无阴影/光照/液体层**：这是“示意俯视图”，不是游戏渲染；要权威结果请把
  `runs/<id>/blueprint.b64.txt` 粘进游戏。
- 门/路由器贴图不带流向箭头（游戏里也是靠玩家看朝向），流向看 ASCII 图与 docs/17、19。
