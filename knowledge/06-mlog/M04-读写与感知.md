# M04 读写与感知

## 一句话

mlog 的「读世界」只有五条正经通道：**sensor**（读属性）、**radar**（找单位）、**ulocate**（找建筑/矿石/刷怪点）、**getlink**（拿链接句柄）、**lookup**（按数字 id 反查内容），外加 **read** 读内存方块。

## 规则 / 公式

### 1. 参数顺序总表（文本槽位）

| 指令 | 文本形 | 输出槽 | 关键 token |
|---|---|---|---|
| sensor | `sensor <结果> <对象> <属性>` | 0 | 属性是 LAccess 名或内容名 |
| read | `read <结果> <内存块> <下标>` | 0 | 下标 0..31（world 512） |
| write | `write <值> <内存块> <下标>` | 无 | 越界静默丢弃 |
| radar | `radar <t1> <t2> <t3> <排序> <建筑> <方向> <结果>` | 6 | RadarTarget×3 / RadarSort |
| ulocate | `ulocate <模式> <flag> <enemy> <ore> <outX> <outY> <found> <outBuild>` | 4,5,6,7 | LLocate / BlockFlag |
| getlink | `getlink <结果> <下标>` | 0 | 0..@links-1 |
| lookup | `lookup <类型> <结果> <id>` | 1 | ContentType token |

`sensor` 的第三槽是「属性」：读引擎属性写 `@` 名（`@enabled`、`@health`），读内容数量写内容名（`@copper`）。

### 3. radar 与 uradar 的枚举

| 枚举 | 值 |
|---|---|
| RadarTarget（8） | any, enemy, ally, player, attacker, flying, boss, ground |
| RadarSort（5） | distance, health, shield, armor, maxHealth |

`radar` 只产出 **1 个**结果（第 6 槽是排序方向 `1`/`-1`，不是数量）。`uradar` 同理，且**第 5 槽在源码里传 null，是死槽**（写啥都不影响）。

### 4. ulocate

| 模式（LLocate） | 含义 | 会写哪些输出 |
|---|---|---|
| ore | 找矿石 | 只写 found（+ 成功时坐标） |
| building | 找建筑（按 BlockFlag） | found / build / 坐标 |
| spawn | 找刷怪点 | 同上 |
| damaged | 找受损建筑 | 同上 |

BlockFlag 18 项：core, storage, generator, turret, factory, repair, battery, reactor, extinguisher, drill, shield, launchPad, unitCargoUnloadPoint, unitAssembler, hasFogRadius, steamVent, blockRepair, synced。

**失败时的坑**：`outX/outY/outBuild` 在搜索失败时不写入 ⇒ 保留旧值；只有 `found` 一定被写。

### 5. getlink 与 lookup

- `getlink`：下标 `0..@links-1`，返回链接对象；越界/未绑定返回 null（不是崩溃）。
- `lookup`：首槽是 ContentType token（item/block/liquid/unit/…），按数字 id 反查内容对象；id 无效返回 null。

## 实测与反例

- ✅【E】未知属性名不报错，而是把结果变量写成 null（覆盖旧值）——S-16。
- ✅【E】未绑定的链接名当 sensor 目标 ⇒ null（S-17）。
- ✅【E】第三槽放建筑名（而非属性名）⇒ null（S-15）。
- ✅【E】@velX/@velY 不存在，正确属性是 @velocityX/@velocityY（L2-24）。
- ✅【E】radar 第 6 槽是排序方向 ±1，不是数量；一次只有一个输出（L2-17）。
- 反例（不成立边界）：**「ulocate 失败会把坐标写成 0」不成立**——失败时根本不写，坐标是上一次的旧值，这是竞态 bug 的常见来源。

## 常见误解

1. 「sensor 能读任意字段」——只能读 LAccess 枚举里的 77 个属性 + 内容数量。
2. 「radar 能一次返回多个单位」——不能，只有 1 个结果槽。
3. 「uradar 第 5 槽要填 0 表示不限」——那槽是死的，填什么都不影响。
4. 「getlink 越界会报错」——返回 null。
