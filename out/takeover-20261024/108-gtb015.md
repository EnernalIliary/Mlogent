# 108 · GTB 0.1.5：进服第一个动作就是拆建筑 ⇒ 拉黑 + 通告 + 把建筑放回去

> 用户 m10703：「再加一条，如果进游戏之后的第一个行为是拆除就ban、通报，然后恢复建筑。」

## §1 判据从哪来

| 需要的东西 | 用哪个 API | 依据 |
|---|---|---|
| 谁拆的 | `BlockBuildEndEvent.unit` → `Unit.getPlayer()` | `Mindustry-Source/core/src/mindustry/world/blocks/ConstructBlock.java:59-69`：`deconstructFinish(Tile, Block, Unit builder)` 里先 fire `BlockBuildEndEvent(tile, builder, team, true, null)`（:67），**然后才** `tile.remove()`（:68） |
| 拆的是什么 | 同一事件里的 `tile`：`tile.block() / tile.team() / tile.build` | 事件早于销毁 ⇒ 读得到种类、队伍、朝向、配置、血量比例 |
| 「第一个动作」 | 自己记账：`GTB_FIRST[uuid] = {t, done}` | 原版没有「玩家动作日志」这种东西；只能从 `PlayerJoin` 起把「非拆除动作」当作 `done` |

只判这四类「非拆除动作」：放方块（`onBuildEnd` 非 breaking）、改配置（`onConfig`）、
控单位 / 指挥方块（`noteInteract`，由 `UnitControlEvent` / `BuildingCommandEvent` 进）。
移动、聊天不算动作 —— 站着不动五分钟后才拆，仍然算「第一件事」。

## §2 改法

| 位置 | 改动 |
|---|---|
| `GriefToBan/scripts/main.js` | 新增 `GTB_FIRST`、`firstMark / firstClear / firstPending`、`tileSnapshot`、`restoreTile`、`firstBreakCheck` |
| `onJoin` | 末尾 `if (targetOf(p) === "target") firstMark(p);`（管理员、黑名单、观察模式非目标都不进） |
| `onLeave` / `WorldLoadEvent` | `delete GTB_FIRST[uuid]` / `GTB_FIRST = {}` |
| `onBuildEnd` | `e.breaking === true` 分支放在算 `p` 之前：取 `e.unit.getPlayer()` → `firstBreakCheck(e, p)` → return（不再走登记逻辑）；非 breaking 路径 `firstClear(p)` |
| `onConfig` / `noteInteract` | `firstClear(p)` |
| `firstBreakCheck` | 开关 / 管理员 / 目标判定 → `firstClear` → `punish(p, LIB.REASON.firstBreak)` → `Core.app.post` 里 `restoreTile` → 广播「已把 X 拆掉的建筑放回原处。」 |
| `restoreTile` | 原位不是 air 就不动（避免盖掉别人刚铺的）；`t.setBlock(block, team, rot)`，血量与配置按快照恢复 |
| `gtb-lib.js` | `BH_KEYS` 加 `firstBreak`、`DEFAULTS.bh.firstBreak: true`、`REASON.firstBreak` |
| `gtb-ui.js` | 行为开关第 ⑦ 项 + 说明 |

## §5 真机验

- 新建一个号进服，第一件事拆掉一台别人的建筑 ⇒ 应立刻看到「已拉黑 X：进服后第一个动作就是拆建筑」
  与「已把 X 拆掉的建筑放回原处。」两条通告，建筑回到原位（朝向、配置、血量比例一致）。
- 反过来：进服先放一块方块 / 改一次配置 / 控一下单位，再去拆 ⇒ 不处置。
- 设置界面「行为黑名单」里应有第 ⑦ 项，关掉后不再判。
