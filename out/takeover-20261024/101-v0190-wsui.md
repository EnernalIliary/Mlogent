# 101 · v0.19.0 工作区界面重做（A+C 改版）

日期：2026-11-02　驱动：用户 m13036 之后的界面改版规划（`docs/Mlog辅助-工作区快照-界面改版-方案.md`）

## 1. 取证（改之前是什么样）

- `renderWorkspaces(host,d)`（旧 `main.js:4869`）把每个工作区渲染成**一列纯文本行**：
  `wsRowLabel` + `wsBoundsText` + `wsProcLines` + `wsJobLines` 拼字符串，处理器表与作业时间线
  只有前几行、无列宽、无状态色。
- `renderWorkspaceDetail(host,d,ws)`（旧 `:4830`）是另一屏，一次只能看一个，且要先进去再退出来。
- `openWorkspaceDialog()`（旧 `:5470`）是 600×320 单栏 `pane`，底栏 5 颗按钮。
- 释放工作区（`wsRelease` :2332）**没有任何确认**：详情里点一下就删，规划稿 §4 要求确认。
- 世界里看不到工作区：`drawSelection` 只画当前拖拽框，工作区范围只以文字存在。

### 与方案的偏离（都在方案文档 §11 有回填）

1. **没有 `Pal.scarlet`**：本 checkout `Mindustry-Source/core/src/mindustry/graphics/Pal.java:76-88` 只有
   `remove=e55454` / `health=ff341c`，异地图与失败一律 `Pal.remove`。
2. **悬停高亮（C2）未做**：`InputListener` 子类化在 Rhino 下本仓 0 先例（`JavaAdapter` 也是 0 命中），
   风险大于收益；选中高亮已表达「这个矩形是这行」。
3. **选中态**只做 `▸` 前缀 + 左色条加亮，不用 `Styles.flatOver`（`Styles` 静态字段要 atlas，无头会炸）。
4. 处理器表四列固定宽而不是 `growX`（`growX` 会把四列挤成一团）。

## 4. 打包守卫（装机时抓到的坑，已修）

- 第一次装进游戏目录后 AI 全不可用：`main.js:266-271` 的 `sidecarVersionMismatch(h)` 返回
  `(v !== "" && v !== String(MOD_VERSION))`，而 `tools/logicd.py:87` 的 `SIDECAR_VERSION` 还停在 `0.18.4`、
  `MOD_VERSION` 已是 `0.19.0` ⇒ `sidecarTick`（`main.js:349-352`）与 `ensureSidecar`（`main.js:399-400`）
  会 `sidecarRetire(...)` 把模组自带的后端退役，AI 功能全不可用。gate 17/17 抓不到（没有断言两处版本相等）。
- 修法：① `tools/logicd.py:87` → `SIDECAR_VERSION = '0.19.0'`；② `tools/package.py` 的 `build()` 在
  `ver = mod_version()` 之后加守卫，`sidecar_version() != ver` 直接 `SystemExit`；③
  `tests/packaging/run_pack_tests.py` 的 VERSION.txt 检查后加两处版本一致性检查；④ CHANGELOG 0.19.0 加一条。
