# 24 · 石油钻井的产量：22.5 油/s 的真机实测（含探针的三条硬坑）

> 起因：用户指出「石油钻井的生产有误，煤分离比钻井 **3:1**」（`ratio-calc` 里 `oil-extractor` 一度按 **15 油/s** 算，
> 于是 3 台 `coal-centrifuge`（18 油/s）被算成要 2 台钻井）。
> 本文件把 `22.5 油/s` 从「源码推断」升级为 **v160.7 真机实测**，并记下复现所需的三个引擎坑。

## 0. 结论

| 地板 | `Attribute.oil` | 期望油/s | 真机实测油/s | 偏差 | `lastPump × 60` |
|---|---|---|---|---|---|
| `darksand`（黑沙） | 1.5 | 22.5 | **22.502** | 0.0% | 22.5 |
| `sand-floor`（沙地） | 0.7 | 10.5 | **10.502** | 0.0% | 10.5 |
| `shale`（页岩） | 2.0 | 30.0 | **30.002** | 0.0% | 30.0 |

同一台跑着的 `coal-centrifuge`：**2.045 煤/s**（理论 2）、**5.999 油/s**（理论 6）⇒ 3 台离心机吃 18 油/s，
1 台满黑沙钻井产 22.5 油/s，**供得起，用户说的 3:1 成立**（原来按 15/s 会算成 2 台钻井 = 2:3）。

- 探针：`spikes/sim/oil_floor_probe.py`（9354 B）
- 复现：`python -X utf8 MBO/spikes/sim/oil_floor_probe.py --ticks 900`
- 结果 JSON：`out/_probe/oil_floor_probe2.json`（`rates` / `dev_pct` / `lastPump_x60` / `centrifuge`）

## 1. 公式（源码，`Mindustry-Source` v159.3 语义）

```java
// SolidPump.updateTile（Fracker 继承它）
float fraction = Math.max(validTiles + boost + (attribute == null ? 0 : attribute.env()), 0);
if(efficiency > 0 && typeLiquid() < liquidCapacity - 0.001f){
    float maxPump = Math.min(liquidCapacity - typeLiquid(), pumpAmount * delta() * fraction * efficiency);
    liquids.add(result, maxPump);
    lastPump = maxPump / Time.delta;
}
// SolidPump.onProximityUpdate
boost = sumAttribute(attribute, tile.x, tile.y) / size / size;   // 3×3 全 darksand => 13.5/9 = 1.5
```

`oil-extractor` 的真机字段（从 `b` 打印）：`size=3 liquidCapacity=40 itemCapacity=10 baseEfficiency=0
pumpAmount=0.25 attribute=oil itemUseTime=60`。所以

```
每秒油 = pumpAmount × 60 × (validTiles + boost + attribute.env()) × efficiency
       = 0.25 × 60 × 1.5 × 1 = 22.5        （满黑沙）
```

`validTiles = Σ baseEfficiency/size² = 0`（Fracker 的 `baseEfficiency` 是 0，只有 `boost` 起作用）；
`pumpAmount × 60 = 15` 正是游戏 UI 印的那个数 —— 它是「属性 = 1.0」的乐观值，和钻头 UI 同类陷阱。

## 2. 三条硬坑（不满足就是「eff 恒 0、一滴不出」）

### 2.1 Fracker 需要 `Env.groundOil`，而生成世界默认没有

`Fracker` 构造里 `envRequired |= Env.groundOil`（`Env.groundOil = 1<<5 = 32`），
`BuildingComp.allowUpdate()` 要求 `block.supportsEnv(state.rules.env)`，即
`(envRequired & env) == envRequired`。`loadGenerator` 出来的世界 `rules.env` 只有 `terrestrial(1)` 等位，
**不含 32** ⇒ 方块根本不 update，`efficiency` 恒 0（但 `enabled/allowUpdate` 之外的一切看起来都很正常）。

修复：摆方块前 `Vars.state.rules.env = Vars.state.rules.env | 32 | 64;`（64 = `groundWater`，给抽水机备用）。

### 2.2 电力不能靠「贴相邻」

`power-source` 与 consumer 相邻**不会**并网：`e.power.graph.all.size = 1`、`prod = 0`、`status = 0`。
- `configureAny(...)` **不生效**（links 不变）；
- `b.configure(Point2[])` 生效，但 `Point2` 的类名是 `arc.math.geom.Point2`（`mindustry.types.Point2` 不存在），
  且必须用 `java.lang.Class.forName("arc.math.geom.Point2")` + `java.lang.reflect.Array.newInstance(cls, n)` 造数组，
  直接 `Array.newInstance(P2, n)` 在 Rhino 里报 `Can't find method (object,number)`。

```javascript
function setLinks(b, arr){                       // arr = [[dx,dy], ...] 相对坐标
  var cls = java.lang.Class.forName("arc.math.geom.Point2");
  var out = java.lang.reflect.Array.newInstance(cls, arr.length);
  for(var i = 0; i < arr.length; i++){ out[i] = new P2(arr[i][0], arr[i][1]); }
  b.configure(out);
}
setLinks(node, [[0,-1]]);   // node 连 source
setLinks(source, [[0,1]]);  // source 连 node（双向都要）
```

### 2.3 `setBlock` 不走 `placed()`，consumer 得手动进图

即使 node/source 之间 configure 好了，consumer 自己还在一张单方块图里（`extractor.gid` 不同、
`all = 1`、`status = 0`）。对 node 调 `placed()` 无效。有效且最短的做法：

```javascript
node.power.graph.add(extractor);   // 三者同一 gid，all=3，status=1，sat=1
```

（原因：直接 `tile.setBlock(...)` + `Vars.world.build(x,y)` 绕过了 `Building.placed()` 里的自动并网。）

## 3. 怎么量：把钻井自带的油倒空

钻井**不会**把油 dump 进相邻的 2×2 `liquid-container`（本 rig 里 `tankOil` 恒 0）；
油积满自带的 `liquidCapacity = 40` 后 `shouldConsume()` 变 false、`efficiency` 归 0。

所以采样口径用「每轮读出自带油再清空，累加 / 时长」：

```javascript
function drainP(b, item){ var v = b.liquids.get(item); b.liquids.remove(item, v); return v; }
// 另存 b.lastPump*60 交叉校验（lastPump 就是「每 tick 打了多少」）
```

实测 `--ticks 900` → 42 个采样、窗口 13.2 s，`rates` 与 `lastPump_x60` 两套口径完全一致。

## 4. 对 ratio-calc 的影响

- `oil-extractor` 数据从 `15` 改成 **`22.5`**（`ratio-calc/export_data.py` 的 `build_pumps`：
  `Fracker` 用 `perSecond = pumpAmount*60*floorAttr`、`tiles = size²`，并写入 `floorAttr/floorName`）。
- 新增 `--oilfloor`（页面「油田属性」输入框，默认 1.5）：0.7 → 10.5 油/s、2.0 → 30 油/s，台数随之变化
  （沙地时 3 台离心机要 2 台钻井）。
- 3:1 现在是**实测结论**，不是经验值。

## 5. 反例 / 边界（别踩）

| 现象 | 真实原因 |
|---|---|
| 钻井 `efficiency = 0`、一滴不出，但 `enabled/productionValid` 都 true | `rules.env` 缺 `groundOil`，方块压根不 update |
| 电力 UI 显示没电、`sat = 0`，但方块确实贴着 `power-source` | 没 `configure`、也没 `graph.add`，图和图没并起来 |
| 钻井把油憋在 40 容量里不出 | 它 dump 不到邻居时就会堵住 → `shouldConsume()` false；这是正常行为，不是 bug |
| 游戏内 UI 显示 15/s | `pumpAmount × 60`；真实产量还要乘地板属性（满黑沙 1.5） |
