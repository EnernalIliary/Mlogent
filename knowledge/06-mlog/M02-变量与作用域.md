# M02 Variables and scope

## In one sentence

Each processor has its own LExecutor variable table; a variable has only two shapes — **number** or **object** — and null is not a third value but "the object slot is empty", which **converts to the number 0, not NaN**.

## Rules / formulas

### 1. The real structure of LVar (LVar.java:8-127)

| Field | Meaning |
|---|---|
| name / id | variable name (with the @ prefix) and integer slot number |
| isobj | true = object shape (objval is live), false = number shape (numval is live) |
| objval (Object) | the object; **null means an empty reference** |
| numval (double) | the numeric value |
| constant | the constant bit; SetI **silently drops writes** to a constant variable |
| syncTime | network sync timestamp |

**There is no separate null type**: null == isobj is true and objval == null.

### 2. Three read semantics (memorise these)

| Method | Number variable | Object variable (non-null) | null | Source |
|---|---|---|---|---|
| bool() | abs(numval) >= 0.00001 | true | **false** | LVar.java:52-54 |
| num() | numval (NaN/Inf→0) | 1 | **0** | LVar.java:56-58 |
| numOrNan() | numval | 1 | **NaN** | LVar.java:61-63 |

⇒ For the same null: bool gives false, num gives 0, numOrNan gives NaN. **Only numOrNan can tell null apart from the number 0**.

### 3. Write semantics

- setnum(v) (LVar.java:87-97): when v is NaN or ±Inf it **writes no number but a null object instead** (objval=null; isobj=true). ⇒ set x (0/0) yields null, not NaN.
- set(LVar other) (LVar.java:110-118): objects are copied verbatim; in number shape, if other.numval is invalid it writes 0.
- The 0.00001 threshold appears only in bool(); num() has no threshold. [src: knowledge/VERSION.md:1]

### 4. Scope

- **One processor, one scope**: the variable table hangs off LExecutor, so same-named variables on two processors do not affect each other; a link passes object handles only, never variables.
- Variable names are case-sensitive; an @ prefix looks in the built-in table / content table first (@copper and @conveyor come from the content table) and only falls back to a plain variable when nothing matches.
- Variables need no declaration: assignment creates them; an unassigned variable starts at putVar's default numval=0 (【I】 inference, not checked on a live machine).

### 5. Built-in variables (v159.3 source view: 34 read-only + 3 special) [src: knowledge/VERSION.md:1]

@this @thisx @thisy @links @ipt @unit @counter @time @tick @second @minute @waveNumber @waveTime @mapw @maph @ctrlProcessor @ctrlPlayer @ctrlCommand @server @client @clientLocale @clientUnit @clientName @clientTeam @clientMobile @clientMusicPlaying @pi @e @degToRad @radToDeg @wait true false null

Three tiers of writability (the key difference):

| Variable | Can it be set | Note | Source |
|---|---|---|---|
| @counter | ✅ yes | a non-constant built by putVar; this is the documented jump | LAssembler.java:25 |
| @ipt | ❌ no | a putConst constant, SetI drops it; **setrate only** | LExecutor.java:138 / :2018-2036 |
| @unit | ❌ no | putConst(@unit, null), SetI drops it; **ubind only** | LAssembler.java:27 |

`@links` = the current **valid** link count (written at LogicBlock.java:582-599), not the number of placed link blocks.

### 6. Memory cells (storage that outlives a tick)

| Block | Capacity | Read | Write | Source |
|---|---|---|---|---|
| memory-cell / memory-bank | 64 cells / 512 cells | read result cell index | write value cell index | MemoryBlock.java:41; content/Blocks.java:6872-6883 |
| world memory cell | **512 cells** | same | same | Blocks.java:6962-6969 |

An out-of-range read returns null (`Double.NaN`), an unwritten but legal address returns 0, and an out-of-range write is silently dropped (MemoryBlock.java:64-81). Variables also survive across ticks, but dismantling or rebuilding the processor clears them while memory blocks keep their contents.

## Measured facts and counter-examples

- ✅【E】sensor_attrs.json records @enabled/@color as added in the v160.7 jar (added_2026_10_25) and absent from the v159.3 source ⇒ the same sensor code may stop working across versions. [src: sensor_attrs.json]
- Counter-example (a boundary that does not hold): **"null equals 0" holds only under num()**. op equal uses num() ⇒ null and 0 compare equal; but arguments that go through numOrNan (some world instruction coordinates) do not treat null as 0.
- Counter-example: **a set does not always land**. Setting @unit/@ipt fails silently: the program keeps running and the value never changes — the hardest class of bug to find.
- ✅【E】op select is silently replaced by a noop in v160.7 (assertion table L1-25): no error, the index does not move, and the result variable keeps its old value. [measured: assertion table (docs/断言表.md)]

## Common misconceptions

1. "mlog has a null value." — no; null is an empty object slot that converts to the number 0 and the boolean false.
2. "NaN can be stored in a variable." — setnum turns NaN/Inf into null outright (LVar.java:87-97).
3. "@ipt can be set." — the constant bit blocks it; only setrate takes effect.
4. "Variables are shared between processors." — they are not; sharing works only through memory cells, or read/write plus a world processor.
