# 108 · v0.20.0 自由对话（纯文本 + 模型可调工具 + 双栏选单/详情）

m02414「就是在MAI管理面板中新建对话」/ m02455「对了，对话选单和右侧对话详情的分隔也加回去」。

## 1. 取证（为什么是这个做法）

- 原有「对话」都不是多轮自由对话：v0.16.1 蓝图页 `blueprintChatAsk/Submit/Poll`（`main.js`）只是拿蓝图上下文投一个 improve 作业；
  F3 描述面板是「填一句 → 投作业 → 看结果」。作业契约 `tools/jobqueue.py` 的 mode 只有 `new|edit|improve`，
  且 `tools/mlogprovider.py` 的 `HttpProvider.__call__` 只发一次 `/chat/completions`、`parse_reply()` 抠一个 JSON ⇒ **流水线里没有工具调用**。
- 模组侧 socket 读超时 16s（`main.js` 的 `TIMEOUT_MS * 4`），而一次模型调用可能 60s ⇒ `/chat` 必须**先回包再算**，只能异步 + 轮询。
- UI 结论沿用 v0.19.6：Arc 的 `Cell.align` 不继承表（`Table.java:1243`），所以新窗口里每一格都要显式 `.left()`；
  `Dialog.java:78` 的 `add(title).expandX().fillX()` 会把标题撑满 ⇒ 打开前先 `titleTable.clearChildren()` 再按自然宽度重放。
  两栏之间 `padRight(6)` 的 6px 空隙在深色背景上几乎看不见 ⇒ 用户要的「分隔」必须画一条真实控件。

## 2. 实现

### 2.1 侧车（`tools/chats.py` 新增 921 行 + `tools/logicd.py` 路由）

| 位置 | 内容 |
| --- | --- |
| `tools/chats.py` Store :213 | 一会话一 JSON（`<chats>/<id>.json`），tmp + fsync + `os.replace` 原子写，Windows 争用重试 6 次（照 `jobqueue.Store`） |
| `chats.start` :429 | 追加 user 行 → `state='running'` → 起 daemon 线程 → **立刻返回**（模组 16s 超时等不起模型） |
| `chats._run_loop` :539 | 工具循环，`MAX_ROUNDS = 6`，单次工具输出截 `MAX_TOOL_OUTPUT = 4000`，整轮 `OVERALL_TIMEOUT = 180` |
| `chats._call_model` :603 | 端点不支持 tools（400/404/422）→ 去掉 `tools`/`tool_choice` 重试一次，成功则 `tools_supported=false`，该会话后续不再带 tools |
| 工具表 `TOOLS` :57 | `mlog_check`（静态检查）、`mlog_value`（抽象求值）、`mlog_pack`（打包成蓝图串）、`game_lookup`（block/item/unit/status/sensor/instr/op/template/cmd）、`mlog_template`（6 个内置模板） |
| `chats._post_chat` :627 | 回环绕开系统代理直连（本机注册表代理会吞上传/回包） |
| `tools/logicd.py` | `import chats` :83、`SIDECAR_VERSION = '0.20.0'` :88、`GET /chats` :1274、`GET /chat?id=` :1278、`POST /chat` :1367、`DELETE /chat?id=` :1389、`chats_store()` :1430、idle-exit 也把 chats 计入 running :1452、`--chats-dir` :1481 |

线格式（模组只读这些）：

- `POST /chat {id?,text}` → `{ok,id,title,state:'running',created,updated,msgs,messages}`；空 text / 超 8000 / 未知 id → 400 中文 error；同一会话运行中 → 400 `{ok:false,error:'busy'}`。
- `GET /chats?limit=50` → `{ok,count,chats:[{id,title,state,msgs,turns,tools,created,updated,error,model,tools_supported}]}`（`tools` 是**次数**，按 `updated` 倒序）。
- `GET /chat?id=` → `{ok,chat:{id,title,state,messages[],tools[],rounds,tools_supported,error,created,updated,reply,last}}`（`tools` 是**数组**，`messages` 是 OpenAI 形状）。
- `DELETE /chat?id=` → `{ok,id,deleted}`。
- `state` 只有 `idle|running`；失败时 `state='idle'` + `error` 文本（见 m02669/m02725 两次对齐）。

### 2.2 模组（`MlogAuxiliary/scripts/main.js`，约 +470 行）

- 入口：`openJobManager()` 内容区顶部一行 `＋ 新建对话`（130×30）+ 灰色说明「模型可以自己调 mlog 检查 / 游戏数据这些工具；对话不写进处理器」。
  底栏 5 个按钮已占满 600 宽，所以入口放内容区第一行。
- `openChatDialog()`：标题钉左（`titleTable.clearChildren()` + 自然宽度）、`chatPlan(wsScreenSize())` 算尺寸（scene 单位，沿用 v0.19.3 结论：
  `availW = clamp(w-56, 520, 1080)`、`availH = clamp(h-210, 300, 700)`、`listW = clamp(availW*0.24, 190, 260)`、`detailW = max(300, availW-listW-16)`、`wide = w >= 860`）。
  宽屏三件套：`pane(listT).width(listW)` → `image(Tex.whiteui).width(2).height(availH).color(Pal.gray).padLeft(7).padRight(7)` → `pane(detailT).width(detailW)`；
  分隔线拿不到 `Tex.whiteui`（无头）时 catch 里退回 14px 空 Table。窄屏退化成单栏 + 「← 返回选单」。
- 输入行**不随刷新重建**（打了一半的字不会被吃掉）；发送成功后立刻 `chatPoll()` + `chatReloadList()`。
- 轮询：`chatPoll()` 一次 `GET /chat?id=`，`state !== 'running'` 收工；`chatTick()` 每帧只在 `open && polling` 时动、900ms 节流；
  侧车没连上（-1/0）累计 20 次放弃；`busy` → 「上一条还没答完，等它说完再发」。
- 列表卡：状态色条（选中 `themeColor()` / 出错 `Pal.remove` / 思考中 `Pal.accent` / 其它 `Pal.gray`）+ 标题 + 「N 条 · 工具 M 次 · 时间 · 状态」。
- 详情：标题 + 状态、`工具 N 次 · 轮次 N[· 端点不支持工具（已降级成纯文本）]`、transcript（你说 / MAI 说 / 每次工具调用单独一行「🔧 名字 参数摘要」/
  tool 结果「· 名字 → 单行摘要」），超过 60 条只显示最后 60 条，底部 error 行。
- 删除：`showConfirm("删除对话", "删掉这段对话（名字）？聊天记录不再留存，也不能恢复。")`。
- 自检口 `api.maiChatUiProbe`（`MAICHATUI`）：`chatPlan` 三档、`chatStateCn` 三态、`chatCardSub`、`chatToolLine`、`chatFlat/chatStrip/chatIdSafe/chatErrText/chatArrLen`。
