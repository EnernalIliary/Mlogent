# §102 v0.24.1：一行写错会被游戏静默换成 noop —— 门禁三层

日期：2026-11-10。用户原话（m07998）：

> 刚刚在游戏中为MAI下发了一次任务，但是第一行是noop，你排查一下原因，改进。

## 1. 取证：那行为什么变成 noop

真 v160.7 引擎逐条解析那个作业的代码（`out/_noop_probe.py`，用 `out/_server160.jar` 的
`LAssembler.read`），首行 `radar e projector1 enemy distance 1` 得到 `InvalidStatement`。

机制链（源码在本仓 `Mindustry-Source/`）：

- `core/src/mindustry/logic/LParser.java:142-147`：每行解析失败不抛，直接换成
  `new InvalidStatement()`；
- `LStatements$InvalidStatement` 以 `@RegisterStatement("noop")` 注册，`build()` 返回 `NoopI`
  ⇒ 编辑器里那行显示 `noop`，执行时什么都不做；
- `LAssembler.read()` 自己不 catch（只有 `LParser.parse()` 结尾对**未定义 jump 标签**才
  `error(...)` 抛出，属整段失败）。

解析矩阵（`out/_noop_matrix2.py`，真引擎一次跑完）确认**只有四类**硬失败：

| 类 | 例 | 结果 |
|---|---|---|
| 未知指令 | `frobnicate a b c` | InvalidStatement |
| 枚举槽写了词表外的词（大小写敏感） | `radar e …` / `radar Enemy …` / `control foo …` / `ucontrol foo …` / `jump 0 foo a b` | InvalidStatement |
| `ulocate` 参数不足 | `ulocate foo` | InvalidStatement |
| 字面 `noop` | `noop` | InvalidStatement |

少操作数（`radar` / `uradar` / `sensor` / `control` / `jump`）由引擎按默认值补齐，**照常执行**
⇒ `under-arity` 保持 WARN 是对的。

用户那行的三处错：`e` 是输出变量却被塞进第一个 filter 槽；`projector1`（建筑）放到了 filter 槽；
少了最后的输出变量。正确写法：

    radar enemy any any distance projector1 1 e

另：整段解析失败（未定义标签等）不是只丢那一行 —— `LogicBlock.java:430-432`
`catch(Exception e){ … executor.load(LAssembler.assemble(code = "", privileged)); }`
会把代码换成**空程序**、处理器停摆（不是「继续跑旧程序」，此前说法已纠正）。

## 2. 三层修改

| 层 | 文件 | 改法 |
|---|---|---|
| 分析器 | `tools/mlogcheck.py`（+3 镜像 + MANIFEST） | `slot-not-in-enum` WARN→**ERR**，覆盖面扩到 ConditionOp / BlockFlag / LUnitControl，比较改大小写精确，radar 文案带七操作数签名；新增 `unknown-instruction`（**ERR**，与 54 个注册语句名精确比对）；`undefined-jump-location`（**ERR**，原 `no-target-jump` 的 WARN 升级）；`under-arity` 仍 WARN、why 补默认值说明。新增 6 个夹具，`rule-coverage.json` 重生成 |
| 模组 | `MlogAuxiliary/scripts/main.js`（+225 行纯插入，起点 `:2514`） | `engineNoopReport()` 用 `LAssembler.read(code, privileged)` 在写入前跑游戏自己的解析器：`writeBuild` 见到 `InvalidStatement` 拒写并报行号；`writeMany` 事务预检每台报第一处；作业卡片成功结果上加「⚠ 游戏会把第 N 行解析成 noop」；整段失败写明「游戏会把它当成空程序：写进去也不会执行」。`noopLineMap()` 照抄 LParser 的切分规则把语句下标映射回物理行号（注释/空行/label 不漂） |
| 话术 | `tools/mlogprovider.py` | `=== rules ===` 段新增 `enum_rules()`：从 `tools/instr_enums.json` 直接引 radar/uradar 七操作数顺序 + RadarTarget/RadarSort/ControlType/LUnitControl/LLocate/BlockFlag/ConditionOp 词表；结尾大写警告「这些槽收词表里的词、大小写敏感、写错整行变 noop、作业会被拒」 |

## 2.5 顺带修好：样板库里的两条死指令

11 个 prompt 样板里「unit transport」「unit supply loop」用了 `itemTake` / `itemDrop` ——
v160.7 没有这两条指令（`LStatements.java` 的 54 个 `@RegisterStatement` 里没有，它们是
`ucontrol` 的子命令）。真引擎解析后每行都是 `InvalidStatement`；模型抄样板就会写出整段
停摆的程序。改成 `ucontrol itemTake` / `ucontrol itemDrop` 后，把 11 个样板全过一遍真
v160.7 引擎（`out/_samples_parse.py`，LAssembler.read）：

    [0] stmts=7 invalid=0
    ...
    [10] stmts=6 invalid=0
