# 100 · v0.18.4：模型思考可以看全文了

起因是用户 `m13036` 一句话：「为什么不能查看当时的思考内容，而只能看到工作状态」。
结论不是「思考没存」，而是「存了，但三个入口都只显示状态词」。

## 一、取证：思考一直都在，是三处 UI 只给开头/状态

1. **思考确实被收下并落盘**：`tools/mlogprovider.py:719-728` 把端点的 `reasoning_content`（或 `reasoning`）
   收进 `res["reasoning"]`（`REASONING_MAX = 12000`）；`tools/jobqueue.py:680-684` 在作业收尾时写进
   `job["reasoning"]`（`REASONING_MAX = 20000`）。`out/jobs/` 里 done 的作业逐条带这个字段。
2. **生成过程中确实只有状态词**：sidecar 是非流式调用，整轮 HTTP 结束前不存在思考文本。这是结构性的，
   不是 UI 藏起来了 —— 所以「当时的思考」只能在作业终态之后看。
3. **终态入口原来不给看**：`jobWidgetView()` 里 `done` 只 `previewLogic()`（开原版逻辑编辑器预览代码），
   `rejected/failed/cancelled` 只 `hint` 一行状态。思考只挂在 `renderJob()` 与 `renderManagerDetail()`
   两个隐蔽详情窗里，各显示 `jobReasoningLines(job, 16, 40)` 的开头 16 行 × 40 字。
4. **列表接口故意不带全文**：`GET /jobs?all=1` 在 `tools/logicd.py:1176-1190` 的 `BRIEF_DROP` 里剥掉
   reasoning，只有单个 `GET /jobs?id=` 带全量。所以「作业管理」列表点进来的行要先按 id 再拉一次。

## 二、改法（都在 `MlogAuxiliary/scripts/main.js`）

| 新函数 | 行 | 干什么 |
|---|---|---|
| `jobThinkAll(job)` | `:3397` | 取全量思考文本（`jobReasoningText` 的别名，语义更直白） |
| `jobThinkCopy(job)` | `:3401` | `Core.app.setClipboardText` 复制全量；空则提示「端点没返回 reasoning_content」 |
| `openThinkDialog(job)` | `:3414` | `Packages.arc.scene.ui.Dialog` + `cont.pane` 滚动区 640×420（pane 失败则回落 `growX`），`jobReasoningLines(job, 100000, 60)`；按钮 `复制全部` / done 时 `看代码` / `关闭` |
| `jobThinkFetchOpen(job)` | `:3440` | 列表行没有全文时先 `jobGet(String(job.id))` 拉全量再开窗 |

三个入口接上：

- `jobWidgetView()` 终态（`:4006`）一律先 `var tr = openThinkDialog(job);`，只有回 `no reasoning`/`no ui`
  才退回老行为（done 弹代码预览、其它弹一行状态 + 「端点没返回思考内容」）。
- `renderJob()`：done 分支 `写入` 旁边加 `思考`（`:3515`）；失败/被拒那一支补 `思考`/`关闭`（`:3537`，
  这一段以前一个按钮都没有）。
- `renderManagerDetail()`：作业详情加 `思考（N 字符）` / 没全文时 `思考（读取全文）`（`:4567`），走
  `jobThinkFetchOpen()`。
