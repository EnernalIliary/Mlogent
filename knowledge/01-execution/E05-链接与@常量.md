# E05 链接与 @ 常量

## 一句话

处理器能在程序里直接用「链接名」访问方块，链接名是**编译期常量对象**；`@` 开头的东西分三种：真常量（const，`set` 静默丢弃）、全局可写变量（每帧由引擎刷新）、以及内容/数学常量。

## 规则 / 公式

### 1. 链接的解析

```java
// LogicBlock.java:379-397
link.logicVar = asm.putConst(link.name, world.build(link.x, link.y));  // 名字 → 方块对象
linksVar = asm.putConst("@links", executor.links.length);              // 有效链接数
```

| 事实 | 值 / 行为 | 依据 |
|---|---|---|
| 链接坐标 | 相对处理器（`--link name@dx,dy`） | 断言表 S-02 |
| `@links` | **有效**链接数（不是配置数） | LogicBlock.java:396/582-599 |
| `getlink result i` | 第 i 个有效链接（0 基），越界 → null | LExecutor LinkI |
| 链接名 | 编译期 `putConst`，不可被 `set` 改 | LAssembler.java:124 |
| 未绑定名字当 sensor 目标 | 结果 **null** | 断言表 S-17 |

### 2. @ 常量三层分类（GlobalVars 注册表）

| 层 | 注册方式 | 可写性 | 例子 |
|---|---|---|---|
| 编译期常量 | `putConst` | **不可写**（set 静默丢弃） | `@links` `@ipt` `@unit` `@this` `@thisx` `@thisy` `@queries`(仅 world) |
| 全局变量 | `putEntry` | 可读，引擎每帧刷新 | `@time` `@tick` `@second` `@minute` `@waveNumber` `@waveTime` `@mapw` `@maph` `@server` `@client` |
| 客户端特权 | `putEntry(...,true)` | 仅特权处理器可读 | `@clientLocale` `@clientUnit` `@clientName` `@clientTeam` `@clientMobile` `@clientMusicPlaying` |
| 内容常量 | `put` | 不可写 | `@copper` `@air` `@solid` `@mono` `@status-wet` … |
| 数学常量 | `putEntry` | 可读 | `@pi` `@e` `@degToRad` `@radToDeg`（还有 `π`） |
| 单位控制源 | `put`（句柄） | 用于 sensor 的 controller 属性 | `@ctrlProcessor` `@ctrlPlayer` `@ctrlCommand` |

### 3. 时间类变量的**单位陷阱**

```java
// GlobalVars.java:190-199
varTime.numval   = state.tick / 60.0 * 1000.0;   // 毫秒！
varTick.numval   = state.tick;                  // tick 数
varSecond.numval = state.tick / 60f;            // 秒
varMinute.numval = state.tick / 60f / 60f;      // 分
varWaveTime.numval = state.wavetime / 60f;      // 秒
```

| 变量 | 单位 | 换算 |
|---|---|---|
| `@time` | **毫秒** | 游戏运行 tick/60×1000 |
| `@tick` | tick | 整数 tick 数 |
| `@second` | 秒 | tick/60 |
| `@minute` | 分 | tick/3600 |
| `@waveTime` | 秒 | 当前波剩余时间 |

### 5. set 不可写的三个特殊变量

`@counter` 是**普通 var**（可写，改写跳转）；`@ipt` / `@unit` 是 **const**：

| 变量 | 声明 | 想改它 | 正确做法 |
|---|---|---|---|
| `@counter` | `putVar`（非对象） | 直接 `set @counter N` | 可写 |
| `@ipt` | `putConst`（LAssembler:26 / LExecutor:136） | `set @ipt 10` **静默丢弃** | `setrate 10` |
| `@unit` | `putConst(null)`（LAssembler:27） | `set @unit u` **静默丢弃** | `ubind` |

## 实测与反例

- ✅【E】`set @ipt 5` 后读回 @ipt 不变（const 被 SetI 丢弃）。
- ✅【E】`sensor x 目标 @enabled` 在 v160.7 有效，在 v159.3 无效（LAccess 集合差异）。 [src: knowledge/VERSION.md:1]
- 反例（不成立边界）：**「链接名就是变量名，可以 set」不成立** —— 链接名是 const 对象，`set 名字 x` 被丢弃。
- 反例：**「把 block 名写在第三操作数等于给坐标」不成立** —— 第三操作数放 block 名 ⇒ 结果是 null（断言表 S-15）。
- 【U】`getlink` 下标越界的确切产物（null 还是保持旧值）需要探针实验；源码按数组访问，推测为 null。

## 常见误解

1. 「@time 是秒」——是**毫秒**（GlobalVars.java:190）。
2. 「@links 是配置的链接数」——是有效链接数。
3. 「sensor 属性随便写」——写错属性名会把目标变量写成 null 覆盖旧值（S-16）。
4. 「@unit 是变量可以 set」——const。
