# E06 Cross-version differences

## In one sentence

This project has **two authorities**: semantics come from the `v159.3` source tree (tag v159.3, HEAD 5811844), numbers come from the `v160.7` jar reflection plus the live game — the source trails the live build by one minor version, so "not in the source" does not mean "not in the game". [src: knowledge/VERSION.md:1]

## Rules / formulas

### 1. Division of labour between the two authorities (VERSION.md)

| Authority | Location | Answers |
|---|---|---|
| v160.7_rt | `out/_server160.jar` reflection, `MBO/gamedata/v160.7/`, the live game | numbers, enum sets, actual behaviour | [src: knowledge/VERSION.md:1]
| v159.3_src | `Mindustry-Source/core/src/mindustry` (tag v159.3) | semantics, execution flow, field order | [src: knowledge/VERSION.md:1]

Precedence for numbers: **jar reflection > v159.3 source > live-game measurement > our own manual > any other copy**. [src: knowledge/VERSION.md:1]

### 2. Confirmed version differences

| Item | [v159.3] | [v160.7] | Evidence |
|---|---|---|---|
| `status` state names | accepts only the **bare name** (`wet`) | the bare name and `@status-wet` are **equivalent** | assertion table L1-23/L1-24 |
| `op select` | works as a normal select | **silently swapped for noop** (`@RegisterStatement("noop")`), the instruction index stays the same | L1-25 |
| LAccess set | no `enabled` / `color` | **has them** (77 entries in total) | `added_2026_10_25` in `tools/sensor_attrs.json` |
| world processor rate cap | the source says 8 ipt / 40 clamp | **maxInstructionsPerTick=1000** | Blocks.java:6949-6960 vs jar |
| Save build number | — | a build 160 save **only loads under v160** | assertion table L3-04 |

### 3. Writing convention (enforced in this project)

Behaviour that may vary by version must be written **side by side**:

```text
[v159.3] status 槽只认裸名 wet。
[v160.7] status 槽裸名与 @status-wet 等价。
```

For a conclusion that holds in one version only, list just that version in the frontmatter `ver` field (e.g. `ver: [v160.7_rt]`).

### 4. Documentation-conflict list (**do not inherit**)

| Conflict | Wrong claim | Correct | Evidence |
|---|---|---|---|
| status argument | status takes true/false | the source field is the boolean `clear`, written true / false | L2-22 |
| ulocate arguments | the first slots are coordinate outputs | slot 1 is the locate enum; outX/outY sit in slots 4/5 | L2-23 |
| radar | slot 6 is a count | it is the **sort direction, ±1**, and there is a single output | L2-17 |
| uradar | all 7 parameters are used | slot 5 is dead (the source passes null) | L2-17 |
| Unit velocity | `@velX` / `@velY` | `@velocityX` / `@velocityY` | L2-24 |
| `cmd_index.json` argument order | getblock/setblock/weathersense/spawnwave/playsound are out of order | follow `## 导出格式` in the md | `06-mlog/instructions.json.meta.discrepancies` |
| Old data table | all 447 `craftTime` entries are -1 | unusable | VERSION.md |
| The "power use" column in the docs | claims per unit time | it is actually **per tick** | VERSION.md |
| `instr_semantics.json` | three size versions coexist | use the **56.5KB** one under `tools/` | VERSION.md |

### 5. How to tell whether "this is a version difference"

1. Check the jar reflection artefacts first (the `source`/`version` fields in `tools/*.json`).
2. Then the v159.3 source; if the source lacks it and the jar has it ⇒ **added in the new version**, tag [v160.7].
3. If both have it but behaviour differs ⇒ a real semantic change; measure it (live game/emulator) and then write it side by side.
4. If only the manual has it ⇒ downgrade to **U** and state "which experiment is needed".

## Measurements and counter-examples

- ✅【E】`op select` silently becomes noop on v160.7 (L1-25); nothing in the v159.3 source shows this, **only measurement finds it** — counter-example: reading the source alone misses this kind of "version drift". [measured: assertion table (docs/断言表.md)]
- ✅【E】The bare-name / `@status-` difference for `status` (L1-23/24) shows "the documented slot was right but the value set changed".
- Counter-example (a boundary that does not hold): **"source = live behaviour" is false**. The source trails by one version, with at least 2 confirmed differences.
- 【U】How to tell reliably "which version the emulator is running" is not yet baked into a probe; it needs the `_server160.jar` manifest or `Vars.build`.

## Common misconceptions

1. "if the source lacks it, it does not exist" — it may have been added in the new version.
2. "every number in the manual is usable" — `craftTime` is all -1 and the power column has the wrong unit; check the known errors in VERSION.md first.
3. "any of the three instr_semantics copies will do" — only the 56.5KB version under `tools/` counts.
