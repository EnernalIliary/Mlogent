# 113 · v0.21.1：合并「控制面板 / MAI 对话」两个入口，加上逻辑标志

> 版本：0.21.1（`MlogAuxiliary/scripts/main.js` 的 `MOD_VERSION`、`MlogAuxiliary/mod.hjson`、`tools/logicd.py` 的 `SIDECAR_VERSION`）
> 用户原话（m04334）：「可以，但是工作区的按钮宽度不够，被换行了其它没有问题。合并控制面板和MAI对话吧。对了，合并之后要加个逻辑标志并染上主题色。完成之后继续做档3」

## 1. 取证

- **按钮折行**：v0.21.0 把两个分段按钮写死成 `width(64)`。「工作区」是三个汉字，字宽约 15px（默认 16 号字），
  加上按钮内边距与 `.padLeft(6)`，64px 装不下 ⇒ Arc 的 `Label` 在按钮里自动换行，视觉上按钮变高、上下不齐。
  用户在真机上看到的正是「按钮宽度不够，被换行了」。
- **两个入口其实是同一件事**：`<main.js:6604>` 的「MAI 控制面板」按钮（v0.18.3 用户 m11124 命名）调的就是
  `openWorkspaceDialog()`；v0.20.1 又在旁边加了「MAI 对话」调 `openChatDialog()`。v0.21.0 档1 之后两者已经是同一窗口的两种模式，
  并排两个按钮既重复又容易让人以为它们是两套东西。
- **逻辑标志**：用户要「加个逻辑标志并染上主题色」。仓库里已有的主题色取值函数是 `themeColor()`（设置里的主题色），
  `Table.image(Drawable, Color)` 是 Arc 现成 API（本文件 `:928` 就有 `t.image(Tex.whiteui, themeColor()).growX().height(3)` 的先例），
  不需要 JavaAdapter、不需要新 drawable。

## 2. 改法

| 位置 | 改法 |
| --- | --- |
| `dualSegWidth(mode)`（新增，共用外壳区） | 按字数给宽度：对话 72 / 工作区 88；两个分段按钮都加 `.ellipsis(true)` —— 大字号时只省略、不折行 |
| `LOGIC_NAME = "逻辑助手"`（新增） | 合并后的窗口名，标题为 `"Mlog辅助 · 逻辑助手 v" + MOD_VERSION` |
| `dualChrome(d, mode)` | 标题行最左插主题色方块 `d.titleTable.image(Tex.whiteui, themeColor()).size(10).padLeft(2).padRight(6)`，再是标题文字，再是分段开关 |
| `openLogicAssistant()`（新增）+ `api.maiLogicAssistant` | 唯一对外入口：`dualSwitch(DUAL.last)`，即按上次用过的模式打开（第一次是对话） |
| `blueprintPageHook()` | 原来并排的「MAI 控制面板」(150) + 「MAI 对话」(130) 合成一个 `btns.button("MAI " + LOGIC_NAME, ...)`（150 宽），左边先放一个 `btns.image(Tex.whiteui, themeColor()).width(8).height(18)` 主题色方块 |
| 工作区窗底栏 | 删掉 v0.20.1 加的「＋ 对话」（切模式用标题行开关就够了），底栏只留工作区自己的动作 |
| `api.maiDualProbe` | 输出追加 `name=逻辑助手 seg=72/88` |

刻意没改：`chatPlan()` / `wsDialogPlan()` 的宽度数学、两窗底栏顺序（chat 靠右、新对话最右；ws 靠左，各有 L2-98 / L2-109 守着）。
