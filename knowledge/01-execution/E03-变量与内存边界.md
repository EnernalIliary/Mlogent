# E03 Variables and memory boundaries

## In one sentence

Every mlog variable is an `LVar` with only **number / object / null** as observable states (plus a const flag); there are no strings, no arrays, no maps — all "complex data" is assembled from memory cells and object references.

## Rules / formulas

### 1. The three fields and four states of LVar

| Field | Type | Meaning |
|---|---|---|
| `isobj` | boolean | whether the object slot is in use |
| `objval` | Object | object value; `null` is the "null state" |
| `numval` | double | numeric value (meaningful only when `isobj=false`) |
| `constant` | boolean | whether it is a constant (set cannot write it) |

| State | Test | `bool()` | `num()` | `numOrNan()` |
|---|---|---|---|---|
| Number | `!isobj` | `abs(num) >= 1e-5` | `numval` | `numval` |
| Object | `isobj && objval!=null` | true | **1** | 1 |
| null | `isobj && objval==null` | false | **0** | **NaN** |
| Numeric NaN/Inf | `!isobj && invalid(numval)` | false | **0** | NaN |

⇒ "null equals 0" holds only for `num()`, not for `numOrNan()` / `bool()`.

### 2. Three rules on the write path

```java
// LVar.java:87-97  setnum
if(invalid(value)){ objval = null; isobj = true; }   // NaN/Inf 直接变 null
else { numval = value; isobj = false; }
```

| Rule | Code | Effect |
|---|---|---|
| NaN assignment | `setnum` :87-97 | the variable becomes a **null object**, not a NaN number |
| Numeric variable passed to set(LVar) | :110-118 | if the source numval is invalid ⇒ **0** is written |
| Constant | `constant` | `set` is silently dropped (@ipt/@unit/@links and so on) |

### 3. memory cell

| Type | Capacity | Source |
|---|---|---|
| memory-cell / memory-bank | **64 / 512** cells | content/Blocks.java:6872-6883 |
| world memory cell | **512** cells | Blocks.java:6962-6969 |
| Reading the capacity | `@memoryCapacity` | MemoryBlock.java:86 |

`read cell <address> <result>` / `write cell <address> <value>`: the address is an integer index and **out of range raises nothing**; it follows Java array semantics (an out-of-range write throws, the engine swallows the exception ⇒ it shows up as no effect; 【U】the exact behaviour needs an experiment).

### 4. Text buffers

| Buffer | Cap | Behaviour |
|---|---|---|
| `textBuffer` | **400** characters | when full, new text is **dropped outright** (LExecutor.java:1057/:1100), no error raised |
| `format` result | 400 | over-long is truncated (:1155-1156) |
| `message` block | 400 | over-long **refuses the write** (MessageBlock.java:42) |
| Chat | 150 | `Vars.maxTextLength` (unrelated to print) |

### 5. @links and the link count

`LogicBlock.updateLinks()` (:582-599) writes `@links` as the **number of valid links** (not the configured count): an invalid link name is not counted ⇒ reading `@links` as a loop bound is safe.

### 6. Cap on the number of variables

【U】Not verified. The source shows no "per-processor variable cap" constant (variables are a `Map<String,LVar>`, created on demand), but in practice memory and the `LParser` cap of 1000 lines bound it; an experiment that "creates 5000 variables with distinct names" is needed to confirm whether it OOMs.

## Measurements and counter-examples

- 【S】`sensor result cell @memoryCapacity`: memory-cell=64, memory-bank=512, world-cell=512 (`MemoryBlock.java:84-88` returns `memoryCapacity` directly; for the per-instance values see `Blocks.java:6875/6881/6967`).
- Counter-example (a boundary that does not hold): **"a memory cell can hold an object" is false**. A cell stores only a double; to store a unit/block reference you need `flag` or a variable holding the reference.
- Counter-example: **"print wraps and grows on its own" is false**. There is a hard cap of 400 characters, and print appends no newline, so an explicit newline such as `print "\n"` is required.
- 【S】Out-of-range memory: **an out-of-range read gives null (`Double.NaN`)**, **an out-of-range write is silently dropped** — the comment at `MemoryBlock.java:67-68` says `Return null when out of bounds. (instead of 0)`, and `:79` returns early when out of range. A legal address never written reads 0 (the `double[]` default). [src: MemoryBlock.java:64-81]

## Common misconceptions

1. "NaN is a value" — in mlog it is equivalent to the null state.
2. "@links is the configured link count" — it is the **valid** link count.
3. "a variable can hold a string" — print/format only produce a text stream; it never enters a variable.
