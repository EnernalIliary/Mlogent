# 03 · 交付物定义（v1 冻结版）

> 日期：2026-11-04 ｜ 决策人：项目作者（用户）｜ 状态：**已确认，冻结** —— 后续排期、验收、指标口径都以本文为准；要改必须先改本文并注明日期。

## 1. 一句话定义

**v1 的最终产物 = 一条命令生成、可直接导入 Mindustry v160.7 的"单条产线蓝图"，并附离线预测与真机实测的对照报告。**

- 工具（`mbo` CLI）是手段，**蓝图是交付物**，报告是证据。
- 范围严格限定在 **单条产线**（一个目标产物、一份边界输入清单），不是整座工厂。

## 2. 交付物清单（每次运行产出，落在 `runs/<run_id>/`）

| 文件 | 内容 | 给谁用 |
|---|---|---|
| `blueprint.msch` | 二进制蓝图，放进游戏 `schematics/` 即可用 | 游戏 |
| `blueprint.b64.txt` | 游戏内"导入蓝图"框可直接粘贴的 base64 | 人 |
| `metrics.json` | 建筑清单（方块×台数）、8 项指标、三量（blocks/tiles/footprint）、耗电、边界输入速率 | 程序/表格 |
| `report.md` | 一页人读：目标 → 预测 → 实测 → 逐项偏差与归因 → 结论（达标/未达标） | 人 |
| `trace.json` | 随机种子、搜索轨迹、剪枝理由、gamedata_id、jar_sha256、git_rev | 复现 |

> 没有 `report.md` 的运行视为未交付；没有 `trace.json` 的结果不可引用。

## 3. 冻结的验收标准

### 3.1 MVP Gate（E1）

| 项 | 标准 |
|---|---|
| 命令 | `mbo gen silicon:3/s --boundary coal,sand --canvas 24x24 --seed <s>` 单条命令跑通 |
| 产物 | 上述 5 个文件齐全，`blueprint.msch` 能被 v160.7 游戏导入（真机 `Schematics.readBase64` 成功、建筑数一致） |
| 静态合法性 | 无重叠、无越界、每台机器输入/输出端口都有连接、电力连通块数 = 1。**重叠必须由生成器自校验**：Schematics.place 是静默覆盖，不报错（docs/13 §2.7） |
| 真机产量 | 1800 tick 窗口内实测 **≥ 2.85/s**，且与离线预测的**相对误差 ≤ 5%**。产量口径 = 丢弃前 300 tick 后扫 **container tile 的 items 差分**；禁用 Groups.build（docs/13 §2.6）。电力前提：节点紧贴 consumer + 节点间显式 array config（docs/13 §2.4） |
| 稳定性 | 1800 tick 内无死锁（无机器 `eff<0.05` 且 `progress` 停滞 ≥120 tick）、电力 `satisfaction ≥ 0.98` |
| 耗时 | 端到端（含 warmup 13 s）**≤ 5 分钟** |

> **当前状态（`mbo` CLI v0.1，2026-11-05，`docs/15`）**：E1 Gate 六项**全部达成**——
> ①单命令 `python -X utf8 -m mbo gen silicon:3/s --boundary coal,sand`；
> ②5 件产物齐全（`blueprint.msch` / `blueprint.b64.txt` / `metrics.json` / `report.md` / `trace.json`）；
> ③静态合法（occupancy 重算、带子指向、输入可达、电力连通块=1）；
> ④真机 2.958/s vs 预测 3.000/s（−1.4%，判据 ≤5% 且 ≥2.85）；
> ⑤无死锁（`eff_low=0`）；⑥端到端 45.6 s（≤300 s）。
> 同一条流水线下石墨 1/s（1.367/s，+2.5%）、玻璃 4/s（4.012/s，+0.3%）也全 PASS。
> `mbo verify s3` 能从 `trace.json` 重建并**重编码出逐字节相同的 body**，即"报告里的蓝图 = 磁盘上的蓝图 = 粘贴码里的蓝图"。
> 读数口径：产量 = 丢弃前 300 tick 后扫 container/vault 的 `build.items` 差分；2×2 方块的 origin **等于**中心格（`(size-1)//2 = 0`），按"中心−1"读会读到隔壁方块、读出 0 的假失败；世界坐标需加 `ox=64-w//2`（place 以蓝图中心为锚）。

### 3.2 v1 终点（E2 之后）

| 项 | 标准 |
|---|---|
| 命令 | `mbo gen surge-alloy:0.8/s --boundary coal,sand,copper,lead,titanium` 跑通，产物同上 |
| 逻辑 | 允许使用**参数化逻辑模板槽位**（不合成新 mlog）；模板 id 与参数写入 `metrics.json` |
| 电力 | 三组统一 `power-source` 供电，`power_source=true`；电力维度只评耗电与连线质量 |
| 对比报告 | A1 手搭 / A2 语料改造 / B 全自动 / C 人机协同，13 项指标并排，含"逻辑使用情况"列 |
| 结论粒度 | 允许"MBO 只在部分维度更优"；不允许合成单一总分 |

## 4. 明确不做（v1 之外）

- GUI / 编辑器 / 游戏内 mod；
- 整座多模块工厂（供电主干、多产物协同、矿脉选址）；
- mlog 代码合成（只做模板槽位与保留）；
- 战斗、波次、地形碰撞、单位生产；
- 模组方块（只处理原版 v160.7 快照）；
- 130×130 以上蓝图（游戏硬限 128×128 / 16384 tile 内工作）。

## 6. 判定"做完了"的三个问题

1. 换台机器、只给 `runs/<id>/`，能不能复现同一张蓝图？→ 看 `trace.json`
2. 把 `blueprint.msch` 拖进游戏，产线能不能自己转起来？→ 看真机实测
3. 报告里的数字，能不能被第三方用 `mbo verify` 重跑出来？→ 看 `report.md` 的复现命令

三个都"是"，v1 就算交付；有一个"否"，改动都不算完成。
