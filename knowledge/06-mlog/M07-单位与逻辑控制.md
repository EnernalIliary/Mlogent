# M07 单位与逻辑控制

## 一句话

`ubind` 把某个单位绑到 `@unit` 上，之后所有 `ucontrol` 都作用于 `@unit`；`@unit` 只能被 ubind 写（`set @unit` 会被静默丢弃），单位死亡后自动变 null。

## 规则 / 公式

### 1. @unit 的生命周期

| 事件 | @unit 状态 | 依据 |
|---|---|---|
| 初始 | null | 未绑定 |
| `ubind <单位类型>` | 指向该类型的一个可用单位 | LExecutor.java:193 `exec.unit.setconst(...)` |
| 目标死亡/被毁 | **null**（对象位清空） | 单位失效时引擎置空 |
| `ubind <单位类型>`，场上**没有**该型单位 | **null**（不保留旧单位、也不报错） | 断言表 L2-133 |
| `ucontrol unbind` | null | 主动解绑 |
| `set @unit x` | **不变** | @unit 是 putConst（LAssembler.java:27），SetI 丢弃 |

⇒ 判断「有没有单位」要用 `jump ... equal @unit null`，不要用 `equal @unit 0`（null 与 0 在 num() 口径相等，会误判）。

### 2. ucontrol 的 21 个子命令完整参数表（LUnitControl 枚举）

源码：`Mindustry-Source/core/src/mindustry/logic/LUnitControl.java`（`:4-24` 声明 **21 项**，顺序即枚举声明序，`params` 数组就是文本参数表）。文本格式：`ucontrol <子命令> <p1> <p2> <p3> <p4> <p5>` —— 0 号 token 是 `ucontrol`、1 号是子命令，**参数从 2 号 token 起**（源码里的 p1..p5）。

| # | 子命令 | 参数（源码声明序） | 参数类型 | 语义 | 常见错误 |

**坐标口径（最常错）**：`LExecutor.java:352` `x1 = World.unconv(p1.numf())`、`y1 = World.unconv(p2.numf())`、`d1 = World.unconv(p3.numf())`，而 `World.unconv` 是 **tile → world（×8）**（`core/World.java:170-172`）⇒ **x / y / radius 全部按 tile 写**，写像素会跑偏 8 倍；`target`/`build`/`deconstruct`/`getBlock`/`within` 同理。

**生效前提**：非世界处理器要求 `state.rules.logicUnitControl`（LExecutor.java:344），`build`/`deconstruct` 另有 `logicUnitBuild`（:445）/ `logicUnitDeconstruct`（:470）；世界处理器 `privileged` 直接放行。

21 项机读版：`06-mlog/enums.json#enums.LUnitControl`；另有每条的 `params` 数组在 `06-mlog/instructions.json`。

### 3. 输出类子命令（容易写错）

- `ucontrol getBlock x y type building floor`：第 **4/5/6** 槽是输出（type/building/floor），不是输入。
- `ucontrol within x y radius result`：第 **5** 槽是输出（布尔结果），第 4 槽必须留 0。
- 源码对所有子命令**无条件**把 p1,p2,p3 转数字（LExecutor.java:352），所以「无用槽」被读也不会出错，但把输出变量写进 p1..p3 会被覆盖。

### 4. ulocate：LLocate 4 值 + 四个输出

`ulocate <locate> <flag> <enemy> <ore> <outX> <outY> <outFound> <outBuild>`（8 参）。枚举 `LLocate`（`logic/LLocate.java`:3-7）：**ore / building / spawn / damaged**。

| locate | 用到的输入 | 找什么 | 源码 |
|---|---|---|---|
| ore | 第 4 参 ore（物品常量） | 离 @unit 最近的该矿格 | LExecutor.java:247-251 |
| building | flag（BlockFlag）+ enemy 布尔 | 最近带该 flag 的方块（enemy=true 时找敌方） | LExecutor.java:252-256 |
| spawn | — | 最近的敌出生点 | LExecutor.java:257-259 |
| damaged | — | 最近的己方受损建筑 | LExecutor.java:260-264 |

输出语义（容易写错）：

- `outX`/`outY` 写的是 **tile 坐标**：`World.conv(...)`（world→tile，÷8，LExecutor.java:270-271）。
- 找不到时**只写 outFound=0**，`outX`/`outY`/`outBuild` 保持旧值（:273-276）⇒ 判断存在只能看 outFound。
- `outBuild` 只在「建筑在射程内或属于本方」时才写，否则置 null（:278-284）。
- 结果有缓存：`ai.checkTargetTimer(this)` 未到点直接回放 cache（:242、:285-290），输出会滞后，不要每 tick 当成实时值。
- 依赖 `@unit`：未绑定或单位失效时整个指令不执行（:237 判 `unitObj instanceof Unit && ai != null`），非世界处理器还要求 `logicUnitControl`（:232）。

### 5. radar / uradar：target 8 值、sort 5 值、死槽

`RadarTarget`（`logic/RadarTarget.java`:6-14）**8 个值**，每个值带一个过滤 lambda：

| target | 过滤条件（源码） |
|---|---|
| any | 恒 true |
| enemy | `team != other.team && other.team != Team.derelict`（**排除中立残骸**） |
| ally | `team == other.team` |
| player | `other.isPlayer()` |
| attacker | `other.canShoot()` |
| flying | `other.isFlying()` |
| boss | `other.isBoss()` |
| ground | `other.isGrounded()` |

`RadarSort`（`logic/RadarSort.java`:6-11）**5 个值**，排序键：

| sort | 排序键（源码） |
|---|---|
| distance | `-pos.dst2(other)`（负**平方**距离，不是 dst） |
| health | `other.health()` |
| shield | `other.shield()` |
| armor | `other.armor()` |
| maxHealth | `other.maxHealth()` |

文本格式与死槽：

| 指令 | 参数（8 个 token 的位置） | 说明 |
|---|---|---|
| radar | `radar <t1> <t2> <t3> <sort> <from> <order> <output>` | from = 处理器链接的建筑名 |
| uradar | `uradar <t1> <t2> <t3> <sort> <0> <order> <output>` | **第 5 参数是死槽**：`UnitRadarStatement` 固定 `radar="0"` 且 `buildFrom()==false`（LStatements.java:1171-1186），源码直接用 `@unit`，该槽写什么都无效 |

- 三个 target 不是「与」关系：源码只统计三槽里有没有 enemy / ally 来决定扫描范围（`enemies`/`allies`，LExecutor.java:765-766）。
- `order` 是**布尔方向**不是数量：`sortDir = sortOrder.bool() ? 1 : -1`（:752）；distance 的键取负 ⇒ `order=true` 取最近。
- 输出只有一个对象，找不到写 null（:800 之后）。
- 结果按 30 tick 缓存（建筑 `timer.get(30f)`，LExecutor.java:763；单位用 `ai.checkTargetTimer`）⇒ 缓存期内重复执行结果不变，不能当逐 tick 精确检测。 [src: LExecutor.java:763]
- radar 的 `<from>` 建筑必须是 Ranged 且同队；对特权方块还要 privileged（:755-756）。

## 实测与反例

- ✅【E】`op select` 被静默换成 noop（L1-25），所以「用 select 二选一改单位」在 v160.7 不成立。 [实测: docs/断言表.md]
- ✅【E】@velX/@velY 不存在（L2-24），读单位速度要用 @velocityX/@velocityY。
- 反例（不成立边界）：**「ubind 一次就永久持有」不成立**。单位死亡后 @unit 变 null，后续 ucontrol 全部变成空操作；正确做法是每轮循环判断 `@unit == null` 再 ubind。
- 【U】控制权丢失的精确条件（如被其他处理器抢绑、单位被玩家接管）未核实，需要双处理器抢同一单位的实验。

## 常见误解

1. 「set @unit 可以换单位」——静默丢弃，只有 ubind 有效。
2. 「ucontrol 只读用到的槽」——p1..p3 无条件求值。
3. 「getBlock 的输出在末尾两槽」——是第 4/5/6 槽三个输出。
4. 「unit flag 与 block flag 是同一个东西」——不是；block 侧是 BlockFlag 枚举，单位侧是数字 flag。
