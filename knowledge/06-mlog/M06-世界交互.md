# M06 World interaction

## In one sentence

The world processor is **the only executor that can change world state**: it can rewrite rules, spawn units, place bombs and switch buildings on and off; an ordinary processor can only read the world and modify the blocks it is linked to.

## Rules / formulas

### 1. Privilege test

`LogicBlock.java:559-562`:

```java
if(!privileged) ipt = instructionsPerTick;          // 非特权只能用自己的 ipt
if(disableWorldProcessors && privileged) return;    // 房主可一键禁用世界处理器
```

| Processor | privileged | ipt | max/tick | range |
|---|---|---|---|---|
| micro / logic / hyper | false | 2 / 8 / 25 | 40 | 80 / 176 / 336 tile |
| world processor | **true** | 8 | **1000** | unlimited |

**A multi-tile target reaches further**: the criterion is not `range` but `range + size * tilesize / 2` (`LogicBlock.java:736`
`validLink`, `tilesize = 8wu`). Point the same micro processor at a 4×4 landing pad and the real linkable distance is
`80 + 4*8/2 = 96wu = 12 tiles`, not the 10 in the table; logic 24 tiles, hyper 44 tiles. Measured boundary: a 1×1 target links
at 10 tiles, not at 11; a 2×2 target links at 10.5 tiles (assertion table L2-27).

### 2. control: modify the blocks you are linked to

`control <type> <target> <p1> <p2> <p3> <p4>`, where the type is the ControlType enum (5 values):

| Type | Effect | Parameters |
|---|---|---|
| enabled | switch the block on/off | p1 = boolean |
| config | write config (e.g. pick a factory recipe) | p1 = config object/number |
| color | write the color | p1 = color value |
| shoot | fire at a coordinate | p1,p2 = target; p3 = whether to fire |
| shootp | fire at a unit | p1 = unit; p2 = whether to fire |

**Trap**: the source **evaluates all of `p1..p4` every time** (LExecutor.java:577/584), even slots it will not use, so putting an undefined variable in an unused slot has no side effect, but putting an **expression with side effects** there still runs it.

### 3. setrule: rewrite the game rules (29 LogicRule entries)

`setrule <rule> <value> <p1> <p2> <p3> <p4>`, where the rule name is a LogicRule enum token:

| Group | Rules |
|---|---|
| waves | currentWaveTime, waveTimer, waves, wave, waveSpacing, waveSending, attackMode |
| map | enemyCoreBuildRadius, dropZoneRadius, unitCap, mapArea, lighting, canGameOver, ambientLight, solarMultiplier, dragMultiplier |
| player management | ban, unban, pauseDisabled |
| numeric multipliers | buildSpeed, unitHealth, unitBuildSpeed, unitMineSpeed, unitCost, unitDamage, blockHealth, blockDamage |
| AI | rtsMinWeight, rtsMinSquad |

Only `mapArea` reads p1..p4 (the four corners of the rectangle); the team-multiplier rules read p1; the rest read only value (LExecutor.java:1786/1812).

### 4. The 26 world processor instructions (grouped by use)

| Group | Instructions | Note |
|---|---|---|
| block read/write | getblock, setblock | **the first slot is layer**: `getblock <layer> <result> <x> <y>`, `setblock <layer> <block> <x> <y> <team> <rotation>` |
| entity spawning | spawn, bullet, explosion, effect, spawnwave | coordinates are tiles |
| rules/environment | setrule, weathersense, weatherset, message, localeprint | |
| units/players | fetch, clientdata, query, sync | fetch's FetchType has 8 entries |
| interaction | cutscene, setmarker, makemarker, playsound, playmusic | client-side presentation only |
| state | getflag, setflag, setprop | flag carries a value (a number) between processors |

`fetch <type> <result> <team> <index> <extra>`: FetchType = unit, unitCount, player, playerCount, core, coreCount, build, buildCount (8 entries).

### 4b. TileLayer: the four layers and their writability

Source `Mindustry-Source/core/src/mindustry/logic/TileLayer.java`:

```java
public enum TileLayer{
    floor,
    ore,
    block,
    building;
    public static final TileLayer[] all = values(), settable = {floor, ore, block};   // :9
}
```

| Layer | Meaning | getblock returns | setblock writable | Source |
|---|---|---|---|---|
| floor | floor (including air) | `tile.floor()` | ✅ accepts only a Floor that is not overlay/air | GetBlockI:1530 / SetBlockI:1567-1571 |
| ore | ore (overlay) | `tile.overlay()` | ✅ accepts only an OverlayFloor or air | GetBlockI:1531 / SetBlockI:1564-1566 |
| block | block | `tile.block()` | ✅ accepts a non-floor block (air clears it) | GetBlockI:1532 / SetBlockI:1572-1580 |
| building | building instance | `tile.build` | ❌ **not writable** (`settable` excludes building) | GetBlockI:1533 / SetBlockI:1582 `//building case not allowed` |

**layer sits in slot 0, not the last slot:**

| Instruction | Correct text (docs and source agree) | Wrong text (what cmd_index.json says) |
|---|---|---|
| getblock | `getblock <layer> <result> <x> <y>` | ~~`getblock <result> <x> <y> <layer>`~~ |
| setblock | `setblock <layer> <block> <x> <y> <team> <rotation>` | ~~`setblock <x> <y> <block> <team> <rotation> <layer>`~~ |

The coordinates are **integer tile numbers**: `world.tile(Mathf.round(x.numf()), Mathf.round(y.numf()))` (GetBlockI:1525 / SetBlockI:1561) — no ×8, write the tile index directly. When the target tile does not exist (out of range), getblock sets result to null (:1526-1527).

### 4c. The four one-line enums of message / cutscene / query

| Enum | All values | Semantic point | Source |
|---|---|---|---|
| MessageType (`logic/MessageType.java`) | notify / announce / toast / mission | `mission` is the only one that also runs on a headless server; the rest are discarded there and the text buffer is cleared | MessageType.java:3-7 / LExecutor.java:1906-1909 |
| CutsceneAction (`logic/CutsceneAction.java`) | pan / zoom / stop | pan reads p1,p2 (tiles, `World.unconv` ×8) and p3 speed; zoom reads only p1 (clamp); stop ends cinematic mode | CutsceneAction.java:3-6 / LExecutor.java:1328-1341 |
| QueryType (`logic/QueryType.java`) | unit / building / bullet | **bullet cannot be queried**: `queryable = {unit, building}`, and the source returns immediately for bullet (pooled object references would go stale) | QueryType.java:3-7 / LExecutor.java:1462 |
| QueryShape (`logic/QueryShape.java`) | circle / rect | circle treats width as the radius and (x,y) as the centre; rect uses width/height | QueryShape.java:3-4 / LExecutor.java:1449-1457 |

`query <type> <target team> <x> <y> <w> <h> <result>` (7 params) has two more easy mistakes:

- The coordinates are tiles, but the source goes through `numfWorld()` (×8 into world units, LExecutor.java:1449) ⇒ you may write fractional tiles.
- When `team` is an empty team such as `@derelict`, the source walks every present team (LExecutor.java:1468-1471/1488-1492).

`message <type> <duration> <outSuccess>`: the buffer content accumulates from earlier `print` calls; passing `@wait` as the third argument makes it block (counter-- + yield), otherwise outSuccess=0 means "the previous message has not faded yet, retry yourself" (LExecutor.java:1911-1924).

`cutscene` returns immediately when headless (LExecutor.java:1326) ⇒ it is a pure client-side effect; a world processor running on a server shows no change.

### 5. Budget rules for building / deconstructing

- Unit building goes through `ucontrol build` / `ucontrol deconstruct`: **one action per instruction**, and the speed ceiling is set by the processor ipt together with the `buildSpeed`/`unitBuildSpeed` rules.
- A hyper processor has ipt=25 ⇒ theoretically 25×60=1500 build calls per second, but actual building is limited by the unit's own build speed and the block's cost, so **calls ≠ completions**.
- Exactly how much build progress advances per tick is **【U】unverified**; it needs one experiment measuring "ticks to finish a single block with unitBuildSpeed=1".

## Measured facts and counter-examples

- ✅【E】`--update all` factories produce, `none` does not (assertion table L3-02); `worldTick` skips processors to avoid double execution (L3-03).
- ✅【E】a `build 160` save can only be loaded by v160 (L3-04).
- Counter-example (a boundary that does not hold): **the world processor is not omnipotent**. It cannot change the save structure, cannot bypass the `disableWorldProcessors` switch, and cannot make a logic display render on a headless server.
- Counter-example: **setrule multipliers are not retroactive**. Changing `unitDamage` only affects later damage resolution; existing health bars are not recomputed.

## Common misconceptions

1. "A world processor only has a bigger range." — it can rewrite rules and spawn entities, which an ordinary processor cannot.
2. "getblock takes the coordinates first." — the first slot is layer.
3. "control reads only the parameters it uses." — all four parameters are evaluated.
4. "setflag can store strings." — flag only has numeric semantics.
