# M02 变量与作用域

## 一句话

每个处理器有一套独立的 LExecutor 变量表；变量只有两种形态——**数字**或**对象**，而 null 不是第三种值，是「对象位为空」，且它转成数字时**是 0，不是 NaN**。

## 规则 / 公式

### 1. LVar 的真实结构（LVar.java:8-127）

| 字段 | 含义 |
|---|---|
| name / id | 变量名（含 @ 前缀）与整数槽号 |
| isobj | true = 对象形态（objval 有效），false = 数字形态（numval 有效） |
| objval (Object) | 对象；**null 表示空引用** |
| numval (double) | 数值 |
| constant | 常量位；SetI 对 constant 变量**静默丢弃赋值** |
| syncTime | 网络同步时间戳 |

**没有独立 null 类型**：null == isobj 为 true 且 objval == null。

### 2. 三种读取语义（必须背下来）

| 方法 | 数字变量 | 对象变量（非空） | null | 源码 |
|---|---|---|---|---|
| bool() | abs(numval) >= 0.00001 | true | **false** | LVar.java:52-54 |
| num() | numval（NaN/Inf→0） | 1 | **0** | LVar.java:56-58 |
| numOrNan() | numval | 1 | **NaN** | LVar.java:61-63 |

⇒ 同一个 null：bool 得 false、num 得 0、numOrNan 得 NaN。**只有 numOrNan 能区分 null 与数字 0**。

### 3. 写入语义

- setnum(v)（LVar.java:87-97）：v 为 NaN 或 ±Inf 时**不写数字，反而写成 null 对象**（objval=null; isobj=true）。⇒ set x (0/0) 得到 null，不是 NaN。
- set(LVar other)（LVar.java:110-118）：对象照抄；数字形态下若 other.numval 非法则写 0。
- 0.00001 阈值只出现在 bool()，num() 没有阈值。 [src: knowledge/VERSION.md:1]

### 4. 作用域

- **一处理器一作用域**：变量表挂在 LExecutor 上，两个处理器同名变量互不影响；链接只传对象句柄，不传变量。
- 变量名区分大小写；@ 前缀先查内建表/内容表（@copper、@conveyor 来自内容表），查不到才当普通变量。
- 变量无需声明，赋值即创建；未赋值初值按 putVar 的默认 numval=0 处理（【I】推断，未经真机核对）。

### 5. 内建变量（v159.3 源码口径：34 个只读 + 3 个特殊） [src: knowledge/VERSION.md:1]

@this @thisx @thisy @links @ipt @unit @counter @time @tick @second @minute @waveNumber @waveTime @mapw @maph @ctrlProcessor @ctrlPlayer @ctrlCommand @server @client @clientLocale @clientUnit @clientName @clientTeam @clientMobile @clientMusicPlaying @pi @e @degToRad @radToDeg @wait true false null

可写性三档（关键差异）：

| 变量 | 能否 set | 说明 | 源码 |
|---|---|---|---|
| @counter | ✅ 能 | putVar 建的非常量，这就是文档化跳转 | LAssembler.java:25 |
| @ipt | ❌ 不能 | putConst 常量，SetI 丢弃；**只能 setrate** | LExecutor.java:138 / :2018-2036 |
| @unit | ❌ 不能 | putConst(@unit, null)，SetI 丢弃；**只能 ubind** | LAssembler.java:27 |

@links = 当前**有效**链接数（LogicBlock.java:582-599 写入），不是放下的链接方块数。

### 6. 内存单元（跨 tick 存储）

| 方块 | 容量 | 读 | 写 | 源码 |
|---|---|---|---|---|
| memory-cell / memory-bank | 64 格 / 512 格 | read result cell index | write value cell index | MemoryBlock.java:41；content/Blocks.java:6872-6883 |
| world memory cell | **512 格** | 同上 | 同上 | Blocks.java:6962-6969 |

越界读返回 null（`Double.NaN`），未写过的合法地址返回 0；越界写静默丢弃（MemoryBlock.java:64-81）。变量本身也跨 tick 存活，但处理器被拆/重建会清空，内存方块不会。

## 实测与反例

- ✅【E】sensor_attrs.json 记录 @enabled/@color 是 v160.7 jar 新增（added_2026_10_25），v159.3 源码里没有 ⇒ 同一条 sensor 代码跨版本可能失效。 [src: sensor_attrs.json]
- 反例（不成立边界）：**null 等于 0 只在 num() 口径成立**。op equal 用 num() ⇒ null 与 0 判定相等；但走 numOrNan 的参数（部分 world 指令坐标）null 不等于 0。
- 反例：**set 不一定写进去**。对 @unit/@ipt 的 set 是无声失败：程序继续跑、值不变——最难查的一类 bug。
- ✅【E】op select 在 v160.7 被静默替换为 noop（断言表 L1-25）：不报错、下标不变、结果变量保持旧值。 [实测: docs/断言表.md]

## 常见误解

1. 「mlog 有 null 值」——没有；null 是对象位为空，转数字 0、转布尔 false。
2. 「NaN 可以存进变量」——setnum 把 NaN/Inf 直接转 null（LVar.java:87-97）。
3. 「@ipt 可以 set」——常量位拦住，只有 setrate 生效。
4. 「变量在处理器间共享」——不共享；共享只能靠内存单元或 read/write + 世界处理器。
