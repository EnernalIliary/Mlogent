# 109 · v0.20.1 把对话入口搬到看得见的地方

日期：2026-11-02　驱动：用户 m02850「没有看到哪里更新了」。

## 1. 取证（为什么用户看不到 v0.20.0）

- 真机确认新代码已在跑：`saves/last_log.txt` 里有 `[mai] v0.20.0 ready, 87/87 console function(s), sidecar=http://127.0.0.1:8765`
  （Mindustry pid 47768，19:52 启动），日志里没有任何 `chat dialog` 行 ⇒ **用户从来没打开过对话窗**，不是没装。
- 入口只有一个，而且够不着：`openChatDialog()` 唯一的用户入口是作业管理窗内容区顶部的 `＋ 新建对话`（`main.js` 的 `chatBar`），
  而作业管理窗只有两个调用点 —— `main.js` 作业框「查看」按钮（`openJobManager()`）与 `api.maiJobManager`。
  也就是说：**必须先投一个作业，再点作业框上的「查看」，才可能看到新功能**。
- 用户平时点的「MAI 控制面板」（`blueprintPageHook()` 里 `btns.button("MAI 控制面板", openWorkspaceDialog)`, main.js:6449）
  开的是**工作区快照**窗，底栏只有 刷新 / 撤销上次写入 / 撤销快照 / 从蓝图创建 / 关闭 —— 没有任何对话入口。
⇒ 结论：这不是渲染 bug，是**信息架构 bug**：新功能挂在了需要前置状态的窗口里。

## 2. 改法

| 位置 | 改动 |
| --- | --- |
| 蓝图页底栏（`blueprintPageHook()`） | 「MAI 控制面板」右侧新增 **「MAI 对话」**（宽 130），`try{ openChatDialog(); }catch(e3){ hint("对话窗口打不开：" + e3); }` |
| 工作区快照底栏（`openWorkspaceDialog()`） | 「从蓝图创建」之后、`关闭`之前新增 **「＋ 对话」**（高 34、`padLeft(4)`、`ellipsis(true)`），同样的 try/catch 兜底 |
| 作业管理窗 | 原「＋ 新建对话」保留 —— 三条路开的是同一个 `openChatDialog()` |

两条红线（`tests/mlogauxiliary/run_ui_smoke.py` 的 v0.20.1 组）：`btns.button("MAI 对话"`、`d.buttons.button("＋ 对话"`。
入口本身不是新状态：`CHAT_UI` 仍是单例，`d.hidden()` 统一清 `open/polling/listHost/detailHost/tf`（见 L2-107）。
