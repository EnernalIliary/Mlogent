# 110 · GTB 0.1.7：拆除「刚动手」就判，还原的是原方块（不再是 @air）

> 用户 m10997：「你放置的建筑不是原建筑，而是@air，而且应该检测拆除行为，而不是等完全拆除再拉黑」

## §1 为什么会放回 @air

| 事实 | 位置 |
|---|---|
| 旧实现挂的是「拆完」事件 `BlockBuildEndEvent(breaking = true)`。到这个时刻，tile 上的方块早就不是原来那个了 | `Mindustry-Source/core/src/mindustry/world/blocks/ConstructBlock.java:59-69`（`deconstructFinish` 先 fire 结束事件、再 `tile.remove()`） |
| 拆除一开始（`beginBreak`）就把 tile 换成 `ConstructBlock`，原方块被挪进 `ConstructBuild.previous` | `Mindustry-Source/core/src/mindustry/world/Build.java:39-58`（`:39` 取 previous、`:56` `tile.setBlock(sub, ...)`、`:58` `build.setDeconstruct(previous)`） |
| `ConstructBuild.previous` 的默认值是 `Blocks.air` | `Mindustry-Source/core/src/mindustry/world/blocks/ConstructBlock.java:167` |
| 于是旧代码 `tile.block()` 读到的是构造块、`setBlock` 回去等于放了个 `previous = air` 的空壳 ⇒ 画面上就是一片空白 | 旧 `restoreTile` 用 `tileSnapshot(t)` |
| 拆除行为其实在「刚开始」就有事件 | `Mindustry-Source/core/src/mindustry/world/Build.java:66` `Events.fire(new BlockBuildBeginEvent(tile, team, unit, true))` |

## §2 改法

| 用户要的 | 改法 |
|---|---|
| 拆出来的要还原成原建筑 | 新增 `breakSnapshot(t, cb)`：`block = cb.previous`、旧建筑 `= cb.prevBuild.get(0)`（team / rotation / `config()` / `healthf()` / 物品 / 液体都从旧建筑取）；`previous` 是 air/null 就当没取到 |
| 不要等完全拆除 | 新增 `onBuildBegin(e)` + `firstBreakBegin(e, p)`，挂 `ET.BlockBuildBeginEvent`；判中就直接把 ConstructBlock 换回原方块 = 当场撤销这次拆除 |
| 兜底 | `firstBreakCheck` 遇到 ConstructBlock 直接返回；`onBuildEnd` 的 breaking 分支先查 `GTB_BREAK[key]`（begin 时没放成功的），下一帧用快照放回 |
| 联机也要看得见 | 新增 `placeBlock(t, snap)`：`net.active()` 时先 `t.setNet(block, team, rot)`（`Call.setTile` 才会同步给客户端），`t.block()` 没变就退回 `t.setBlock(...)` |

### 2.1 快照从构造块里取

```js
function breakSnapshot(t, cb) {
    var snap = { block: null, team: null, rot: 0, conf: null, hp: 1, items: null, liquids: null };
    snap.block = cb.previous;                       // 原方块（air 当没取到）
    var old = cb.prevBuild.size > 0 ? cb.prevBuild.get(0) : null;  // 还带着库存的旧建筑
    if (old != null) { snap.team = old.team; snap.rot = old.rotation; snap.conf = old.config(); ... }
}
```

### 2.2 判定时机

- `onBuildBegin(e)`：非权威 / 编辑器 / `e.breaking !== true` / 总开关关 → 直接 return；否则 `firstBreakBegin(e, p)`。
- `firstBreakBegin`：`firstPending` → 行为开关 `bh.firstBreak` → 时间窗 `firstRecent(p, cfg0.thInteractWindow)` → 管理员/非目标跳过 → `isConstructBlock(cb)` → `breakSnapshot` → `punish` + `GTB_BREAK[key]` → `restoreTile(t, snap, true)`。
- `restoreTile(t, snap, allowConstruct)`：`allowConstruct === true` 且当前正是 ConstructBlock 时才允许覆盖，其余情况仍只在空位放。

## §5 真机验

1. 重启游戏（模组装好才加载）→ 用普通账号进服，进服后**立刻**拆一块建筑：应当当场被拉黑 + 全服通告 + 方块立刻回到原位（不是空白、不是 @air）。
2. 拆一块带物品的容器 / 带冷冻液的钍堆：放回后里面的东西还在。
3. 进服后先做别的事（放一块方块）再拆：不判（时间窗与「没做过别的事」两条都要满足）。
4. 联机别人看：主机之外的人也能看见方块被放回（`placeBlock` 走 `setNet`）。
