# 23 · 单源单汇的四台压机线（先把物品流向定下来）

> 目标来自用户：**只许一个 `item-source`、一个 `item-void`**，跑 4 台 `graphite-press`。
> 本文件先定"物品往哪走"，再谈能不能更快。

## 0. 一条硬上限：单源最多喂出 2.45/s

| 量 | 值 | 来源 |
|---|---|---|
| 单格物流上限 | 4.9 items/s | `spikes/gen/belt_probe.py` 实测 |
| 4 台压机需煤 | 4 × 2 / 1.5 = **5.3333/s** | `graphite-press` 90 帧、2 coal → 1 graphite |
| 一个源能供的煤 | 4.9/s | 源只有一个出口，只能进一条带子 |
| ⇒ 单源能支撑的石墨 | 4.9 / 2 = **2.45/s** | 4 台 × 0.6667 = 2.6667 > 2.45 |

**结论：单源单汇下，4 台压机永远吃不饱**（缺口 8%）。2.45/s 是这套约束的天花板，不是搜索没找到。

## 1. 最终形状（`runs/q-tap1`，2 端口 / 2 开口 / 38 工厂格）

```
    00000000001111
    01234567890123
  0 S>+>>+>>+>>+
  1   MM MM MM MM
  2   MM MM MM MM
  3   >>>>>>>>>>nx
```

* 行 0 是煤的主干：源 → 带子 → **反溢门** → 带子 → 反溢门 ……（门正面朝东继续走主干）
* 门的两侧优先：南侧正对压机，所以**压机先吃，吃饱了煤才继续往东**（这是反溢门在本作里的正确用法）
* 压机占行 1–2，产物往南推到行 3 的输出带子，一路向东经路由器汇进唯一的黑洞
* 端口的 `item-source`(0,0) 与 `item-void`(13,3) 都在工厂矩形 `[1..12]×[0..3]` 之外 ⇒ 合规

| 项 | 值 |
|---|---|
| 端口 / 开口 | 2 / 2 |
| 方块数 / 工厂格 / 占地 | 28 / 38 / 14×4 |
| 模型预测 | **2.4500/s**（bottleneck=input，煤 4.9） |
| 真机（1800 tick） | **1.9236/s**，eff_avg=0.71，无死锁 |
| 达成率 | 实测 / 上限 = **78.5%** |

## 2. 三版流向的实测对比（都是 1 源 1 汇、4 台压机）

| 版本 | 形状要点 | 真机 | 与 2.45 之比 | 死因 |
|---|---|---|---|---|
| `runs/q-single` | 主干 = 带子＋**路由器**串联，门挂在下游 | 1.2849/s | 52% | 路由器只把一部分给门，压机侧长期半饥 |
| `runs/q-tap4` | 门串在带子线上，每台压机各一个黑洞（端口 5，仅作诊断） | 1.6856/s | 69% | 输出侧无合流，压机被产物回压 |
| **`runs/q-tap1`** | 门串在带子线上 + 输出合并到一个黑洞 | **1.9236/s** | **78.5%** | 干线上的带子贴着压机，压机偶尔把石墨推回干线 |

## 3. 拆分探针：掉速到底掉在哪

| 探针 | 内容 | 实测 | 说明 |
|---|---|---|---|
| `spikes/gen/flow_trunk.py` | 源 → 带子 → 容器（无机器） | 4.61/s | 基线 |
| 同上 `routers` | 源 → 带子 → 3 台路由器 → 容器 | 4.69/s | **路由器本身不劈流量** |
| 同上 `gate` | 源 → 带子 → 单个反溢门 → 容器 | 4.90/s | 单个门不丢料 |
| `spikes/gen/flow_gates4.py` | 源 → 主干 → 4 个门 → 4 个容器 | **4.93/s** | **输入网络本身能送满 4.9** |
| `spikes/gen/flow_mp2.py` | 源 → 带子 → 路由器 → 门 → 单台压机 | 0.676/s | 单台能跑满（0.6667） |
| `spikes/gen/flow_probe.py --mode output` | 4 个源 + 输出合并 → 唯一黑洞 | **2.5718/s** | 输出合流本身可以，但**比 2.6667 低 3.6%** |
| 同上 `--mode input` | 单源主干 + 4 台压机各接黑洞 | 1.0708/s | 输入侧接到机器后就掉一半 |

**结论**：主干、门、路由器、输出合流单独测都合格；一旦"门→压机"和"输出去合流"**同时接在 2×2 压机的四邻上**，压机的推料会把干线带子和输出带子当成出口，实测就掉到 78%。这是物流模型（纯容量模型）目前**没有建模**的部分：模型把压机的每个邻格都当成理想汇点。

## 4. 复现

```powershell
cd MBO
python -X utf8 spikes/gen/flow_single2.py --dry                    # 只看形状与模型预测
python -X utf8 spikes/gen/flow_single2.py --sink merged --out q-tap1   # 真机，约 46 s
python -X utf8 spikes/gen/flow_trunk.py                            # 干线吞吐三连测
python -X utf8 spikes/gen/flow_probe.py --mode output --out p-out   # 输出合流上限
python -X utf8 -m mbo preview q-tap1 --scale 14
```
