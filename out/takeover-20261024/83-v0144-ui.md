## 1. 为什么框角按钮要重做

上一版（v0.14.2）的「查看 / 取消」是用即时绘制画的（`Fill.rect` + `Lines.rect` + `font.draw`），不是原版控件。原因有两条：它在世界层的框选区 overlay 上，用 `Fill`/`Lines` 直接画最省事；而且 v0.12.6 被 arc 的字体 autoscale 在 `font.draw` 上错位坑过一次。

代价是：字号随 camerascale 变化、没有悬停反馈、命中判定要自己算，而且和原版任何 UI 都不一致。

正确做法是 HUD stage 上放自己的 `Table` + 原版 `TextButton`：arc 负责排版、缩放、命中、悬停，我只负责每帧把它的位置对上框的右下角。

## 2. 做了什么

### 2.1 框角操作区 = hudGroup 上的原版控件（A）

`Vars.ui.hudGroup` 是 `WidgetGroup`（`UI.java:53/192/239-244`，`setFillParent(true)`、`touchable = Touchable.childrenOnly`）。往里加一张自己的表：

```js
var t = new Packages.arc.scene.ui.layout.Table();
var lbl = new Packages.arc.scene.ui.Label("", new Packages.arc.scene.ui.Label.LabelStyle(
    Packages.mindustry.ui.Fonts.outline, Pal.accent));
t.add(lbl).right().padBottom(Scl.scl(3)).row();
btns.button("查看", Packages.mindustry.ui.Styles.defaultt, ...).size(Scl.scl(84), Scl.scl(40));
```

- `Table.button(String, TextButtonStyle, Runnable)`：Table.java:452
- `Label.LabelStyle(Font, Color)`：Label.java:22-26
- `Scl.scl(float)`：Scl.java:26
- 位置：`Camera.project(worldX, worldY)`（Camera.java:84-94）给的是屏幕像素，原点左下、y 向上，与 arc scene 同一套；再用 `graphics/scene` 宽高比纠正一次。

**降级**：`jobWidgetBuild()` 拿不到 `hudGroup` 或建表抛异常时返回 false，`drawSelection()` 立刻退回即时绘制那套（`drawJobButtons`）。`jobButtonsClick()` 在控件接管时 `return false`，否则 arc 的命中和我自己的世界坐标命中会双触发（点一次按钮关两次框）。

> 未查证：Arc-Source 里没有 `Stage.java`，所以「scene 坐标是否等于像素」无法从源码确认 —— 用宽高比兜底，真机还要目测位置是否贴住框角。

### 2.2 sidecar 随游戏启动（B）

脚本尾部与 `ClientLoadEvent` 各 `ensureSidecar(true)` 一次，都是幂等的（`SIDE.state === "starting"` 直接返回）。不用等 F3。

### 2.3 模型档随 sidecar 自动挂载（K）

`llmAutoSync()`：sidecar 每次重启都会把内存里的模型档忘掉（配置只在进程里）。所以只要 `sidecarTick()` 或 `ensureSidecar()` 探到 200，就把 `Core.settings` 里的地址/密钥/模型推一遍。60 s 内不重复推（每帧的 health 回调会反复命中）。

### 2.4 删模板档（D）

模组侧删掉：`openPanel`/`panelShown`/`togglePanel`（模板面板）、`plan`/`renderPlan`（`POST /plan`）、`compose`（`POST /compose`）、AI 面板的「直接生成」按钮、探针 `maiPanel`/`maiCompose`/`maiApply`、`llmUseTemplate()`。`llmState` 默认 `kind: "none"`，`llmText()` 说「未配置模型」。

sidecar 侧：`jobqueue.unconfigured_provider` 成为 `Queue` 默认 —— 返回 `{'error': '未配置模型：…', 'fatal': True}`，`_run` 见到 `fatal` 只跑一次就 `failed`（重试只会得到同一句话）。`apply_llm(kind=template)` 现在切到「未配置模型」。`--jobs-provider` 默认 `none`。

**保留**：`TEMPLATES`、`/compose`、`/plan`、`--jobs-provider template` 全留着 —— 写路径测试要靠它们验真实 v160.7 处理器，只是产品路径不再走。

### 2.5 设置页重排（C/E/F）

新顺序：大模型 → 聊天播报 → 快捷动作 → 本地快检 → 说明 → 运行环境（永远最后）。sidecar 段整段删掉（地址固定本机 8765、随游戏自启），「复制诊断」进快捷动作。本地快检加一句「规则与 sidecar 的检查器同源，只在本机跑」。

### 2.6 密钥默认遮（G）

原来只调了 `setPasswordMode(true)` 却没有 `setPasswordCharacter` —— `Fonts.def` 里没有 U+25CF 的 bullet 字形，等于没遮。补 `setPasswordCharacter('*')`，再加一个「显示密钥」按钮按需看明文。

### 2.7 聊天播报开关（H）

`CHAT_SEND_KEY = "mlogauxiliary-chat-send"`，`Core.settings.getBool(..., false)`，默认关。`chatSay` 的判据从 `if(netActive())` 改成 `if(netActive() && chatSendOn())`；关掉时仍走 `hint`（本机淡出提示），状态不会因为「不想进聊天框」就消失。

### 2.8 投递前先查模型

`jobSubmit` 里没配模型直接回「未配置模型：先在「设置 → Mlog辅助 → 大模型」填地址、密钥、模型，再点「启用模型档」」，不投一个注定失败的作业。
