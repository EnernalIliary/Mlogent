## 2 radar / uradar 槽位（L2-17）

7 个槽、第 6 槽是排序**方向**不是数量、整条语句只输出一个结果、radar 的 30 tick 缓存：

## 3 文本 token 序 = Java 字段声明序（L1-27）

`getblock` 真序是 `layer result x y`，写成 `<result> <x> <y> <layer>` 是「数目对、顺序错」→ 静默错位：

- [M01-执行模型总览](../knowledge/06-mlog/M01-执行模型总览.md)
- [E02-指令语义陷阱](../knowledge/01-execution/E02-指令语义陷阱.md)

## 4 status：第一槽是布尔（L2-22 L1-23 L1-24）

`status <true|false> <effect> <unit> <duration>`；`false` 才是施加、`true` 是清除；
写 `apply` / `clear` 会被当成未定义变量（= false）⇒ 两条都在施加；效果名拼错静默无效：

- [E02-指令语义陷阱](../knowledge/01-execution/E02-指令语义陷阱.md)
- [CHEAT](../knowledge/08-evidence/CHEAT.md)

## 5 控制租约 600 tick（L2-25 L2-15）

单位最后一次 `ucontrol` 后 600 tick（10 s）自动脱离；炮台 `control shoot` 同样约 600 tick 停火
——「开局发一条就完事」的程序会自己失效：

- [P07 单位多控](../knowledge/07-patterns/P07-unit-multicontrol.md)

## 6 链接半径与链接名（L2-12 L2-13 L2-130）

规则只有一条：**链接名 = 方块名最后一段 + 1 基序号**（`core-shard` → `shard1`，不是 `core1`），
前缀写错会在读档时被静默重算，代码里的旧名从此恒 null（写 `sw1` 的那次事故，m00622）。

- [E05-链接与@常量](../knowledge/01-execution/E05-链接与@常量.md)（解析、基名表、读档重命名）
- [M06-世界交互](../knowledge/06-mlog/M06-世界交互.md)（多格目标的余量 `range + size*8/2`）

## 7 预算是额度池，wait 的粒度是 1 tick（L1-28 L1-29 L1-30 L1-31）

跨 tick 累积、上限 5×ipt、超出削顶丢弃；`wait 0.001` 与 `wait 0.0166` 等价；`wait 0` 不省空转；
`wait 0.08` 是「攒满 5 tick」专用值：

- [E01-执行模型与预算](../knowledge/01-execution/E01-执行模型与预算.md)
- [M03-控制流](../knowledge/06-mlog/M03-控制流.md)、[M08-性能与限制](../knowledge/06-mlog/M08-性能与限制.md)

## 8 `equal` / `notEqual` 里的 null 就是 0（L1-07 L1-32）

`equal X 0` 在 X 为 null 时判真；`equal` 只在两侧都是对象时才比对象；要分辨 null 与 0 用
`strictEqual`：

- [E03-变量与内存边界](../knowledge/01-execution/E03-变量与内存边界.md)
- [CHEAT](../knowledge/08-evidence/CHEAT.md)

## 9 世界处理器与跨台部署（L1-33 L1-34 L1-35 L1-36 L2-131）

默认 `ipt=8`、`setrate 1000` ⇒ 60,000 条/s、`setrate` 是特权指令、界面上的 `ipt =` 只是提示文本、
单台编译后最多 1000 条、`write` 后对端 ≤1 tick 可见：

- [M06-世界交互](../knowledge/06-mlog/M06-世界交互.md)
- [M08-性能与限制](../knowledge/06-mlog/M08-性能与限制.md)、[P06 性能](../knowledge/07-patterns/P06-performance.md)

## 10 闭环、一次性块、跨台握手（L1-37 L1-38 L1-39）

`end` 不是停机（等价跳回第 0 条）、一次性块必须自己驻留、`op rand` 只有 1 个操作数；
跨台握手要用**只增相位号 + 完成计数**，不能用 `0 → 1` 边沿（写立刻可见，对方在任意指令点采样就会
跳过中间态 ⇒ 互等死锁）：

- [M01-执行模型总览](../knowledge/06-mlog/M01-执行模型总览.md)
- [P03-通信与总线](../knowledge/07-patterns/P03-comm-bus.md)（无锁竞态三条 + 五行握手模板）
- [anti-patterns](../knowledge/08-evidence/anti-patterns.md)、[P02 状态机](../knowledge/07-patterns/P02-state-machine.md)

## 11 曾经只有 docs 有的实测（现已迁入 knowledge）

- **链接名会被读档改名**：写 `sw1` 存档再读，名字变 `switch1`，代码恒 null（m00622 事故，L2-130）→ `E05` 的「链接名的合法形式」。
- **多格建筑的链接余量**：micro 对 4×4 台 12 格、logic 24 格、hyper 44 格（L2-27）→ `M06` 的「多格目标吃得更多」。
- **相位号握手**：五行模板与死锁机理（L1-39）→ `P03` 的「边沿会丢，序号不会」。

这一节保留只为「旧链接 / 旧笔记能找到归属」，事实本身以 knowledge 为准。
