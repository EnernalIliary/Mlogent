# Grief to Ban 0.1.2：更新检查在限流下也能用

日期：2026-11-11。前一份：104-gtb011.md。

## 1 为什么还有这一版

0.1.1 刚发完就发现一件事：模组的更新检查走 `https://api.github.com/repos/<owner>/<repo>/releases/latest`，
而这台机器的 IP 打这个接口直接 `HTTP 403 rate limit exceeded`（匿名额度按 IP 算，共用 IP 很容易用光）。
也就是说「自动更新」在发布后仍然可能是哑的，只是日志里多一条失败。

## 2 改法

- `parseHjsonVersion(text)`（GriefToBan/scripts/main.js，插在 checkUpdate 之前）：从 mod.hjson 文本里
  找以 `version` 开头的行、取引号里的值。**不用正则字面量**（v160.7 的 Rhino 在构造期会对某些正则 codeBug，
  JS 的 try/catch 抓不住 —— 这条坑在 MAI 里已经踩过，断言表 L2-118）。
- `fetchRawVersion(tail, finish)`：读 `https://raw.githubusercontent.com/<owner>/<repo>/main/GriefToBan/mod.hjson`。
  raw.githubusercontent 走 CDN，没有按 IP 限流。
- `checkUpdate(cb)`：API 成功走原路；API 失败（含 403、DNS、超时）先 `dbg("update: api failed ...") `，
  然后退到 raw 版本号；两条都失败才回调 `{ ok:false }`，不刷屏、不报错。
- 自检加两条：`parseHjsonVersion('name: "x"\nversion: "0.1.2"\nminGameVersion: "146"')` 得 "0.1.2"；
  `parseHjsonVersion('minGameVersion: "146"')` 得空串（不会被 minGameVersion 误命中）。

## 5 已知限制

1. raw 回退读的是 **main 上的版本号**，不是 release 上的；如果有人往 main 推了没发版的提交，会提前提示「有新版本」。
2. 两条都失败时不提示（日志里有 `update: ...`），这是刻意的：宁可静默，也不要在聊天栏刷错误。
3. API 通了但仓库没有任何 release 时，GitHub 返回 404，此时同样走 raw 回退，于是会拿 main 的版本号 —— 对首个版本之前是有意义的，
   但读到的就是「当前版本」，不会误报。

## 7 发布页 Contributors 的两个脏名字（2026-11-11）

发布页右侧 Contributors 盒子出现过两个不该有的名字，成因是两件独立的事：

1. **「this」= 正文里的 @提及**。release BODY 写了「放置自复制逻辑（ucontrol build ... @this）」，GitHub 把 `@this` 解析成对 /users/this（Sajith Ariyarathna）的提及并列进 Contributors。
   改法：PATCH release body，把 @this 改写成「ucontrol build 出来的处理器把 configure 指向自己」；同时把 0.1.1 的 zip 名换成版本变量。改完重新抓页面，盒子消失（`users: []`）。
2. **「Ilia R.」= 提交邮箱映射到了另一个账号**。旧提交 author 用的是 `iliary@users.noreply.github.com`，这个 noreply 邮箱属于账号 `iliary`（显示名 Ilia R.），不是 `EnernalIliary`。
   改法：在 `out/_publish/gtb-clone` 里 `git checkout --orphan clean` 重做单一提交，author/committer 都用 `iliary <iliary@outlook.com>`（这个邮箱在 GitHub 上映射到 `EnernalIliary`，与 MAI-MlogAuxIliary 仓的 30 个提交一致），再 force push。新提交 `d346f3e`。
   远端随之清理：删掉旧 release v0.1.1/v0.1.2、删掉旧 tag，重建 `refs/tags/v0.1.2` → d346f3e，再重发 Release（两资产同名同大小）。

验证（API）：`/repos/.../commits/main` 的 `author.login` = **EnernalIliary**；`/stats/contributors` = `[('EnernalIliary', 1)]`；
`/graphs/contributors` 页面只链接 EnernalIliary；repo 首页、release 页 HTML 里 `Ilia R.` / `%s` 均为 0 次。

遗留：`GET /repos/.../contributors` 这个 REST 端点仍在返回缓存的 `[('iliary', 2)]`（GitHub 侧缓存，统计图已重算为 1），
为此另推了一个空提交 `cd7e1c9`（同一作者，只为碰 head 触发重算，无内容改动）；若浏览器里仍看到旧名字，是页面缓存，硬刷新即可。

脚本：`out/_gtb_fix_body.py`（重写 body）、`out/_gtb_reset_remote.py`（删旧 release/tag + 建新 tag）、`out/_gtb_verify_final.py`（核对 main/tag/release）、`out/_gtb_who.py`（邮箱→login 映射）、`out/_gtb_poll_contrib.py`（轮询 contributors 缓存）。
