## 1. bug1：取消框选后，框角控件留在屏幕上

**表现**：点框角「取消」把选框关掉后，右下角那排按钮（状态文字 + 取消 + 查看 + 续聊）不消失。

**根因**：两条路径都只清了数据、没摘控件。

- `drawSelection()` 在框已经没了时走早退分支 `if(r === null){ jobBadge = null; return; }` —— 它负责
  重建/隐藏控件，早退就永远不会调到 `jobWidgetHide()`；
- `closeJobBox(why)` 只把 `jobBox`、`jobBadge` 置 null。

而框角控件从 v0.14.4 起是挂在 `ui.hudGroup` 上的**原版控件**（`jobWidgetBuild()`），不是每帧重画的，
所以只要没人主动 `remove()`，它就一直挂在 HUD 上。

**修法**（`out/_v152_main.py`，六处，`node --check` 0）：

- `jobWidgetCancel()` 末尾、`jobButtonsClick()` 的取消分支末尾各补 `jobWidgetHide();`；
- `drawSelection()` 早退分支改成 `if(r === null){ jobBadge = null; jobWidgetHide(); return; }`。

**验法**：`run_ui_smoke.py` 的 `MAIJOBBOXCLOSE`/`MAIJOBBOX4` 仍 pass；真机上点「取消」「右键关」「关闭框选框」
三条路径都能让控件消失。

## 2. bug3：聊天播报要发成真消息，格式不能省尖括号

**原来的问题**：`chatSay()` 最终只是 `hint()`（`Vars.ui.showInfoFade`），单机自己能看见，联机里对方看不见；
而且格式被简化成了 `Generating(12,34):…`。

**修法**：

- `chatLine()` 输出 `<MAI:logic:><状态>(x,y):详情`，状态词仍是 Generating / Done / Rejected / Failed / Cancelled；
- `chatPretty()` 过 `Packages.mindustry.core.UI.formatIcons()`，`:logic:` 由游戏换成逻辑图标字符
  （这是原版顿号替换表里的写法，不是 `[logic]`）；
- `chatSay()` 在 `chatSendOn() && netActive()` 时直接 `Packages.mindustry.gen.Call.sendChatMessage(s)`，
  否则退回 `hint`（单机没有聊天框）。

**依据**：`Mindustry-Source/core/src/mindustry/ui/fragments/ChatFragment.java:221-237` —— 原版
`sendMessage()` 也是先 `UI.formatIcons(text)` 再 `Call.sendChatMessage`，`addMessage()` 只往本地列表写。
所以我们走同一条路：客机发出去，服务端广播，所有人看到的是同一条消息；主机与客机行为一致。

**验法**：`run_ui_smoke.py` 的 `MAICHAT` 断言格式串 `<MAI:logic:><`、`formatIcons`、`sendChatMessage` 三处红线。

## 3. bug2：样板太少 —— 8 条已验证样例，每次挑 3 条

**原来**：`build_prompt()` 只给一条骨架（`loop:` / `sensor` / `jump loop always`），模型写稍复杂的东西就
自己瞎猜 `jump` 目标、瞎引用链接名。

**现在**（`tools/mlogprovider.py`）：

- `EXAMPLES`：8 条，覆盖阈值计数、周期触发、开关方块、炮塔自动开火、内存读写、消息板、二选一分支、波次计数；
  每条带 `title`（给模型看的说明）、`keys`（中文关键词，用于挑选）、`links`（需要的链接名）、`code`；
- 全部先过 `mlogcheck.analyse()`：`err=0 warn=0`（不过检查的样例绝不给模型）；
- `_examples_for(desc, limit=3)`：按 `keys` 命中数打分，取前 3；
- `build_prompt()` 用 `Program shapes -- each one below passes the analyzer; adapt one:` 开头，逐条给标题 + 代码。

**为什么是 8 条、每次 3 条**：4 条覆盖不到「分支 + 循环 + 传感器」的组合；16 条以上提示词塞不下、
且同类模板重复没有新信息。8 条 × 取 3 条（每条 8–12 行）是覆盖面与 token 的折中。

**验法**：`tests/logicd/run_logicd_tests.py` 的 `diag` 5→7 checks（样板 ≥8、每条 analyse 干净、
`_examples_for('给炮塔加上自动射击敌人')` 首条是炮塔样板、提示词含该样板标题、样本数 ≤3）。
