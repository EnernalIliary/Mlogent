# 项目结构与数据流

本文说明 AtomicStates 工作区的主要组成、常用数据流和维护边界。它是导航文档；命令参数与完整行为以各目录 README 和 `--help` 输出为准。

## 项目全貌

```text
用户的 mlog / 蓝图 / 存档
          │
          ├── tools/mlog.py ── 解析、检查、IR/值域分析、蓝图读写
          ├── tools/mlogsim.py ── 调用 Mindustry 真执行器进行运行期验证
          ├── tools/logicd.py ── 为游戏内 MlogAuxiliary 提供本地 sidecar
          └── tools/kb.py ── 从文档与源码构建本地检索索引

规则与事实 ── rules/*.json、tools/*semantics*.json、data/game/
          │
          ├── tests/ ── 固定样例、规则覆盖、运行期与模组契约校验
          └── gate.py ── 汇总门禁

相关产品/项目：MlogAuxiliary、GriefToBan、MBO、ratio-calc、技能与 Agent 配置
本地资料与生成物：knowledge/、docs/、Logic/、out/、saves/（dist/ 是发布导出，按需由脚本重建）
```

## 主工具链

| 路径 | 职责 | 主要输入/输出 |
|---|---|---|
| `tools/mlog.py` | 日常统一命令入口，调度解析、静态检查、分析、蓝图生成与查询 | `.mlog`、`.msch`、存档；输出报告或蓝图 |
| `tools/mlogcheck.py` | 对单个处理器逻辑做静态检查 | 指令列表、规则/语义数据；输出 findings |
| `tools/mlogir.py`、`mlogval.py`、`mlogcross.py` | 控制流、值域和跨处理器分析 | 解析后的程序/蓝图信息；输出分析结果 |
| `tools/msch.py`、`mschgen.py`、`mlogpack.py` | 蓝图与逻辑配置的读写、生成和打包 | `.msch`、逻辑文本；输出蓝图或配置数据 |
| `tools/mlogsim.py` | 驱动 Mindustry server jar 执行逻辑 | 逻辑或场景；输出 trace、断言结果或存档 |
| `tools/logicd.py` | 提供本机 HTTP sidecar，供游戏模组调用 | 模组请求；输出生成的逻辑、检查结果和配置载荷 |
| `tools/kb.py` | 构建与查询本地文档/代码索引 | 仓库资料；索引写入 `out/_kb/` |
| `gate.py` | 调度轻量和完整验证步骤 | 调用各测试脚本；汇总 PASS/WARN/SKIP/FAIL |

`tools/` 同时包含核心模块、数据表、维护脚本和语料工具。不要仅凭文件位于该目录就假定它是运行时依赖；查看对应入口的导入关系及 `tools/README.md`。

## 规则、语义数据与测试

- `rules/*.json` 保存检查规则的声明、严重度、证据和匹配条件。`tools/rule_ids.py` 将分析器 findings 关联到稳定规则 ID。
- `tools/instr_semantics.json` 等数据文件记录指令签名和参数语义，并被检查器、文档校验或游戏内快检生成流程使用。
- `data/game/` 保存游戏内容事实数据；`tools/` 中若干 JSON 是其面向工具的索引或派生表。
- `tests/cases/` 与 `tests/expected.json` 固定静态分析等行为；`tests/ruleids/` 检查规则是否真正命中样例；`tests/shapes/` 检查检查器对语句形状变化的健壮性。
- `tests/probes/`、`tests/logicd/`、`tests/mlogauxiliary/` 和 `tests/grief-to-ban/` 覆盖真执行器、sidecar 与游戏模组边界。部分用例需要本机 JRE、游戏 jar 或外部语料。
- `gate.py` 是汇总入口；`README.md` 记录默认门禁和 `--full` 的差异、环境依赖及跳过规则。

## 工具副本与发布

当前测试套件从 `mindustry-blueprint/tools/` 导入分析器副本，而主要开发源位于根目录 `tools/`。`gate.py` 的 `mirror` 步骤通过 `tools/sync_mlogagent.py` 检查副本一致性。修改核心工具后，应按 README 的同步流程更新副本，再运行相应校验；否则测试拒绝运行或可能测到陈旧实现。

`.dsh/skills/`、`mindustry-blueprint/` 和 `dsh-preset-mlog/` 面向技能/Agent 使用与分发；`dist/` 是可重建的发布导出（`tools/dev/_build_public_export.py` 生成，默认不入库、当前未检出）。它们与根目录工具共享知识，但不等同于唯一源码目录。

## 相关项目

这些都是**同级独立项目**（与本仓库同在一个父目录下，各自独立），不在本仓库内；本仓库只保留调用约定与必要的入口文档。

| 路径 | 与主工具链的关系 |
|---|---|
| `../MlogAuxiliary/` | Mindustry 游戏内辅助模组；通过 `tools/logicd.py` 获得本地生成/检查能力 |
| `../GriefToBan/` | 独立的反破坏模组，有自己的脚本与测试 |
| `../MBO/` | 蓝图生成、搜索、优化和真机验证项目 |
| `../ratio-calc/` | 配方配比计算网页；与 MBO 规则有共享背景 |
| `../DP-CameraUnbind/`、`../DP-AdjutantDebug/`、`../DP-AdjutantPlugin/` | 相关的反编译/调试插件 |

| 仓库内路径 | 说明 |
|---|---|
| `Logic/`、`logic-corpus/` | 个人逻辑示例与外部/本地语料，不是核心工具实现 |
| `Arc-Source/`、`Mindustry-Source/` | 上游源码工作区（各自带 `.git`，本仓库不跟踪） |

游戏素材（`assetsraw`，盘上目录名为 `TextureMDT`）同样已经拆到同级目录：`knowledge/tools/gen_name_docs.py` 会依次找 `$MLOG_ASSETS`、本仓库下的 `assetsraw/`、同级 `TextureMDT/`。

## 本地资料和产物

- `knowledge/` 是本地知识库内容与生成工具；`tools/kb.py` 的 SQLite 索引、模型和依赖位于 `out/` 下的本机目录。
- `docs/` 放维护说明、设计记录、验证证据和速查资料。
- `out/` 混合运行产物、场景、基线、临时探测脚本和日志；其中并非所有内容都可安全删除。清理前应先按 README、`.gitignore` 和具体产物来源确认是否可重建。
- `saves/` 保存游戏存档及相关工具资料；`dist/` 是发布导出目录，由 `tools/dev/_build_public_export.py` 生成，默认不入库。

## 常见改动路径

| 任务 | 主要位置 | 后续校验入口 |
|---|---|---|
| 改静态检查行为 | `tools/mlogcheck.py`、相关语义数据、`rules/` | `tests/run_tests.py`、`tests/ruleids/`、`gate.py` |
| 增加或调整规则 | `rules/`、`tests/cases/`、覆盖清单 | `tools/rule_capture.py lint`、`tests/ruleids/` |
| 改蓝图读写或分析 | `tools/msch*.py`、`tools/mlog*.py` | `tests/` 中相关 golden、自检或蓝图验证 |
| 改执行期模拟 | `tools/mlogsim.py`、`tests/probes/` | 探针；需本机 JRE 与匹配的 server jar |
| 改 sidecar 或辅助模组 | `tools/logicd.py`、`MlogAuxiliary/` | `tests/logicd/`、`tests/mlogauxiliary/` |
| 改反破坏模组 | `GriefToBan/` | `tests/grief-to-ban/` |
| 改知识库内容/索引 | `knowledge/`、`tools/kb.py` | 知识库构建与 `gate.py` 的 freshness 检查 |

具体测试命令、版本要求和完整门禁定义请以根目录 `README.md` 为准。本文不定义新的发布或清理流程。
