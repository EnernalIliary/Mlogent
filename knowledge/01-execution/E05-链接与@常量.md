# E05 Links and @ constants

## In one sentence

A processor can address a block directly through its "link name", and a link name is a **compile-time constant object**; things starting with `@` come in three kinds: true constants (const, where `set` is silently dropped), global writable variables (refreshed by the engine every frame), and content/math constants.

## Rules / formulas

### 1. Resolving a link

```java
// LogicBlock.java:379-397
link.logicVar = asm.putConst(link.name, world.build(link.x, link.y));  // 名字 → 方块对象
linksVar = asm.putConst("@links", executor.links.length);              // 有效链接数
```

| Fact | Value / behaviour | Basis |
|---|---|---|
| Link coordinates | relative to the processor (`--link name@dx,dy`) | assertion table S-02 |
| `@links` | the **valid** link count (not the configured count) | LogicBlock.java:396/582-599 |
| `getlink result i` | the i-th valid link (0-based); out of range → null | LExecutor LinkI |
| Link name | a compile-time `putConst`, cannot be changed by `set` | LAssembler.java:124 |
| Unbound name as a sensor target | result **null** | assertion table S-17 |

**Legal forms of a link name** — the name is not arbitrary; it is recomputed per block type when a save is loaded:

```java
// LogicBlock.java:123-135  getLinkName：取方块名的最后一段（末尾是 large / 数字时退一段）
// LogicBlock.java:331-356  findLinkName：基名 + 最小的未占用序号（1 基）
// LogicBlock.java:315-318  读档：已有名字不以基名开头 ⇒ 整名重算
if(!name.startsWith(bestName)) name = findLinkName(build.block);
```

| Block | Base name | Default link name |
|---|---|---|
| `switch` | `switch` | `switch1` |
| `message` | `message` | `message1` |
| `world-cell` | `cell` | `cell1` |
| `memory-bank` | `bank` | `bank1` |
| `core-shard` | `shard` | `shard1` (**not** `core1`) |
| `silicon-arc-furnace` | `furnace` | `furnace1` |

Consequence: write a switch's link name as `sw1` (only the start of `switch`) and a save-and-reload renames the whole name to `switch1`, so `sw1` in the program is permanently null — the measured incident m00622, where two switches failed at once (assertion table L2-130). To rename, change only the trailing digits; a wrong prefix is **silently** recomputed, with no error at all.

### 2. Three-tier classification of @ constants (the GlobalVars registry)

| Tier | Registration | Writable | Examples |
|---|---|---|---|
| Compile-time constant | `putConst` | **not writable** (set silently dropped) | `@links` `@ipt` `@unit` `@this` `@thisx` `@thisy` `@queries` (world only) |
| Global variable | `putEntry` | readable, refreshed by the engine every frame | `@time` `@tick` `@second` `@minute` `@waveNumber` `@waveTime` `@mapw` `@maph` `@server` `@client` |
| Client privilege | `putEntry(...,true)` | readable only by a privileged processor | `@clientLocale` `@clientUnit` `@clientName` `@clientTeam` `@clientMobile` `@clientMusicPlaying` |
| Content constant | `put` | not writable | `@copper` `@air` `@solid` `@mono` `@status-wet` … |
| Math constant | `putEntry` | readable | `@pi` `@e` `@degToRad` `@radToDeg` (plus `π`) |
| Unit control source | `put` (handle) | used for sensor's controller attribute | `@ctrlProcessor` `@ctrlPlayer` `@ctrlCommand` |

### 3. The **unit trap** in time variables

```java
// GlobalVars.java:190-199
varTime.numval   = state.tick / 60.0 * 1000.0;   // 毫秒！
varTick.numval   = state.tick;                  // tick 数
varSecond.numval = state.tick / 60f;            // 秒
varMinute.numval = state.tick / 60f / 60f;      // 分
varWaveTime.numval = state.wavetime / 60f;      // 秒
```

| Variable | Unit | Conversion |
|---|---|---|
| `@time` | **milliseconds** | game tick/60×1000 |
| `@tick` | tick | integer tick count |
| `@second` | seconds | tick/60 |
| `@minute` | minutes | tick/3600 |
| `@waveTime` | seconds | remaining time in the current wave |

### 5. The three special variables set cannot write

`@counter` is an **ordinary var** (writable, and a write jumps); `@ipt` / `@unit` are **const**:

| Variable | Declaration | Trying to change it | Correct way |
|---|---|---|---|
| `@counter` | `putVar` (non-object) | `set @counter N` directly | writable |
| `@ipt` | `putConst` (LAssembler:26 / LExecutor:136) | `set @ipt 10` **silently dropped** | `setrate 10` |
| `@unit` | `putConst(null)` (LAssembler:27) | `set @unit u` **silently dropped** | `ubind` |

## Measurements and counter-examples

- ✅【E】after `set @ipt 5`, reading @ipt back is unchanged (the const is dropped by SetI).
- ✅【E】`sensor x target @enabled` works on v160.7 and not on v159.3 (a difference in the LAccess set). [src: knowledge/VERSION.md:1]
- Counter-example (a boundary that does not hold): **"a link name is just a variable name and can be set" is false** — a link name is a const object, so `set name x` is dropped.
- Counter-example: **"a block name in the third operand is the same as giving coordinates" is false** — a block name in the third operand ⇒ the result is null (assertion table S-15).
- 【U】The exact product of an out-of-range `getlink` index (null, or the old value kept) needs a probe experiment; the source indexes an array, so null is the likely answer.

## Common misconceptions

1. "@time is seconds" — it is **milliseconds** (GlobalVars.java:190).
2. "@links is the configured link count" — it is the valid link count.
3. "a sensor attribute can be anything" — a wrong attribute name writes the target variable as null, overwriting the old value (S-16).
4. "@unit is a variable you can set" — it is const.
