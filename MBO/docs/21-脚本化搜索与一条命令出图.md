# 21 脚本化搜索：一条命令从「枚举」到「真机验证」

> 结论：`python -m mbo opt graphite:1/s --boundary coal --crop` 一条命令跑完
> **枚举 6195 张候选 → 物流模型算速率 → Pareto 前沿 3 条 → 选优 → 静态校验 → 真机验证 → 出 5 件产物**，
> 全程无人工挑图。选中的蓝图实测 **1.359/s**（理论 1.333，+1.9%），`eff=1.0`、无死锁、`verify` 字节一致。

## 0. 为什么要有这一层

用户 m02968 问「这个成果是脚本出来的结果吗」，m02995 之前也说过「能脚本化的推理都脚本化试一下」。
此前答案是半自动的：

| 环节 | 之前 | 现在 |
|---|---|---|
| 算建筑数、边界需求 | 脚本 `production.expand` | 同 |
| 定几何（谁贴谁） | **人读源码 + 手写模板**（`build_direct` / `build_ported`） | **脚本枚举 6195 张** |
| 算可达速率 | **手算**「台数 × 单机速率」 | **最大流物流模型**（`mbo/logistics.py`） |
| 挑一张 | 人按直觉 | **Pareto 前沿 + 明确的 objective** |
| 验证 | 手敲 `gen` + `verify` | 同一条命令里自动跑 |

`mbo/search.py` 把原来只在 `spikes/gen/search_ported.py` 里做的搜索搬成生产代码，
并修掉了"人只搜自己想到的形状"这个漏洞：手写模板也进候选池（见 §4）。

## 1. 搜索空间

石墨 1/s = 2 台 `graphite-press`（2×2、单输入 coal），在 9×7 网格上枚举：

```
机器排布   h/v × 缝宽 0..3                      8 种
桥接元件   无 / underflow-gate / overflow-gate / router   （同时贴两台机器的那一格）
输入方案   单源经桥接元件 / 每台机器各一个源
出口方案   每台一个 item-void / 单个 item-void（其余机器用 带子 或 带子+路由器 接力）
```

每张候选都要过两道硬约束：

1. **端口在外**（用户 m02384）：`item-source` / `item-void` 的所有格子必须落在
   「非端口方块外接矩形」之外；贴边也算在内。
2. **物流限速**（用户 m02384 第二条）：速率 = `min(机器产能, 输入侧最大流, 输出侧最大流)`，
   不是「台数 × 单机速率」。模型与真机一致性在 docs/19 §2 有 6 张历史图的复算。

访问顺序固定（`sorted` + 固定 gate 顺序），同一输入重复运行给同一结果 —— 测试
`test_search_is_deterministic` 守着这条。

## 2. 结果：Pareto 前沿 3 条

三个目标不塌缩：**端口数 / 工厂格数 / 外接矩形面积**。石墨 1/s 的非支配集正好 3 条：

| 端口 | 工厂格 | 外接面积 | 形状 | 实测 |
|---|---|---|---|---|
| **2** | 12 | 15 | 单源经反溢门 + 路由器合流到单黑洞（模板 `ported:one`） | **1.359/s** |
| **3** | 9 | 10 | 单源经溢流门 + 两台各一黑洞（枚举 `h1/overflow-gate/src1/out1`） | 1.333/s（模型） |
| **4** | 8 | 8 | 每台机器进口/出口各贴一个端口（枚举 `h0/-/src2/out1`） | **1.359/s** |

- 没有哪条严格更优：想少占格就多花端口（4/8），想少拉端口就多占格（2/12）。
- 所以在**用户没给偏好之前不允许私自拍一个**：`SearchResult.front` 永远保留全部前沿；
  `--objective` 只是"这次先按哪个轴挑代表点"。

## 3. 一条命令做了什么

```
python -X utf8 -m mbo opt graphite:1/s --boundary coal --crop --out o-ports
```

```
搜索：6195 张候选（满足产能 6195 张），Pareto 前沿 3 条（目标 ports）
  ports=2 工厂格=12 外接面积=15 预测 1.3333/s  template:ported:one
  ports=3 工厂格= 9 外接面积=10 预测 1.3333/s  h1/overflow-gate/src1/out1
  ports=4 工厂格= 8 外接面积= 8 预测 1.3333/s  h0/-/src2/out1
运行目录 MBO/runs/o-ports
选中 template:ported:one（2 端口 / 12 工厂格 / 预测 1.3333/s）
静态 OK，真机 1.359/s
结论：PASS — 实测 1.359/s vs 预测 1.333/s（+1.9%）
```

逐步：

1. `production.expand` 算建筑清单与边界需求（coal 2.667/s）；
2. `search.enumerate_candidates` 枚举 + `logistics.estimate` 打分（1.9 s）；
3. `search.pareto` 留前沿，`search.pick(objective)` 选代表点；
4. `search.to_layout` 把候选变成画布坐标的 `Layout`；
5. `validate.static_check(strict_ports=True)` 复核端口在外 + 全部原有检查；
6. `engine.run` 进真机（warmup 13 s、1800 tick、丢前 300 tick）；
7. `report.write_run` 写 5 件产物，`trace.json` 里多一个 `search` 字段记搜索来源。

`trace.json` 的搜索证据（可复现"为什么是这一张"）：

```json
"search": {
  "objective": "ports",
  "grid": [9, 7],
  "candidates": 6195,
  "feasible": 6195,
  "pareto": [[2, 12, 15, 1.333], [3, 9, 10, 1.333], [4, 8, 8, 1.333]],
  "picked": {"label": "template:ported:one", "ports": 2, "tiles": 12, "box": 15,
             "rate": 1.3333, "bottleneck": "machine", ...}
}
```

`mbo verify o-ports` 从 `trace.json` 重建布局，重编码 body 与 `blueprint.msch` 逐字节一致
（8 建筑 / 14 格，静态 OK）。

## 4. 手写模板为什么也进候选池

枚举只铺「机器外一圈」的端口，像 `ported:one` 这种"黑洞再往外退一格、靠路由器合流"
的形状枚举不到（枚举里 2 端口的方案会因为传送带把外接矩形撑大而违反端口在外）。
手写模板本来就是为这些形状写的，放进同一个池子用同一把尺子量才公平：

| 模板 | 端口 | 工厂格 | 是否入选前沿 |
|---|---|---|---|
| `cells` | 1 | 20 | 否（产物进厂内容器，没有输出标记） |
| `split` | 1 | 17 | 否（同上） |
| `ported:both` | 4 | 8 | 是（与枚举同一形状） |
| `ported:gate` | 3 | 9 | 是（与枚举同一形状） |
| `ported:one` | 2 | 12 | 是（枚举够不到，靠模板补） |

"没有 `item-void` 的模板"被直接排除：新口径要求输入**和**输出标记都在工厂外，
厂内容器不是输出标记，两者不是同一个问题的解。

## 5. 复现

```powershell
cd MBO
python -X utf8 -m mbo opt graphite:1/s --boundary coal --crop --out o-ports
python -X utf8 -m mbo opt graphite:1/s --boundary coal --objective tiles --crop --out o-tiles
python -X utf8 -m mbo verify o-ports
python -X utf8 -m mbo preview --all
```

`--no-engine` 只做静态（约 2 s），`--no-templates` 只搜枚举几何（看枚举本身的解），
`--top N` 控制前沿打印条数。

## 6. 局限（明确写出来，免得当成能力）

- **只支持 2 台、2×2、单输入的机器**：`_machine_spec` 会明确抛 `ValueError`，不静默降级。
  2/s（4 台）要多机器排布，还没写。
- **枚举只铺一环端口**：≥3 个端口内圈的组合可以，但"再退一圈"的几何只能靠模板补。
- **随机搜索留在 spike**：`spikes/gen/search_ported.py` 的 30 万随机解是"枚举没漏解"的
  证据，没搬进生产代码（太慢，且 `mbo opt` 的关键是确定性）。
- **物流模型是容量模型**：不建模带子延迟、不建模侧向投料掉速（docs/19 §5 的反例），
  所以预测只保证"上限"，真机仍要跑。

## 7. 单开口（1 个端口簇）

"端口数"和"开口数"是两件事：**端口数**数的是 `item-source`/`item-void` 方块个数，
**开口数**数的是这些端口格按 4-邻接分组的组数——1 簇就是"工厂只有一个开口"。

新增维度 `clusters`（`--objective clusters` 可让它当第一目标），结论三条：

| 方案 | 端口方块 | 开口 | 工厂格 | 形状 | 实测 |
|---|---|---|---|---|---|
| 1 个端口方块 | 1 | 1 | — | — | **不可能**：源只发不收、黑洞只收不发，一进一出至少要两个方块 |
| 3 方块单开口 | 3 | **1** | 9 | `xSx` / `MM+MM` / `MM MM` | **1.287/s（−3.5%）** |
| 4 方块单开口 | 4 | **1** | 8 | `SxSx` / `MMMM` / `MMMM` | **1.354/s（−0.4%）** |
| 2 方块单开口 | 2 | 1 | — | — | 枚举里不存在；随机撒 2.4 万张（6 种机器排布）也是 0 张 |

- **单开口能做到，但代价是端口方块变多**：源和黑洞相邻后，两台机器就没有"各自独立的
  进出通路"，得靠 4 个端口（每台一进一出）或 3 个端口（源贴一侧、黑洞贴两侧）。
- **2 个端口方块凑不出单开口**：源要么直接喂机器（那它和黑洞之间没通路），要么经带子/门
  中转（那它们不再相邻）。`test_no_two_port_single_opening` 和随机探针同时守着这条。
- **单开口不是免费的**：9 格那版掉 3.5%（源与黑洞相邻会互抢，源把煤漏进黑洞），
  8 格那版基本无损（−0.4%）。想少一个开口又不想掉速，8 格 / 4 端口 `SxSx` 是答案。

```powershell
python -X utf8 -m mbo opt graphite:1/s --boundary coal --objective clusters --crop --out o-clusters
python -X utf8 spikes/gen/run_one_cluster.py        # 两张单开口蓝图各跑一次真机
python -X utf8 spikes/gen/probe_single_opening_random.py   # 2 端口 + 1 开口 的反例搜索
```

`runs/o-cluster8`（8 格 / 4 端口 / 1 开口 / 1.354/s）与 `runs/o-cluster9`
（9 格 / 3 端口 / 1 开口 / 1.287/s）都已 `verify` 字节一致，画廊里可直接看。

## 8. 双端单入单出（2 端口）的最优：12 格

"双端单入单出"= 一个 `item-source` + 一个 `item-void`，各占一个开口，不再有多余端口标记。
用 `--only-ports 2` 把候选池卡到只剩这种形状，再用穷举证明它已经到底：

| 总格数 | 组成 | 枚举摆法 | 可行 |
|---|---|---|---|
| 10 | 8 格机器 + 2 个端口 | 7 446 | **0** |
| 11 | 上面 + 1 个中转方块（带子 4 向 / 两种门 4 向 / 路由器 / 汇接器） | 3 418 380 | **0** |
| 12 | 上面 + 2 个中转方块 | —（模板给出） | **1 张** |

所以 **12 格就是下界且可达**，脚本给的就是这张（`template:ported:one`）：

```
  S          S=物料源  x=黑洞  M=石墨压机  +=门  >n<=路由器
MM+MM
MM MM
 >n<
  x
```

- 2 端口 / 2 开口 / 8 个方块（2 压机 + 门 + 路由器 + 2 条带子 + 源 + 黑洞）；
  工厂格 = 8（机器）+ 1（门）+ 1（路由器）+ 2（带子）= **12**，加 2 个端口格 = 14 张
  tile、蓝图裁到 5×5；真机 **1.352/s（+1.4%）**；
- 为什么 10、11 格不行：2 个端口互不相邻，源与黑洞之间没有独立通路，必须有个中转方块
  同时服务"进"与"出"；而一个中转方块只有一条穿过通道（门/路由器都只能把货往一个方向
  递），一台机器喂饱就顾不上另一台的产出。11 格里那些 340 万种摆法确实一张都没有。

```powershell
python -X utf8 -m mbo opt graphite:1/s --boundary coal --only-ports 2 --objective tiles --crop --out o-dual
python -X utf8 spikes/gen/search_dual.py     # 10/11 格的穷举反证（约 40 s）
```

`--max-clusters 1` 是同样的过滤器（开口数约束），两个可以合用。
