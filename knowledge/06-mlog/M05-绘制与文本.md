# M05 绘制与文本

## 一句话

`draw` 把参数按 **10 bit 有符号**打包进显示缓冲（每槽范围 −511..511），`print` 只是往一个 **400 字符**的文本缓冲里追加字符，两者都要靠 `drawflush` / `printflush` 才真正落到方块上。

## 规则 / 公式

### 1. draw 的 16 种类型（GraphicsType 枚举）

| 类型 | 用途 | 用到的参数 |
|---|---|---|
| clear | 清屏（参数是 r,g,b） | x,y,p1 |
| color | 设颜色 | x,y,p1,p2 |
| col | 同上（虚拟类型） | 无 |
| stroke | 线宽 | p1 |
| line | 画线 | x,y,p1,p2 |
| rect | 填充矩形 | x,y,p1,p2 |
| lineRect | 空心矩形 | x,y,p1,p2 |
| poly | 填充多边形 | x,y,p1,p2,p3 |
| linePoly | 空心多边形 | x,y,p1,p2,p3 |
| triangle | 三角形 | x,y,p1,p2,p3 |
| image | 贴图 | x,y,p1,p2,p3 |
| print | 画文本缓冲（内部按字符展开） | x,y,对齐=p1 |
| translate | 位移 | x,y |
| scale | 缩放 | p1 |
| rotate | 旋转 | p1 |
| reset | 复位变换 | 无 |

枚举共 16 值，机读版在 `06-mlog/enums.json#enums.GraphicsType`（源码 LogicDisplay.java:290-312）。

### 2. 10 bit 打包：每条命令只有 ±511 的分辨率

`DisplayCmdStruct`（LogicDisplay.java:314-322）每个字段标 `@StructField(10)`，写入时 packSign、读出时 unpackSign：

```java
static int unpackSign(int value){
    return (value & 0b0111111111) * ((value & (0b1000000000)) != 0 ? -1 : 1);
}
```

⇒ **符号位 1 bit + 幅值 9 bit**：合法范围 `-511..511`，超出部分截断/环绕，不是浮点。屏幕本地坐标通常只有几十到数百，够用；但**画世界坐标（数万级）必然溢出**——这是「draw 到屏幕上位置乱飞」的根因。

### 3. 文本缓冲（print / printchar / format → printflush）

| 指令 | 作用 | 上限 |
|---|---|---|
| `print <值>` | 追加到 textBuffer | 400 字符 |
| `printchar <码点>` | 追加一个字符 | 400 |
| `format <串>` | 把 `{0}..{9}` 替换成缓冲上的数值占位 | 替换后仍截断到 400 |
| `printflush <消息块>` | 把缓冲推给消息方块并清空 | 消息块自身 400 |

关键源码事实：

- `LExecutor.maxTextBuffer = 400`（LExecutor.java:46）。
- 追加前判 `if(exec.textBuffer.length() >= maxTextBuffer) return;`（:1057、:1100）：**缓冲满了以后后续 print 直接丢弃**，不报错。
- `format` 替换后若超长，`setLength(maxTextBuffer)` 截断（:1155-1156）。
- 消息方块另有一个 400 上限，超长**整条拒绝**（MessageBlock.java:29/42）。
- 缓冲在 `printflush`、`draw print` 等消费点被清空（:993、:1178、:1907、:1943）。
- **`printchar <内容>` 打的是图标，不是字符**：`PrintCharI` 对 `UnlockableContent` 追加 `(char)cont.emojiChar()`（LExecutor.java:1101-1104），传数字才走码点分支；传非内容对象**静默忽略**。所以 `printchar copper` 画出铜锭图标、`printchar @landing-pad` 画着陆台图标。
- **图标只在消息方块上保证能显示**：UI 字体自带 Iconc 字形（Fonts.java:78-90），而逻辑显示屏的 `draw print` 用 logic.ttf，字符集只有 ASCII（Fonts.java:92-98）⇒ 信息板要图标只能走 `printchar`。
- **`format <值>` 一次只填一个占位**：扫描缓冲区里**编号最小**的 `{0}..{9}` 并替换（LExecutor.java:1123-1139），占位必须先被 `print` 写进缓冲；值是内容对象时走 `PrintI.toString`（:1143）⇒ **出名字不出图标**。
- 因此「图标 + 数量」最省是 3 条：`printchar it` / `print "  x{0}\n"` / `format cnt`；纯文字版是 `print "  {0} x{1}\n"` + `format it` + `format cnt`。⚠ `format` 需要 build ≥ 147（检查器报 version gate）。

### 4. 坐标系

| 量 | 单位 | 换算 |
|---|---|---|
| tile 坐标 | 1 tile | `tilesize = 8` 世界单位/像素 |
| 处理器 range | tile | range = 8 × tile 数（micro 80、logic 176、hyper 336） |
| draw 坐标 | 显示方块本地坐标（0..显示宽/高） | 由 `@displayWidth`/`@displayHeight` 读出 |
| world 指令坐标 | **tile** | `numfWorld()` 内部做 `World.unconv` 转世界单位（LVar.java:70-72） |

所以：给 `draw` 传 tile 坐标会画到屏幕外；给 world 指令传像素/世界单位会放大 8 倍。

### 5. 颜色

- `draw color r g b a`：分量 0..1 浮点。
- `packcolor result r g b a` / `unpackcolor`：把颜色压成 double 位模式（DrawI 用 `Double.doubleToRawLongBits` 拆包，LExecutor.java:933-942）。
- 颜色进显示缓冲后同样受 10 bit 打包限制 ⇒ 分量精度约 8-10 bit。

## 实测与反例

- 反例（不成立边界）：**draw 坐标不是浮点，不能画任意位置**。所有字段最终走 unpackSign 的 10 bit 有符号整数，±511 之外失真。
- 反例：**print 超长不会自动换行**。缓冲满了直接丢弃后续字符，且不提示。
- 反例：**printflush 之后缓冲不保留**。flush 会 setLength(0) 清空，要重建。
- 【U】服务器（headless）下 DrawI 直接 return，逻辑屏不显示：这是「显示在服务器上看不到」的机制推断，需一次带显示器的服务器实验确认。

## 常见误解

1. 「draw 能画世界坐标」——不能，超过 ±511 失真；世界坐标要先减去屏幕原点。
2. 「print 直接输出到屏幕」——print 只写内部缓冲，必须 printflush 或 draw print。
3. 「format 会补齐位数」——只做替换，不补零/不对齐。
4. 「文本上限是 1000」——是 400（逻辑缓冲与消息方块各 400）。
