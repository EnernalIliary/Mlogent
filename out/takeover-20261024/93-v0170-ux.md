## 六条怎么做的

### 1. 完成后自动写入（默认关）

- `AUTO_WRITE_KEY = "mlogauxiliary-auto-write"`、`autoWriteOn()/autoWriteSet()/autoWriteText()`：
  开着按钮显示「自动写入已开启」，关着显示「完成后自动写入：关」。
- 设置页新增独立一段「写入」；F3 描述框里也有同一个开关（`d.cont.button(autoWriteText(), …)`），
  两处读写同一个 `Core.settings` 键，所以永远一致。
- 真正写入在 `autoWriteApply(b, job)`：要求「开关开着 + `job.state === "done"` + `bytes_b64` 非空」，
  然后 `writeBuild(b, jobAsPlan(job))` + `jobBoxWritten(b)` + `hint(r)`。
  挂在两条轮询链上：单作业 `jobTick()` 的 terminal 分支、框选 `jobBoxTick()` 的 `lookupBuild(awj)` 之后，
  两处都在 `jobBoxFinishIfDone()` 之前 —— 写入的结果会先记进框角状态，再判是否收尾。
- 为什么不做成「写失败自动重试」：写失败的典型原因是联机权限或代码被改过，重试只会再失败一次，
  让它照样走 `hint` + 作业管理窗，比静默重试可解释。

### 2. 设置主标题两行居中放大

- `titleLine(t, text, scale, color)`：`t.add(text)` 拿 Cell → `width(ROW_W)` + `center()` → `cell.get()`
  上 `setFontScale/ setColor` → `row()`。
- 三行：`MAI`（1.9×，accent）、`MlogAuxIliary`（1.2×，accent）、`v0.17.0 · 说一句要什么 → 生成 → 预检 → 写入`（0.9×，gray）。
- 注意：游戏自己的设置**对话框标题**是 `SettingsMenuDialog` 用 `bundle.get("settings")` 画的，模组改不了；
  左侧分类按钮名也就是 `cat.name`（`SettingsMenuDialog.java:357-365`，且 `menu.defaults().size(300f, 60f)` 固定尺寸），
  所以「主标题」只能落在我们这一页的页内内容上。

### 3. 长解释收进 infoCircle

- `tipOn(el, text)`：`Packages.arc.scene.ui.Tooltip.Tooltips.getInstance().create(String)` + `setInstant(true)` +
  `el.addListener(tp)`。**必须先判 `Core.scene === null` 直接返回** —— 无头环境没有 Scene，Tooltip 建 label
  要 `scene.getStyle`，会抛 NPE 并被 smoke 记成 FAIL（本轮就踩了这个）。
- `infoIcon(row, text)`：`row.image(Packages.mindustry.gen.Icon.infoCircle)` + `size(18)/padLeft(8)/color(accent)`，
  再把 tooltip 挂到这个 icon 上。`kv(t, k, v, mk, expl)` 新增第 5 个参数，行尾自动带图标。
- 收进去的 6 条长解释：模型地址/密钥、聊天播报、框选控件倍率、自动写入、热键、快检。
- 文案：「启用模型档」→「启用模型」三处（设置页按钮、`llmNote`、`jobSubmit` 的未配置提示）。

### 4. 框选时描出框里的逻辑处理器

- `drawLogicHighlight(r)`：逐格 `Vars.world.tile(x,y)`，`isLogicBuild(t.build)` 才 `L.rect(x*8, y*8, 8, 8)`。
- 只画边不填色（和原版选框同一套 `Lines.rect`），smoke 里有一条红线禁止回到 `D.alpha(0.35)` 的半透明填充。
- 面积上限 1024 格（32×32）：Rhino 里每格一次 `Vars.world.tile` 都是跨语言调用，框太大就跳过，
  宁可少画也不掉帧。

### 5. 热键可改（框选 / 清单 / 区域）

- `HOT_KEY = "mlogauxiliary-hotkey-"` + `hotGet/hotSet/hotKeyCode/hotTap/hotLabelText/hotCellSet/hotLabelsRefresh`，
  默认值仍是 `KEY_REGION/KEY_SELECT/KEY_LIST` 里的 `f7/f3/f2`。
- 设置页「热键」段三个按钮：点一下进入 `hotBegin(which)` → `HOT_WANT` 挂上 → 下一帧起 `hotCaptureTick()`
  遍历 `KeyCode.values()` 找 `Core.input.keyTap()` 为真的那个键（跳过 `anyKey/unknown/mouse*`），
  Esc 取消；绑完立即 `hotSet` + `hotLabelsRefresh()`。
- 三处热键读取换成 `hotTap("region", …)` / `hotTap("list", …)` / `hotKeyCode("select", …)`；
  F3 的按住式拉框仍然用 `Core.input.keyDown(selKey)`（smoke 有这条红线）。
- 坑：改键的 store key 必须和读取处一致 —— 第一版把「清单/区域」当 which 传进去，写进的是
  `mlogauxiliary-hotkey-清单`，读取处找的是 `-list`，等于改了没用。已统一成 `select/list/region`。

### 6. 让 sidecar 无感

- `PENDING_SUBMITS` + `flushPendingSubmits()`：`jobSubmit()` 遇到 `SIDE.state === "starting"` 不再直接失败，
  而是把这次投递（含 `cb/wsInfo/batch`）压进队列，提示一次「后端启动中，就绪后自动投递」；
  `sidecarTick()` 成功分支调 `flushPendingSubmits()`，队列里 60 秒内的全部补发。
- 顺手把 `sidecarTick` 成功时的「sidecar 已就绪：url」提示去掉了 —— 那是每局都会闪一次的噪音，
  真要看地址有「运行环境」那一行。
