# 文档索引

仓库里的文档分两层：**knowledge/ 是事实母本**（机制、数值、源码锚点），**docs/ 是入口与证据**
（怎么用、怎么验、当时跑出了什么）。两者出现分歧时以 `knowledge/` 为准，
`docs/断言表.md` 与 `docs/验证记录.md` 例外——它们是 id 命名空间与证据原件，见下面各自说明。

| 文档 | 什么时候看 |
| --- | --- |
| [项目结构与数据流](项目结构与数据流.md) | 第一次进仓库：哪块在哪、数据怎么流、跑什么命令 |
| [后端重构验收](后端重构验收.md) | Sidecar 模块边界、发布收尾、验收结果与环境限制（2026-11-19） |
| [World后端重构计划](World后端重构计划.md) | 常驻世界后端的依赖、通信层拆分与后续验证边界 |
| [速查卡](速查卡.md) | 想快速找到「这件事该翻哪一篇」，一页指路 |
| [断言表](断言表.md) | 要引用一条结论（`L1-03` 这种 id 被 claims、docsig、probes 共用）；**只放 id 与判定标准，不复述机制** |
| [验证记录](验证记录.md) | 想追某条断言是怎么来的：原件、命令、输出；`knowledge/08-evidence/claims.jsonl` 的 `src` 指向这里的行，删行会断链 |
| [实施记录](实施记录.md) | 想知道某个工具为什么存在、契约是什么、哪一块验证到哪一步（含编号表：代码里的 `实施记录 §N` 指它） |
| [观察与差分-契约](观察与差分-契约.md) | 要改差分/观测：信封字段、比较规则、`mlog-observation/v1` 的形状 |
| [Mindcode集成](Mindcode集成.md) | 要接或改编译前端：定位顺序、返回字段、为什么钉在 3.19.3 |
| [MCP部署](MCP部署.md) | 要把 MCP 跑在服务器上：HTTP 传输、鉴权、systemd/Docker、反代、没有 JVM 时降级成什么样 |
| [RELEASE-1.4.0](RELEASE-1.4.0.md) | 蓝图提取与注入、调试和版本回退，以及升级注意事项 |

不在仓库里的文档（本机工作区另有）：`联机调试世界.md`、`群控接收台-架构-v2.md`、
`地图-大肥鱼的调试世界.md`、`Mlog辅助-*.md`、`N动态-方案-v1.md`——私人笔记与产品文档，按
`knowledge/CONVENTIONS.md` 的约定不进公开仓库。

工具本身的用法不在这里，在 `tools/README.md`；模型侧的行为约定在
`mindustry-blueprint/SKILL.md`；事实与数值在 `knowledge/`（入口 `knowledge/KB.md`）。
