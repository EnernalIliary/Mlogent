# M01 Execution model overview

## In one sentence

A processor is not a "script interpreter process" but **an accumulator the game nudges once per tick**: every tick it banks `ipt × Δt` points of budget, each whole point runs one instruction, and the execution position is decided by the writable `@counter`.

## Rules / formulas

### 1. Per-tick budget (the accumulator pool)

The body of updateTile() at `LogicBlock.java:564-579`:

```text
accumulator = min(accumulator, maxInstructionScale * ipt)   // 先削顶
while(accumulator >= 1):
    executor.runOnce()          // 执行一条指令，@counter 自增
    if(executor.yield): break   // 让出：break 写在 accumulator-- 之前
    accumulator -= 1
accumulator += edelta() * ipt   // 累加在循环之后，顺序有意义
```

| Fact | Evidence |
|---|---|
| The budget is a pool **accumulated across ticks**, not an allowance reset each tick | `accumulator += edelta()*ipt` never clears it |
| A single tick banks at most `maxInstructionScale × ipt` points; the excess is dropped (clamped) | `if(accumulator > maxInstructionScale*ipt) accumulator = maxInstructionScale*ipt` |
| **An instruction that yields does not consume budget** | `break` comes before `accumulator--` |
| Long-run average throughput = `ipt` instructions/tick; 60 tick/s ⇒ `ipt×60` per second | steady state of the formula above | [src: knowledge/VERSION.md:1]

### 3. Program and pointer

- One mlog statement compiles into one `LInstruction` stored in an array; `@counter` is an index into that array.
- `runOnce()` (LExecutor.java:111-121):
  ```java
  if(counter.numval >= instructions.length || counter.numval < 0) counter.numval = 0;
  instructions[(int)(counter.numval++)].run(this);
  ```
  ⇒ **an out-of-range pointer does not crash, it just wraps to 0**; `@counter` is a double and is cast to int.
- `@counter` is **the only engine built-in variable you can `set`** (created by `LAssembler.putVar`, not a constant); `@unit`/`@ipt` are `putConst`, so `set` on them is silently dropped (see M02).
- The program size cap is `LExecutor.maxInstructions = 1000`; the parser uses the same constant at LParser.java:185, and the editor truncates with `statements.truncate(1000)` at LCanvas.java:148.
- Comments never enter the instruction array and **do not take a `@counter` index** (LParser strips `#`/`//` while parsing).

## Measured facts and counter-examples

- ✅【E】`print @tick` + `end` prints continuously; statements after `end` never run (assertion table L1-01/L1-02, claims.jsonl).
- ✅【E】`jump -1 always` is not a nop: `counter<0` is normalised to 0, which means run from the top (L1-04).
- Counter-example (a boundary that does not hold): **"exactly ipt instructions per tick" does not hold**. With micro, ipt=2: after a one-frame stall the accumulator can reach `5×2=10` and burst over the following ticks — this is the mechanism behind "logic suddenly speeds up after a stall".
- Counter-example: **"a yielding instruction also eats one unit of budget" does not hold**. When `wait` yields, `accumulator` is not decremented, so a wait loop does not slow down from budget being consumed.

## Common misconceptions

1. "It runs exactly `ipt×60` instructions per second." — right on the long-run average, **wrong instantaneously**; a stall clamps and drops budget, and after the stall the pool bursts.
2. "`@counter` can only be changed by jump/end." — `set @counter x` works just as well and is a documented way to jump.
3. "Instruction count is counted by lines, comments included." — comments take no index; `@counter` is a "statement number".
4. "world-processor only has a bigger range." — its max is 1000 (40 for normal processors) and it can run the world instruction set.
